# 7.1 命令与状态速查

## 本章解决什么

排障时 80% 的时间花在「我该敲哪条命令看什么」。这一章把 RDK X5 上最常用的排查命令按用途编组，每条都给判读方法——不只是命令，还包括「输出里该看哪个数、什么值算异常」。

> 来源：官方文档 Appendix/rdk-command-manual/*（https://developer.d-robotics.cc/rdk_x_doc/Appendix/rdk-command-manual/cmd_rdkos_info）

## 7.1.1 系统信息采集

### 7.1.1.1 rdkos_info：一条命令拿到全部状态

官方推荐的一站式信息采集工具，一次输出软件、硬件版本、驱动加载清单、软件包安装清单、最新系统日志。

```bash
sudo rdkos_info
```

| 选项 | 作用 |
| --- | --- |
| （无参数） | 简洁模式 = `-s`，输出 30 行最新系统日志 |
| `-b` | 基础输出模式，**不收集系统日志** |
| `-s` | 简洁输出模式（默认），30 行日志 |
| `-d` | 详细输出模式，300 行日志 |
| `-v` | 显示版本信息 |
| `-h` | 帮助 |

输出结构（以官方示例为例）：

```
================ RDK System Information Collection ================

[Hardware Model]:
Hobot X3 PI V2.1 (Board Id = 8)

[CPU And BPU Status]:
=====================1=====================
temperature-->
CPU : 56.6 (C)
cpu frequency-->
min cur max
cpu0: 240000 1500000 1500000
...
bpu status information---->
min cur max ratio
bpu0: 400000000 1000000000 1000000000 0

[Total Memory]: 1.9Gi
[Used Memory]: 644Mi
[Free Memory]: 986Mi
[ION Memory Size]: 672MB

[RDK OS Version]:
2.1.0

[RDK Kernel Version]:
Linux ubuntu 4.14.87 ...

[RDK Miniboot Version]:
U-Boot 2018.09-...
```

> 来源：官方文档 Appendix/rdk-command-manual/cmd_rdkos_info（https://developer.d-robotics.cc/rdk_x_doc/Appendix/rdk-command-manual/cmd_rdkos_info）

**判读要点**：

| 字段 | 怎么看 |
| --- | --- |
| `[Hardware Model]` | 确认型号与 Board Id，和实物对不上说明拿错固件 |
| `[RDK OS Version]` | 决定你看哪套文档（见第 0 卷版本总线） |
| `[Free Memory]` | 明显偏小先查 ION 占用与保留内存，别急着说「内存坏了」 |
| `[ION Memory Size]` | 多路摄像头时重点看，不够要调 `srpi-config` |
| `[RDK Miniboot Version]` | 与 OS 版本是否匹配，不匹配就 `rdk-miniboot-update` |

**求助时贴这个**：`sudo rdkos_info -d` 的输出，比自己描述「我的板子好像有点问题」有效得多。

### 7.1.1.2 hrut_somstatus：温度、频率、BPU 负载

```bash
sudo hrut_somstatus
```

输出样例：

```
=====================1=====================
temperature-->
CPU : 61.3 (C)
cpu frequency-->
min cur max
cpu0: 240000 240000 1800000
...
bpu status information---->
min cur max ratio
bpu0: 400000000 1000000000 1000000000 0
bpu1: 400000000 1000000000 1000000000 0
```

| 字段 | 含义 |
| --- | --- |
| `temperature / CPU` | CPU 温度（℃） |
| `cpu frequency` 的 `min/cur/max` | 每个核心的最低/当前/最高频率（单位 Hz） |
| `bpu status` 的 `min/cur/max` | BPU 最低/当前/最高频率 |
| `bpu status` 的 `ratio` | **BPU 负载率** |

> 来源：官方文档 Appendix/rdk-command-manual/cmd_hrut_somstatus（https://developer.d-robotics.cc/rdk_x_doc/Appendix/rdk-command-manual/cmd_hrut_somstatus）

**判读要点**：

- `ratio = 0` 但你在跑推理 → 推理根本没走 BPU，或者没跑起来
- `cur` 远低于 `max` 且负载高 → 触发降频，查温度
- CPU 温度长期 > 80°C → 散热不足，考虑加风扇或降频

### 7.1.1.3 三个温度传感器的原始值

```bash
cat /sys/class/hwmon/hwmon0/temp1_input   # DDR
cat /sys/class/hwmon/hwmon0/temp2_input   # BPU
cat /sys/class/hwmon/hwmon0/temp3_input   # CPU
```

**单位是 0.001 摄氏度** —— `45000` = 45.000°C。

> 来源：官方文档 Advanced_development/linux_development/driver_development_x5/driver_thermal_dev（https://developer.d-robotics.cc/rdk_x_doc/Advanced_development/linux_development/driver_development_x5/driver_thermal_dev）

### 7.1.1.4 版本查询四件套

```bash
cat /etc/version                          # 系统大版本
apt list --installed | grep hobot         # 地瓜核心包版本
hrut_boardid                              # 板卡 ID 与 DDR 属性
uname -a                                  # 内核版本
```

> 来源：官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）Q2

## 7.1.2 最小启动镜像与备份

### 7.1.2.1 rdk-miniboot-update：升级 NAND 固件

```bash
sudo rdk-miniboot-update
```

| 选项 | 作用 |
| --- | --- |
| （无参数） | 使用最新版本 miniboot 镜像升级 |
| `-f <FILE>` | 安装指定文件而非最新版 |
| `-l` | 只打印会用哪个镜像文件，不执行 |
| `-s` | 不显示进度消息 |
| `-h` | 帮助 |

先看会用哪个镜像：

```bash
rdk-miniboot-update -l
```

指定镜像：

```bash
sudo rdk-miniboot-update -f /userdata/miniboot.img
```

> 来源：官方文档 Appendix/rdk-command-manual/cmd_rdk-miniboot-update（https://developer.d-robotics.cc/rdk_x_doc/Appendix/rdk-command-manual/cmd_rdk-miniboot-update）

**什么时候必须跑**：每次系统升级之后。官方在 Release Note 里明确要求。跳过会导致启动异常或可用内存偏小。

### 7.1.2.2 rdk-backup：把当前系统备份成镜像

```bash
sudo rdk-backup
```

- 参数 `[dir]` 是打包目录，**默认 `/mnt`**
- 打包目录本身在制作镜像时会被忽略
- 执行过程会联网下载安装所需工具
- 完成后在打包目录得到 `rdk-<时间日期>.img`

指定目录：

```bash
sudo rdk-backup /userdata
```

> 来源：官方文档 Appendix/rdk-command-manual/cmd_rdk-backup（https://developer.d-robotics.cc/rdk_x_doc/Appendix/rdk-command-manual/cmd_rdk-backup）

**实用场景**：调好环境后先备份一次，后面折腾坏了直接烧回去，比重新配一遍快得多。

## 7.1.3 内存与资源

### 7.1.3.1 看内存真实分布

```bash
free -h
cat /proc/iomem
```

**关键认知**：`free` 显示的可用内存已经扣除了设备树保留的约 1150MB（kernel_ram 128MB + cma_reserved 382MB + adsp_ddr 34MB + ion_reserved 768MB 等）。所以「标称 8GB 只剩 6GB 多」是正常的。

> 来源：官方文档 Advanced_development/linux_development/driver_development_x5/memory（https://developer.d-robotics.cc/rdk_x_doc/Advanced_development/linux_development/driver_development_x5/memory）

### 7.1.3.2 看进程与负载

```bash
top
ps aux --sort=-%cpu | head -20
ps aux --sort=-%mem | head -20
```

地瓜专有工具：

```bash
hrut_ps
```

> 来源：官方文档 Appendix/rdk-command-manual/cmd_hrut_ps（https://developer.d-robotics.cc/rdk_x_doc/Appendix/rdk-command-manual/cmd_hrut_ps）

### 7.1.3.3 编译时内存不足

官方 FAQ 有专门条目：编译大型 C++ 项目/ROS 功能包时进程被 `kill`，通常是内存不足。解决办法是**加 Swap**：

```bash
# 创建 4GB swap 文件（大小按需调整）
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

> 来源：官方文档 FAQ/applications_and_examples（https://developer.d-robotics.cc/rdk_x_doc/FAQ/applications_and_examples）Q2

长期生效要写进 `/etc/fstab`，否则重启丢失。

## 7.1.4 日志

### 7.1.4.1 内核日志

```bash
dmesg | tail -100
dmesg -w          # 实时跟踪
dmesg | grep -i error
dmesg | grep -i -E 'bpu|vio|isp|cam'
```

### 7.1.4.2 系统日志

```bash
journalctl -xe
journalctl -b -p err        # 本次启动的错误级别日志
journalctl -u <service> -n 100
```

### 7.1.4.3 崩溃现场

X5 设备树里有 `ramoops_reserved`（256KB），用于保存崩溃现场。这是定位「随机重启」「内核 panic」的关键手段。

> 来源：官方文档 Advanced_development/linux_development/driver_development_x5/memory（https://developer.d-robotics.cc/rdk_x_doc/Advanced_development/linux_development/driver_development_x5/memory）

## 7.1.5 存储

```bash
df -h                      # 各分区使用率
lsblk                      # 块设备列表
sudo fdisk -l              # 分区表
mount | grep -E 'mmc|sd'   # 挂载情况
```

**红线**：运行中禁止热插拔 TF 卡，会损坏文件系统。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

## 7.1.6 网络

```bash
ifconfig eth0               # 有线网口，默认静态 192.168.127.10
ifconfig wlan0              # Wi-Fi
ip addr
ip route
ping -c 4 <目标>
ss -tlnp                    # 监听端口
netstat -anp | grep <端口>
```

有线默认配置：

| 项目 | 值 |
| --- | --- |
| 接口 | `eth0` |
| 模式 | 静态 |
| 默认 IP | `192.168.127.10` |

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

直连电脑 ping 不通的常见原因：电脑网卡不在 `192.168.127.0/24` 网段。

## 7.1.7 外设

### 7.1.7.1 摄像头

```bash
ls /dev/video*
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext
v4l2-ctl -d /dev/video0 --all
```

拿到一帧验证是否真的出图：

```bash
v4l2-ctl -d /dev/video0 --set-fmt-video=width=1920,height=1080,pixelformat=YUYV \
  --stream-mmap=3 --stream-count=10 --stream-to=/tmp/test.yuv
ls -l /tmp/test.yuv
```

### 7.1.7.2 USB

```bash
lsusb
lsusb -t                    # 树状结构，看带宽分配
dmesg | grep -i usb
```

`lsusb -t` 在排查「4 路 USB 3.0 带宽打满」时特别有用——能看出各设备挂在哪个 Hub 下、跑什么速率。

### 7.1.7.3 I2C / SPI / GPIO

```bash
i2cdetect -y -r <总线号>
ls /dev/spidev*
gpioinfo                    # 若有 libgpiod
cat /sys/kernel/debug/gpio
```

### 7.1.7.4 音频

```bash
aplay -l
arecord -l
aplay -D plughw:0,0 /usr/share/sounds/alsa/Front_Center.wav
arecord -D plughw:0,0 -f cd -t wav -d 5 /tmp/test.wav
```

## 7.1.8 BPU 与推理

### 7.1.8.1 看推理是否真的走 BPU

```bash
sudo hrut_somstatus
```

盯 `bpu0` / `bpu1` 的 `ratio`。跑推理时一直为 0，说明没走 BPU。

### 7.1.8.2 模型执行与性能测试工具

官方 FAQ 提到板端 `hrt_*` 系列工具：

| 工具 | 用途 |
| --- | --- |
| `hrt_model_exec` | 板端执行 `.bin` 模型，推理验证与性能测试 |
| `hrt_bpu_monitor` | 监控 BPU 实时使用率、频率、温度 |
| `hrut_somstatus` | 同上的替代方案，系统自带 |

查找位置：

- `/usr/bin`
- `/opt/hobot/bin`
- 工具链包内 `ddk/package/board/<target_os>/bin/`

> 来源：官方文档 FAQ/toolchain（https://developer.d-robotics.cc/rdk_x_doc/FAQ/toolchain）Q14

### 7.1.8.3 Python 推理接口版本判断

```bash
# 3.5.0 及以上
python3 -c "import hbm_runtime; print(hbm_runtime.__file__)"

# 3.4.1 及以下
python3 -c "import pyeasy_dnn; print(pyeasy_dnn.__file__)"
```

哪条成功就说明你的系统属于哪一代。

## 7.1.10 常用组合：三分钟初诊

板子出问题时，按这个顺序跑，把输出保存下来：

```bash
# 1. 系统全貌
sudo rdkos_info -d > /tmp/diag_os.txt 2>&1

# 2. 温度与频率
sudo hrut_somstatus > /tmp/diag_som.txt 2>&1

# 3. 内存
free -h > /tmp/diag_mem.txt 2>&1
cat /proc/iomem >> /tmp/diag_mem.txt

# 4. 内核错误
dmesg | grep -i -E 'error|fail|timeout' > /tmp/diag_dmesg.txt 2>&1

# 5. 外设
lsusb -t > /tmp/diag_usb.txt 2>&1
ls /dev/video* >> /tmp/diag_usb.txt 2>&1

# 6. 打包
tar czf /tmp/diag_$(date +%Y%m%d_%H%M).tar.gz /tmp/diag_*.txt
ls -l /tmp/diag_*.tar.gz
```

这六个文件能覆盖绝大多数求助场景。贴到社区时说明「板子型号 + 系统版本 + 做了什么操作 + 期望结果 + 实际结果」，比只贴一行报错有效得多。

## 常见误区

1. **`rdkos_info` 不加 `sudo`** —— 收集驱动与包清单需要权限，不加会缺字段。
2. **看温度忘了除以 1000** —— `temp1_input` 读到 `45000` 是 45°C，不是 45000°C。
3. **`free` 显示内存少就以为硬件问题** —— 先扣掉约 1150MB 的保留内存再判断。
4. **`hrut_somstatus` 的 `ratio` 全程为 0 却以为在跑 BPU** —— 说明推理实际走的是 CPU，性能会差一个数量级。
5. **升级系统后不跑 `rdk-miniboot-update`** —— 官方明确要求，跳过会留下启动与内存隐患。
