# 接口与引脚速查

## 本章解决什么

接线、改引脚复用、配总线参数时，最容易出错的是**概念混淆**：拿到的是「物理引脚号」还是「GPIO 编号」？3.3V 能带多少电流？两组复用功能为什么只能开一个？

这一章把电气参数、复用规则、各总线的默认配置集中列出。不需要通读，按需查表。

> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

## 一、40PIN 电气参数（先看这个，看错会烧板）

| 项目 | 规格 | 说明 |
| --- | --- | --- |
| GPIO 逻辑电平 | **3.3V** | 数字 IO 均为 3.3V 逻辑 |
| GPIO 最大耐压 | **3.46V** | **超过即可能永久损坏** |
| 3.3V 引脚最大输出 | **800mA** | 所有 3.3V 引脚合计 |
| 5V 引脚最大输出 | **500mA** | 所有 5V 引脚合计 |
| 满载所需适配器 | **≥ 25W** | 上述最大输出电流下的要求 |

> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

**三条铁律**（官方原文）：

1. 「当连接外设时，应当严格注意 40PIN 上的电源、地、信号电平的大小关系，任何**过压、过流、ESD** 等事件，都有可能导致 RDK 受到**不可逆的损伤**」
2. 「当使用杜邦线连接 RDK 和其他功能板卡时，应当确保 RDK 产品处于**下电关机状态**」
3. 3.3V 最大 800mA / 5V 最大 500mA 是**所有引脚合计**，不是每脚

第 5 条最容易误判：外接一个耗电 300mA 的模组，看起来「才 300mA」，但如果 5V 已经接了别的负载，加起来就可能超 500mA，表现为系统随机重启——和供电不足的症状完全一样。

## 二、引脚复用：X5 特有的规则

RDK X5 的 40PIN 上，**部分接口存在复用关系**。这是 X5 与很多开发板不同的地方，必须先理解规则再接线。

### 核心规则

> 「**同一组复用功能中，只有开启其中一项功能时才会生效**。当所有复用功能都**关闭**时，接口才会表现为普通 GPIO 功能。」
> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

换成人话：

- 一组复用对里，你**只能开一个**
- 想把这个脚当普通 GPIO 用，必须把**这一组里的所有功能都关掉**
- 关闭不等于禁用——配置是 `okay`（启用）/`disabled`（关闭专用功能，可作 GPIO）

### X5 的复用对清单

| 接口功能 1 | 接口功能 2 |
| --- | --- |
| `uart3` | `i2c5` |
| `i2c0` | `pwm2` |
| `spi2` | `pwm0` |
| `spi2` | `pwm1` |
| `i2c1` | `pwm3` |

> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

注意 `spi2` 出现了**两次**——`spi2` 与 `pwm0`、`pwm1` 都冲突。所以一旦启用 SPI2，两路 PWM 都用不了。

### 默认状态

> 「40PIN 的管脚会按照本章节所示，**默认使能 UART、SPI、I2C、I2S 等专用功能**」
> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

**这解释了一个高频困惑**：想用某个脚做普通 GPIO，直接写代码操作没反应——因为它默认被配置成 UART/SPI/I2C 了，必须先关掉。

### 配置方法

```bash
sudo srpi-config
```

路径：`3 Interface Options` → `I3 Peripheral bus config`

操作方式：

| 按键 | 作用 |
| --- | --- |
| ↑ / ↓ | 选择功能项 |
| 回车 | 开关该功能（`okay` ↔ `disabled`） |
| ← / → | 在 `Select` 与 `Exit` 间移动 |
| 回车 | 确认 |

**配置后必须重启才生效。**

> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

注意官方特别提醒：`srpi-config` 需要在**全屏命令行窗口**中运行。通过 SSH 运行时如果终端尺寸太小，界面会错乱。

## 三、物理引脚号 vs GPIO 编号

这是新手第一个大坑。官方示例代码里写的「37 号管脚」「31 号管脚」是**物理引脚号**（丝印位置），不是 GPIO 编号。

官方示例：

> 「以 `/app/40pin_samples/button_led.py` 为例，该程序配置 **37 号管脚**为输入，配置 **31 号管脚**为输出，并根据 37 号管脚的输入状态来控制 31 号管脚的输出状态。」
> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

运行方式：

```bash
cd /app/40pin_samples/
sudo python3 ./button_led.py
```

预期输出：

```
Starting demo now! Press CTRL+C to exit
Outputting 0 to Pin 31
Outputting 1 to Pin 31
Outputting 0 to Pin 31
```

**怎么区分两种编号**：

| 编号类型 | 取值范围 | 出现在哪里 |
| --- | --- | --- |
| 物理引脚号 | 1 ~ 40 | 丝印、官方示例、接线图 |
| GPIO 编号 | 芯片内部编号，数值不连续 | 设备树、`/sys/class/gpio`、驱动代码 |

板上 PIN1 与 PIN40 的位置有丝印网表可对照。**接线前先确认丝印上的 PIN1 在哪**，接反了轻则不工作，重则电源接到信号脚上直接烧。

> 来源：官方文档 Basic_Application/01_40pin_user_sample/40pin_define（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/40pin_define）

## 五、各总线速查

### UART

串口应用示例会持续打印收发数据，验证方式很直观——短接 TX/RX 看数据是否回环：

```
Send: AA55
Recv: AA55
```

> 来源：官方文档 Basic_Application/01_40pin_user_sample/uart（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/01_40pin_user_sample/uart）

**注意**：调试串口（Micro-USB，接口 4）和 40PIN 上的 UART 不是一回事。调试串口固定是 115200-8-N-1，40PIN 上的 UART 波特率可配。

### I2C

扫描总线上的设备：

```bash
i2cdetect -y -r <总线号>
```

**注意**：X5 上 `i2c5` 与 `uart3` 冲突，`i2c0` 与 `pwm2` 冲突，`i2c1` 与 `pwm3` 冲突。用 I2C 之前先确认冲突方已关闭。

### SPI

```bash
ls /dev/spidev*
```

**注意**：`spi2` 同时与 `pwm0`、`pwm1` 冲突，是 X5 上冲突面最大的一个接口。

### PWM

官方在 3.4.1 版本说明里提到 `hobot-gpio` 功能扩展「支持多路 PWM 配置」。

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

老版本系统上多路 PWM 可能不可用，先确认版本。

### CAN

CAN 的硬件实现是 **TCAN4550，SPI 转 CAN**，不是 SoC 原生 CAN。

| 项目 | 说明 |
| --- | --- |
| 控制器 | TCAN4550 |
| 接口方式 | SPI 转 CAN |
| 支持的协议 | CAN FD |
| 已知问题 | 早期版本高速数据丢包（3.2.3 已优化） |

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）
> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

3.2.3 的更新说明里写了「CAN 接口稳定性优化，解决高速数据丢包问题」。在更早的版本上跑高速 CAN，遇到丢包先查版本，不用怀疑代码。

**终端电阻**：X5 Module 载板上有「CAN 终端电阻接入开关」（序号 14）。CAN 总线两端各需 120Ω 终端电阻，短距离单节点测试可以只开一端，多节点长距离必须正确配置，否则通信异常。

### 音频（I2S）

| 硬件 | 实现 |
| --- | --- |
| 板载耳机口 | ES8326 |
| X5 Module 载板 | ES8326B，I2S 转 DAC&ADC |

音频子板的适配列表（按版本累积）：

| 版本 | 新增支持 |
| --- | --- |
| 3.2.3 | 微雪 WM8960 Audio HAT、幻尔载板 |
| 3.5.0 | 幻尔音频子板；BMI08x、ICM42688 两款 IMU |

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

用非官方音频板时，先确认你的系统版本覆盖了它。

音频切换用 `srpi-config`。3.4.1 的更新里提到「srpi-config 音频配置流程改进，与 Ubuntu PulseAudio 通道切换保持同步」——**老版本上音频切换后可能需要手动重启 PulseAudio**。

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

### MIPI 摄像头接口

| 项目 | X5 单板 | X5 Module 载板 |
| --- | --- | --- |
| 路数 | 2 路 | 2 路（CAM1 / CAM2，各 4 lane） |
| 集成信号 | MIPI CSI、LPWM&MCLK、I²C、GPIO | 同左 |

**红线**：开发板未断电时**禁止插拔摄像头**，极易烧坏模组。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

### 显示接口

| 接口 | 规格 | 备注 |
| --- | --- | --- |
| HDMI | 最高 1080P | Server 版只显示 logo |
| MIPI DSI | 22pin | 可用 `DSI-Cable-12cm` 接树莓派款 LCD |

3.0.1 起支持 7 款微雪 MIPI DSI 屏的桌面显示与触控；3.4.1 新增 11.9 英寸微雪宽屏适配，并修复多个屏幕的触摸坐标异常。

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

**触摸坐标异常**是老版本常见问题，升级到 3.4.1+ 通常能解决。

### 调试串口（不是 40PIN）

| 型号 | 接口位置 | 波特率 |
| --- | --- | --- |
| RDK X5 | Micro-USB（接口 4） | **115200** |
| RDK X5 Module | Micro-USB（背面接口 22） | **921600** |

其余参数两者相同：8 数据位、无校验、1 停止位、无流控。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

内核启动阶段波特率配置在 `/boot/boot.cmd`，改完需要重新生成：

```bash
mkimage -C none -A arm -T script -d boot.cmd boot.scr
```

X5 Module 的调试串口通常需要装 **CH340 驱动**。

## 六、传感器与 IMU 接口

| 型号 | 接口 | 说明 |
| --- | --- | --- |
| RDK IMU Module（BMI088） | **I2C** | 6 轴：三轴陀螺仪 + 三轴加速度计 |
| ICM42688 | I2C | 3.5.0 起新增接口支持 |

> 来源：官方文档 Quick_start/accessory（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/accessory）
> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

**IMU 走 I2C，所以与 `i2c0`/`i2c1`/`i2c5` 的复用配置直接相关**。接了 IMU 又开了 PWM 或 UART，可能互相冲突。

## 七、温度与频率接口

三路温度传感器：

```bash
cat /sys/class/hwmon/hwmon0/temp1_input   # DDR
cat /sys/class/hwmon/hwmon0/temp2_input   # BPU
cat /sys/class/hwmon/hwmon0/temp3_input   # CPU
```

单位 0.001°C。

调频能力差异：

| 模块 | 调频 | 调压 |
| --- | --- | --- |
| CPU | ✅ | ✅ |
| GPU 3D | ✅ | ❌ |
| BPU | ✅ | ❌ |
| DDR | ✅ | ❌ |

> 来源：官方文档 Advanced_development/linux_development/driver_development_x5/driver_lowpower（https://developer.d-robotics.cc/rdk_x_doc/Advanced_development/linux_development/driver_development_x5/driver_lowpower）

**只有 CPU 支持调压**。想通过降压实测省电，只能动 CPU。

## 常见误区

1. **「3.3V 能出 800mA，所以每个 3.3V 脚都能给 800mA」** —— 是**合计**上限。多路负载要加总算。
2. **「把脚配成 GPIO 就能直接读写」** —— X5 引脚默认使能了 UART/SPI/I2C/I2S，必须先 `srpi-config` 把冲突组全部 `disabled` 并重启。
3. **「`spi2` 和 `pwm0` 可以同时用」** —— 不行，`spi2` 同时与 `pwm0`、`pwm1` 冲突。
4. **「示例里的 37 号是 GPIO37」** —— 是**物理引脚号**。GPIO 编号是芯片内部编号，两者不相等。
5. **「热插拔 MIPI 摄像头没事」** —— 官方明确警告会烧坏模组。杜邦线接其他板卡也要求先下电。
