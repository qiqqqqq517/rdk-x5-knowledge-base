# 1.3 首次启动与入门配置

## 本章解决什么

镜像烧好、板子上电之后，真正决定你后面几天顺不顺的，是头三十分钟有没有把「能看到系统在干什么」这件事解决掉。HDMI 不出图、串口接不上、登进去却不知道 IP、想连 Wi-Fi 又没有桌面——这些都不是故障，而是首次启动阶段的必经配置。本章按「看灯 → 接串口 → 登录 → 跑 configuration_wizard → 用 srpi-config 补齐时区语言与接口 → 处理首启异常」的顺序讲，所有串口参数、菜单路径、命令都按 RDK X5 与 RDK X5 Module 分开标注，因为两者的调试串口波特率不同（115200 与 921600），填错就是一堆乱码。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

## 1.3.1 指示灯：能信哪一条

RDK X5 面板上有两颗状态灯。官方在不同页面给了三种不完全一致的表述，先把原文摆清：

**硬件简介页第一段**：「将电源适配器接入开发板后， 绿色 电源指示灯 亮起 ，说明开发板供电正常，3.1.0 版本后， 橙色 状态指示灯 闪烁 ，说明系统运行正常。」

**硬件简介页第二段（同一节内紧接着）**：「将电源适配器接入开发板后， 绿色 5V 指示灯 PWR 指示灯 亮起 ，说明开发板供电正常， 绿色 ACT 指示灯 闪烁 ，说明系统运行正常。」

**烧录页与 miniboot 页**：「绿色灯 点亮表示供电正常，橙色灯 闪烁表示系统启动完成。」

三处共同点只有一个：**绿色灯亮 = 供电正常**。分歧在于「运行正常」到底是橙色灯闪还是绿色 ACT 灯闪。这个分歧无法从文档内部消解，因为它同时出现在同一页面的相邻段落里。

再看社区的一手证据。帖 34973 的标题是「X5烧录完系统绿灯常亮，橙灯闪烁，HDMI，ssh，串口均无反应」——绿灯常亮、橙灯闪烁两个条件同时满足，但板子是不可用的状态，根因是 SD 卡没被识别。该帖第 6 楼用户把卡处理正常之后，串口能进系统了，此时的现象描述里并没有提到灯的变化。而帖 35125 的标题是「在烧录官方OriginCar镜像后，RDK X5系统无法正常启动，只有绿灯常亮，橙灯不闪烁」——这一例里「橙灯不闪」确实对应启动失败。

把三方证据合起来，可以给出一条可用的判读规则：

| 灯的状態 | 能推出什么 | 不能推出什么 |
| --- | --- | --- |
| 绿灯亮 | 5V 供电到位 | 不能推出电流够（带载能力另说） |
| 绿灯不亮 | 供电没到 / 线材或适配器问题 | — |
| 橙灯闪烁 | CPU 在跑，系统进入过启动流程 | **不能推出系统已可用**（帖 34973 反例） |
| 橙灯完全不闪 | 极可能启动失败（帖 35125 案例） | 不能确定失败在哪一层 |

结论：**灯只能用来做「有没有电」和「CPU 有没有动」的粗判，不能作为启动成功的判据。** 判启动成功必须靠串口输出或 HDMI 桌面。这也是为什么本章第二节就讲串口——它是唯一能在 HDMI 不出图时告诉你「卡在哪一行」的通道。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）、官方文档 Quick_start/system-burn/burn-sd-card（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/system-burn/burn-sd-card）、社区帖 34973（https://forum.d-robotics.cc/t/topic/34973）、社区帖 35125（https://forum.d-robotics.cc/t/topic/35125）

## 1.3.2 串口登录

### 1.3.2.1 硬件连接

调试串口是全板载 X5 的**接口 4**（Micro USB），是 Module 的**背面接口 22**。用 Micro-USB 线把开发板这个口连到 PC 即可。注意这条线必须是数据线——纯充电线只有电源脚，接上去设备管理器里什么都不会出现。

全板载 X5 与 Module 的串口参数不同：

| 参数 | RDK X5 | RDK X5 Module |
| --- | --- | --- |
| 波特率（Baud rate） | **115200** | **921600** |
| 数据位（Data bits） | 8 | 8 |
| 奇偶校验（Parity） | None | None |
| 停止位（Stop bits） | 1 | 1 |
| 流控（Flow Control） | 无 | 无 |

也就是常说的 **115200-8-N-1**（X5）与 **921600-8-N-1**（Module）。填错波特率的唯一表现是满屏乱码或完全无输出，不会报错。

驱动方面，官方说明「通常情况下，用户第一次使用该接口时需要在电脑上安装 CH340 驱动，用户可搜索 CH340串口驱动 关键字进行下载、安装」。远程登录章节补充说驱动「可从资源中心的工具子栏目获取」，装好后设备管理器应能识别到串口板端口。Windows 下识别为 `COMx`，Linux 下为 `/dev/ttyUSB0` 或 `/dev/ttyACM0`。

### 1.3.2.2 用 MobaXterm 建串口会话

官方以 MobaXterm 为例给了步骤（Putty 同理）：

1. 打开 MobaXterm，点 `Session`，选 `Serial`。
2. 配置端口号，例如 `COM3`——实际以 PC 识别到的为准。
3. 按 3.2 节的表配置波特率、数据位、奇偶校验、停止位、流控。
4. 点 `OK`，出现登录提示后输入用户名 `root`、密码 `root`（或 `sunrise` / `sunrise`）。

官方的串口登录示例给的是 `root` / `root`，而 FAQ 同时列出两种账户，两个都能用。

### 1.3.2.3 内核阶段的串口配置

如果需要在 U-Boot/内核阶段改波特率，官方说明配置位置在 `/boot/boot.cmd`，改完必须重新生成 `boot.scr`：

```bash
# 修改 /boot/boot.cmd 后，重新生成 boot.scr（需要 root，需已安装 u-boot-tools）
sudo mkimage -C none -A arm -T script -d /boot/boot.cmd /boot/boot.scr
```

这条命令要格外小心：`boot.scr` 是 U-Boot 执行的脚本，写坏了板子就进不去系统，只能靠 XBurn 重刷 miniboot 恢复。除非确有需要（例如接了工业设备必须用特定波特率），否则不要动。

### 1.3.2.4 上电时序与「卡在 hobot>」

一个高频问题：串口能显示，但停在 `hobot>` 提示符不动了。FAQ 的解释是「在板卡上电启动的最初几秒内，如果调试串口接收到了某些非预期的字符或电平信号（例如，键盘误触、串口终端软件自动发送的某些控制字符），可能会中断 U-Boot 的自动引导流程，使其停在命令行」。

处置很轻：

```
boot
```

在 `hobot>` 下直接输入 `boot` 回车，通常会继续引导。预防则更简单——先接好串口线、打开终端，**再给板子上电**，并且上电那几秒不要敲键盘。如果反复进 U-Boot，可以拔掉串口线单独上电试一次，用来区分是串口干扰还是引导介质有问题。

FAQ 另外提到「复位 U-Boot 环境变量」这条兜底路径（`env default -a; saveenv; reset`），但明确标注「此操作会清除所有自定义环境变量，请谨慎」，且「具体命令需查阅对应 U-Boot 版本的文档」。RDK X5 的 U-Boot 是 2022.10 版本，与旧版命令集不完全一致，执行前先在 `hobot>` 下用 `help` 确认命令存在。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）、官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）、官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）

## 1.3.3 首次启动的时间预期

官方对首次启动给了一个明确数字：「系统首次启动时会进行默认环境配置，整个过程持续 45 秒左右。」

这个 45 秒的口径需要正确理解：它指的是**从内核接管到出现登录界面**的默认环境配置阶段，不包含 U-Boot 之前的 BootROM/BL1/BL2/DDR 训练阶段。从帖 34478 的完整串口日志可以看到，DDR 训练本身耗时 `ddr cost: 153465 us`（约 0.15 秒），但从上电到 `Starting kernel …` 大约占了 3–4 秒，再加上内核初始化，实际从上电到能登录普遍在 1 分钟量级。

判据：**超过 2 分钟无输出即判定启动异常。** 官方原文是「如果开发板上电后长时间没有显示输出（2 分钟以上），说明开发板启动异常，需要通过串口线进行调试，查看开发板是否正常」。miniboot 文档的表述是「若串口 2 分钟以上无输出或日志停住，设备无法启动时，重新烧录」。

这两句话给了两条不同的动作：HDMI 无输出但串口有输出 → 是显示子系统问题，继续用串口；串口也无输出 → 是启动本身失败，重烧或查供电。

> 来源：官方文档 Quick_start/system-burn/burn-sd-card（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/system-burn/burn-sd-card）、官方文档 Quick_start/system-burn/upgrade-miniboot（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/system-burn/upgrade-miniboot）、社区帖 34478（https://forum.d-robotics.cc/t/topic/34478）

## 1.3.4 默认账户

| 账户类型 | 用户名 | 密码 | 说明 |
| --- | --- | --- | --- |
| 普通用户 | `sunrise` | `sunrise` | 默认账号，`srpi-config` 里改密码改的就是它 |
| 超级用户 | `root` | `root` | 串口登录常用 |

官方 FAQ 对默认账户加了一句限定：「具体默认账户和密码可能因您烧录的系统镜像版本和来源略有不同，建议查阅该镜像的发行说明。」

需要特别指出一处社区错误信息：帖 34973 的自动回复里写「默认用户名密码：用户名：rdk 或 ubuntu，密码：rdk 或 ubuntu（或烧录时设置的密码）」。**这组账号在 RDK X5 上不存在**，是把其他板卡的默认值混进来了。同帖该回复还写了「IP地址 198.168.127.10 是非标准网段」——这也是错的，`192.168.127.10` 正是官方默认静态 IP，只是被误读成了 198。这类自动生成的回复在社区里数量不少，读到时要回到官方文档核对。

> 来源：官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）、社区帖 34973（https://forum.d-robotics.cc/t/topic/34973）

## 1.3.5 入门配置（configuration_wizard）

官方「入门配置」章节有两条前置约束，读之前先确认：

- 仅支持 RDK X3、RDK X5 和 RDK X3 Module 型号。
- **系统版本不低于 2.1.0。**

X5 从 3.0.0 起，所以这条对本卷读者不构成限制。

### 1.3.5.1 连接 Wi-Fi

**桌面版**：用菜单栏右上角的 Wi-Fi 管理工具，点要连的 Wi-Fi 名，在弹出的对话框输入密码。

**Server 版**：用 `srpi-config`。

```bash
# 需要 sudo
sudo srpi-config
```

菜单路径 `System Options -> Wireless LAN`，按提示依次输入 Wi-Fi 名（SSID）和密码（passwd）。

Server 版还有一条纯命令行的路径（LAN access 一节），适合脚本化：

```bash
# 扫描（需要 sudo；扫描过于频繁会报错，等几秒再试）
sudo nmcli device wifi rescan

# 列出扫到的热点（需要 sudo）
sudo nmcli device wifi list

# 连接指定热点（需要 sudo）
sudo wifi_connect "SSID" "PASSWD"
```

成功时返回形如 `Device 'wlan0' successfully activated with 'd7468833-4195-45aa-aa33-3d43da86e1a7'.`。若返回 `Error: No network with SSID 'WiFi-Test' found.`，说明热点没扫到，重新 rescan 后再连。若 rescan 返回 `Error: Scanning not allowed immediately following previous scan.`，是扫描太频繁，官方说明「需要稍后再试」。

### 1.3.5.2 开启 SSH

官方明确「当前系统版本默认开启 SSH 登录服务」，这一节的方法是用于**关掉或重新打开**。

- 桌面版：菜单栏 `RDK Configuration` → `Interface Options -> SSH`。
- Server 版：`sudo srpi-config` → `Interface Options -> SSH`。

`srpi-config` 的说明也印证了默认值：「SSH：使用 SSH 启用/禁用对 RDK 的远程登录。默认情况下系统是启用 SSH 选项的。」

### 1.3.5.3 开启 VNC

桌面版：菜单 `RDK Configuration` → `Interface Options -> VNC`。官方说明「选择使能 VNC 时需要设置登录密码，密码必须是一个 8 位长度的由字符组成的字符串」——8 位是硬要求，短一位会被拒。

`srpi-config` 侧的描述是「启用/禁用 X11vnc 虚拟网络计算服务器」。VNC 默认是关的，需要手动开。

### 1.3.5.4 设置登录模式

桌面版有四种：

1. 开启图形化界面，自动登录
2. 开启图形化界面，用户手动登录
3. 字符终端，自动登录
4. 字符终端，用户手动登录

官方在这里插了一句关键限制：**「X5 系列板卡暂时不支持字符终端登录模式。」** 也就是说 X5 只能选前两种（图形界面），选字符终端那两项不会生效。这是 X5 与 X3 的一处实质差异，很多从 X3 迁过来的用户会在这里踩空。

Server 版只有两种（字符终端自动登录 / 字符终端用户手动登录），路径同样是 `System Options -> Boot / Auto Login`，改完重启生效。

### 1.3.5.5 设置中文环境

路径 `Localisation Options -> Locale`，三步：

1. 选择需要用的语言环境（多选），一般勾 `en_US.UTF-8 UTF-8` 和 `zh_CN.UTF-8 UTF-8` 两项，回车确认。
2. 选择默认语言环境，中文选 `zh_CN.UTF-8 UTF-8`，回车后等待配置完成。
3. 重启生效。

```bash
# 重启（需要 sudo）
sudo reboot
```

官方给了一条很实用的提示：开机时会问要不要更新 home 目录下几个常用文件夹的名称，「建议选择 `Don't ask me again Keep Old Name`，这样可以保持用户工作目录下的 Desktop Documents Downloads 等目录名不随语言环境发生变化」。

这条建议的理由值得说明：如果选了「更新名称」，`~/Desktop` 会变成 `~/桌面`、`~/Downloads` 变成 `~/下载`。而大量脚本、教程、容器挂载路径、`systemd` 服务里写的是英文路径。改完之后要么路径失效，要么你得写 `~/桌面` 这种带中文的路径——在 SSH 传输、rsync 同步、脚本参数里全是麻烦。

### 1.3.5.6 设置中文输入法（仅桌面版）

三步：右键桌面右上角 `EN` 输入法标志 → 首选项 → 「输入法」右侧点添加 → 选中文 → 选「智能拼音」。之后右键 `EN` 即可切换到智能拼音。

### 1.3.5.7 用户管理

改用户名（以 `usertest` 为例）：

```bash
# 关闭 sunrise 用户所有进程（需要 sudo）
sudo pkill -u sunrise

# sunrise 用户改名为 usertest（需要 sudo）
sudo usermod -l usertest sunrise

# 用户的家目录改为 /home/usertest（需要 sudo）
sudo usermod -d /home/usertest -m usertest

# 修改用户密码（需要 sudo）
sudo passwd usertest
```

最后还要改自动登录配置，把 `/etc/lightdm/lightdm.conf.d/22-hobot-autologin.conf` 里的 `autologin-user=sunrise` 改为 `autologin-user=usertest`。**这一步漏掉的表现是：改完用户名重启后，桌面登录界面反复退回登录框，或者直接黑屏。**

新增用户（以 `usertest` 为例）：

```bash
# 创建用户并加入必要用户组（需要 sudo）
sudo useradd -U -m -d /home/usertest -k /etc/skel/ -s /bin/bash -G disk,kmem,dialout,sudo,audio,video,render,i2c,lightdm,vpu,gdm,weston-launch,graphics,jpu,ipu,vps,misc,gpio usertest

# 设置密码（需要 sudo）
sudo passwd usertest

# 复制 skel 模板（需要 sudo）
sudo cp -aRf /etc/skel/. /home/usertest

# 修正属主（需要 sudo）
sudo chown -R usertest:usertest /home/usertest
```

那串 `-G` 参数不能省也不能少。少了 `video` 就没法访问摄像头设备节点，少了 `i2c` 就没法用 `i2cdetect`，少了 `gpio` 就没法操作 `/sys/class/gpio`，少了 `vpu`/`jpu`/`ipu`/`vps` 就跑不了硬件编解码与视觉加速。这是 RDK 平台特有的用户组约定。

> 来源：官方文档 Quick_start/configuration_wizard（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/configuration_wizard）、官方文档 System_configuration/srpi-config（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/srpi-config）、官方文档 System_configuration/network_bluetooth（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/network_bluetooth）

## 1.3.6 srpi-config 全菜单

`srpi-config` 是 X5 上最核心的系统配置入口，`configuration_wizard` 里的很多项其实就是它的子集。启动方式：

```bash
# 必须带 sudo，否则无法修改系统文件
sudo srpi-config
```

官方解释为什么要 sudo：「`sudo` 是提权管理命令，这里必须输入，这样就可以 root 权限来进行配置管理，默认的 `sunrise` 账号不具备系统文件修改权限。」

桌面系统也可以从菜单里点 `RDK Configuration` 应用，效果相同。

### 1.3.6.1 System Options

| 项目 | 作用 | 备注 |
| --- | --- | --- |
| Wireless LAN | 设置无线网络 SSID 与密码 | — |
| Password | 更改「默认」用户密码 | 默认账号 `sunrise` |
| Hostname | 设置设备在网络上的可见名称 | — |
| Boot / Auto login | 引导到控制台还是桌面，是否自动登录 | 自动登录使用 `sunrise` 身份 |
| Power LED | 更改电源 LED 行为 | 依型号支持情况而定，默认熄灭或闪烁 |
| Browser | 设置默认浏览器 | 默认 firefox；可 `sudo apt install chromium` |

### 1.3.6.2 Display Options

| 项目 | 作用 | 备注 |
| --- | --- | --- |
| FB Console Resolution | 设置 Server 与 console 模式下 HDMI 分辨率 | — |
| Display Chose DSI or HDMI | DSI 与 HDMI 显示切换 | **仅 RDK X5 支持** |

这一项是 X5 独有的。切换也可以在命令行做（官方给了等价命令）：

```bash
# 切到 HDMI：启用 hdmi 配置、禁用 dsi 配置（需要 root）
sudo mv /etc/X11/xorg.conf.d/xorg_hdmi_ignore.conf /etc/X11/xorg.conf.d/xorg_hdmi_ignore.conf.disable
sudo mv /etc/X11/xorg.conf.d/xorg_dsi_ignore.conf.disable /etc/X11/xorg.conf.d/xorg_dsi_ignore.conf
```

反向切到 DSI 就把这两条对调。改完需重启。

### 1.3.6.3 Interface Options

SSH、VNC、SPI、I2C、I2S、Serial 等接口的启用/禁用都在这里。其中 `Peripheral bus config` 有一张必须记住的复用表：

官方原文：「本配置方式会直接修改使用的设备树文件的对应总线的 status，重启后生效。」并且「下表中，每行的接口使用相同的引脚，同时只能生效一种功能，当一行的所有接口都为 disable 时，引脚为 gpio 功能脚」。

| 功能 1 | 功能 2 |
| --- | --- |
| serial3 | i2c5 |
| i2c0 | pwm2 |
| spi2 | pwm0 |
| spi2 | pwm1 |
| i2c1 | pwm3 |

这张表的实际含义：同一行两项抢同一组引脚。想用 `i2c5` 就必须关掉 `serial3`；想用 `pwm2` 就必须关掉 `i2c0`。`spi2` 同时跟 `pwm0` 和 `pwm1` 冲突——开了 SPI2，两路 PWM 都用不了。

`Configure Wi-Fi antenna` 用于切换板载/外置天线：`Onboard` 板载，`External` 外置。官方注明支持范围是「RDK X3（V2.1）、RDK X5（V0.1 V1.0）、RDK X5 MD（小于 V1.1）」。改完可以用命令确认：

```bash
# 查看天线配置（不需要 sudo）
cat /boot/config.txt | grep antenna_option
```

`antenna_option=trace` 表示板载天线，`antenna_option=cable` 表示外置天线。

`Audio` 用于安装/卸载音频转接板，可能支持的包括 Audio Driver HAT V1、Audio Driver HAT V2、WM8960 Audio HAT。

### 1.3.6.4 Performance Options

| 项目 | 作用 | 注意事项 |
| --- | --- | --- |
| CPU frequency | CPU 超频 | 官方：「一般不建议开启，如果做好充分散热工作可以尝试修改此选项」 |
| ION memory | 配置 ION 内存大小 | 默认 672MB |

ION 内存的官方定义值得抄下来：「ION 内存是预留出来给 BPU 和图像、视频多媒体功能的物理内存空间。默认配置大小为 672MB，如果需要运行比较大的算法模型、同时编解码多路视频时，请根据具体需要调整该内存大小。」

这条决定了你跑大模型时的表现：ION 不够的直接症状是模型加载失败或编解码创建通道失败，而不是报「内存不足」。反过来，把 ION 调得太大，系统可用内存（`free -h` 里的 MemAvailable）会显著下降，跑桌面时容易 OOM。

X5 的 ION 还可以从 `config.txt` 精调，分三块：

| boot 环境变量名 | dts 标签 | compatible 字符串 | 默认大小 |
| --- | --- | --- | --- |
| `ion_reserved_size` | `ion_reserved` | `ion-pool` | 320M |
| `ion_carveout_size` | `ion_carveout` | `ion-carveout` | 320M |
| `ion_cma_size` | `ion_cma` | `ion-cma` | 128M |

```
ion=ion_reserved_size=0x14000000
ion=ion_carveout_size=0x14000000
ion=ion_cma_size=0x08000000
```

改完可以从启动日志确认：

```bash
# 查看 ION 各区域实际大小（不需要 sudo）
dmesg | grep "Reserved ion"
```

典型输出形如 `Reserved ion-pool MEM start 0xa4100000, size 0x14000000`。三块加起来 320+320+128 = 768M，与 srpi-config 里说的「默认 672MB」口径不同——前者是 dts 默认值，后者是 srpi-config 的档位表述，实际以 `dmesg` 打印为准。

### 1.3.6.5 Localisation Options

| 项目 | 作用 |
| --- | --- |
| Locale | 选择语言环境，如 `zh_CN.UTF-8`，重启生效 |
| Time Zone | 选时区，从地区开始（如亚洲 → 上海）；输入字母可跳到字母表对应位置 |
| Keyboard | 键盘布局；「读取所有键盘类型需要很长时间才能显示」 |

时区这一项的正确做法是**在配置 Wi-Fi 之后立刻做**。原因：不设时区时系统时间是 UTC，日志时间戳会跟你的实际作息差 8 小时，排查「几点钟发生的故障」时会对不上；更实际的是，`apt update` 依赖 HTTPS 证书校验，如果 RTC 电池没装、时间回到出厂值，证书会被判过期，报 `Certificate verification failed`。

也可以直接用命令设时区，不一定要进菜单：

```bash
# 列出可用时区（不需要 sudo）
timedatectl list-timezones | grep Shanghai

# 设置时区（需要 sudo）
sudo timedatectl set-timezone Asia/Shanghai

# 核对（不需要 sudo）
timedatectl
```

### 1.3.6.6 Advanced Options

| 项目 | 作用 |
| --- | --- |
| Expand Filesystem | 扩展安装以填满整个 TF 卡 |
| Network Proxy Settings | 配置网络代理 |
| Boot Order | 切换 eMMC / SD 卡启动（仅 Module） |

`Expand Filesystem` 的官方说明点出了一个具体场景：「如果系统是通过从另一张已经完成初始化配置的系统中复制而来的，那么系统的 TF 卡容量可能不会被自动调整为当前 TF 卡的容量。使用此功能可以方便地完成扩展。」

这正是第 5 章要讲的 `rdk-backup` 备份还原场景——把 32G 卡的镜像还原到 128G 卡上，系统只会用到 32G，剩下的必须手动扩。也可以直接用命令行做：

```bash
# 查看磁盘与分区（不需要 sudo）
lsblk
df -h /

# 在线扩容根分区（需要 sudo，ext4 支持在线 grow）
sudo resize2fs /dev/mmcblk1p2
```

`resize2fs` 只扩文件系统，前提是分区本身已经扩大。如果分区表还是旧大小，需要先用 `gparted` 或 `parted` 扩分区再 `resize2fs`。

### 1.3.6.7 Sensor Profiles

`IMX219 Switch ISP` 用于切换 IMX219 效果库。官方说明：`1 FOV 79.3°` 对应 Jetson Nano 摄像头（适配 200FOV 和 160FOV 的模组），`2 FOV 120°` 对应树莓派 5 代摄像头（适配 120FOV 模组）。原理是「由于模组在光学和调校上的差异，最终成像效果及强度会有所不同，因此需要分别进行 ISP 校准」。选错的表现是画面偏色、暗角或亮度异常，不是「不能用」。

### 1.3.6.8 Update 与 Finish

`Update` 把 srpi-config 工具本身更新到最新版。`Finish` 完成所有更改——官方说明「如果您所做的修改需要重启才能生效，系统将提示您是否立即重新启动」。绝大多数项（Locale、Display、Peripheral bus）都需要重启。

## 1.3.7 首次启动常见异常

### 1.3.7.1 异常 A：HDMI 接上显示器完全无信号

**现象**（帖 34076 原文）：「HDMI连接从网上购买的ADKEFOX深圳永新高科1280x800@60屏没有信号」。同帖还记录了一个诊断细节：「在RDK X5的终端输入xrandr命令,输出`Can't open display`；连接能正常出图的HDMI显示器，xrandr也是同样输出」——说明 `xrandr` 在这个系统上本来就跑不了，不能用它判断 HDMI 好坏。该帖还发现「配置分辨率的文件是disable的: `/etc/X11/xorg.conf.d/1-resolution.conf.disable`」，而「将 `/etc/X11/xorg.conf.d/1-resolution.conf.disable` 修改为 `1-resolution.conf` 会引起系统反复重启」。

**根因**：三条线索指向不同层面。① 显示器兼容性：官方 FAQ 说明「部分显示器可能与 RDK 板卡输出的特定分辨率或刷新率不完全兼容」。② 显示输出可能被切到了 DSI：X5 的 HDMI 与 MIPI DSI 互斥，系统默认走 HDMI，但被切过就回不来。③ 强行启用分辨率配置会导致 X 反复崩溃，进而被 display manager 反复重启。

**处置**：

```bash
# 1. 先确认系统本身起来了（串口能登录就说明系统正常，只是显示问题）
# 2. 用 srpi-config 强制切回 HDMI
sudo srpi-config
#    Display Options > D1 Display Choice > 2 HDMI，重启
```

```bash
# 3. 或走命令行等价路径（需要 root）
sudo mv /etc/X11/xorg.conf.d/xorg_hdmi_ignore.conf /etc/X11/xorg.conf.d/xorg_hdmi_ignore.conf.disable
sudo mv /etc/X11/xorg.conf.d/xorg_dsi_ignore.conf.disable /etc/X11/xorg.conf.d/xorg_dsi_ignore.conf
sudo reboot
```

如果确认是分辨率不兼容，可以改 `/etc/X11/xorg.conf.d/1-resolution.conf` 里的 `Modes`，官方示例给的是 `"1280x720"`：

```
Section "Screen"
    Identifier "Screen0"
    Device     "Device0"
    Monitor    "Monitor0"
    DefaultDepth 24
    SubSection "Display"
        Depth 24
        Modes "1280x720"
    EndSubSection
EndSection
```

**预防**：首次上电优先用一台标准 1080P 显示器验证，确认没问题再换小尺寸/异形屏。官方 FAQ 的原话是「通常情况下，标准的 1080p (1920x1080) 分辨率的显示器在板卡启动时直接连接，兼容性会比较好」。

> 来源：社区帖 34076（https://forum.d-robotics.cc/t/topic/34076）、官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）、官方文档 Quick_start/display_use/display_rdkx5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/display_use/display_rdkx5）

### 1.3.7.2 异常 B：误用电脑 USB 口供电后 DDR 报错，重烧也没用

**现象**（帖 34349 原文）：「误用电脑供电后无法进入系统，重新烧录后还是不行。使用串口登录后发现如下报错：

```
ERROR: invalid ddr adc value:1122mv
ERROR: invalid ddr type:0 rank type:0, use 3200
ERROR: invalid ddr type:0 rank type:0 freq:3200, disable dvfs；
```

」

**根因**：这三条是 BL2 阶段 DDR 参数探测失败的输出。`invalid ddr adc value:1122mv` 说明用来识别颗粒类型的 ADC 采样值落在合法区间外；`invalid ddr type:0 rank type:0` 说明类型与 rank 都读成了 0（即无效值）；系统于是回退到硬编码的 3200 频率并关掉 DVFS。帖内官方回复给的处置只有一句：「重新进行miniboot的烧录」。

机制上讲得通：DDR 的容量/类型/频率这些参数存在板载 NAND 侧的 bootinfo/veeprom 区域，由 miniboot 读取并据此初始化 DDR。供电异常（尤其是电压跌落）可能导致这部分参数被写坏或读取异常，而系统镜像在 SD 卡上，重烧 SD 卡完全不影响这块 NAND——所以「重烧镜像没用」。

**处置**（顺序不能反）：

```bash
# 第一步：用 XBurn 重刷 miniboot（连接类型选 Serial+USB，因为系统已进不去）
# 第二步：确认 boardid 是否正确
sudo hrut_boardid g
```

```bash
# 第三步：核对 DDR 相关字段。boardid 各 bit 含义见下表
# 注意：boardid 会影响到启动时硬件的初始化，不要随意 set
```

| 字段 | 位 | 含义 |
| --- | --- | --- |
| `auto detect` | bit[31] | 0x0 自动探测；0x1 不使用 LPDDR4 auto detection |
| `model` | bit[30:28] | DDR 厂商：0x1 hynix、0x2 micron、0x3 samsung |
| `ddr_type` | bit[27:24] | 0x1 LPDDR4、0x2 LPDDR4X、0x3 DDR4、0x4 DDR3L |
| `frequency` | bit[23:20] | 0x1 667 / 0x2 1600 / 0x3 2133 / 0x4 2666 / 0x5 3200 / 0x6 3733 / 0x7 4266 … |
| `capacity` | bit[19:16] | 0x1 1GB、0x2 2GB、0x4 4GB |

**预防**：这条异常的价值在于它给出了一个明确的反面教材——**电脑 USB 口不只是「供电不足会重启」，它还可能把 DDR 参数写坏，导致重烧镜像无效**。所以第 1 章反复强调的 5V/5A 适配器不是形式要求。

> 来源：社区帖 34349（https://forum.d-robotics.cc/t/topic/34349）、官方文档 Appendix/rdk-command-manual/cmd_hrut_boardid（https://developer.d-robotics.cc/rdk_x_doc/Appendix/rdk-command-manual/cmd_hrut_boardid）

### 1.3.7.3 异常 C：改了 locale 之后桌面反复退回登录界面

现象：按 3.5 节设完中文环境并重启，图形界面停在登录框，输入正确密码后又回到登录框。

根因：这是「改了用户名却漏改自动登录配置」或「改了 locale 但 home 目录下 XDG 目录被重命名」两类问题的共同表现。官方在改用户名一节特意点出要改 `/etc/lightdm/lightdm.conf.d/22-hobot-autologin.conf` 里的 `autologin-user`，正是因为 lightdm 记着一个写死的用户名；而 locale 设置时若在「是否更新目录名」对话框里选了「更新」，`~/Desktop` 等目录被改名，桌面环境的会话脚本找不到目录也会导致登录失败。

处置：

```bash
# 1. 用串口或 SSH 登录（图形界面进不去不影响 SSH）
# 2. 检查自动登录配置里的用户名
cat /etc/lightdm/lightdm.conf.d/22-hobot-autologin.conf

# 3. 若与当前用户名不符，改正（需要 sudo）
sudo sed -i 's/^autologin-user=.*/autologin-user=sunrise/' /etc/lightdm/lightdm.conf.d/22-hobot-autologin.conf

# 4. 检查 home 目录下的实际目录名
ls -d ~/*/

# 5. 重启
sudo reboot
```

预防：设 locale 时在「update names of home directories」对话框选 `Don't ask me again Keep Old Name`，官方明确推荐这一项。

> 来源：官方文档 Quick_start/configuration_wizard（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/configuration_wizard）

### 1.3.7.4 异常 D：串口能进系统，但 SSH 和 HDMI 都进不去

**现象**（帖 34973 第 6 楼原文）：「串口可以进去了，我接网线看了一下ip，是192.168.127.10，但是我远程和HDMI还是进不去」。

**根因**：这是「系统已启动，但访问路径没配好」的典型。`192.168.127.10` 是官方默认静态 IP，本身完全正常；SSH 进不去的原因是 PC 与板子不在同一网段——PC 通常是 `192.168.1.x` 或由路由器 DHCP 分配，而板子是 `192.168.127.10/24`，跨网段且没有路由。HDMI 进不去是显示子系统问题（见异常 A）。

该帖第 8 楼官方人员的回复标准答案：「要用静态IP登录需要修改一下电脑端的以太网配置」——把 PC 的以太网口设成 `192.168.127.x`。

**处置**：PC 端静态 IP 配置（Windows 10/11）：

1. `Win + R` 输入 `ncpa.cpl` 回车，打开网络连接。
2. 找到连板子的那块以太网卡（不是 Wi-Fi），双击 → 属性。
3. 双击 `Internet 协议版本 4 (TCP/IPv4)`。
4. 选「使用下面的 IP 地址」，填 IP `192.168.127.100`、掩码 `255.255.255.0`、网关 `192.168.127.1`，DNS 可留空。
5. 确定保存，然后 `ping 192.168.127.10` 验证。

板子端确认监听状态：

```bash
# 在串口里执行，查看 22 端口是否监听（需要 sudo）
sudo netstat -tlnp | grep :22
```

如果端口没监听，检查 SSH 服务：

```bash
# 查看 SSH 服务状态（不需要 sudo 也能看）
systemctl status ssh
```

**预防**：把「板子静态 IP 是 192.168.127.10、PC 设 192.168.127.100」当成肌肉记忆。几乎所有「远程连不上」的第一诊断都是这条。想让板子走 DHCP 更省事，可以按第 4 章改成 DHCP 再由路由器做 MAC 绑定。

> 来源：社区帖 34973（https://forum.d-robotics.cc/t/topic/34973）、官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）

### 1.3.7.5 异常 E：apt 报证书过期

现象：`sudo apt update` 报 `Certificate verification failed: The certificate is NOT trusted` 或 `Release file ... is not valid yet`。

根因：系统时间是错的。X5 没有 RTC 电池时断电即丢时间，重启后回到镜像构建时间（通常是几个月前）。HTTPS 证书校验会用本地时间判断有效区间，时间早于证书生效时间即判定失败。第 1 章讲过 RTC 电池要求，这一条是它在软件侧的后果。

处置：

```bash
# 1. 先看当前时间（不需要 sudo）
date

# 2. 手动校时（需要 sudo）
sudo date -s "2026-11-02 14:30:00"

# 3. 装 NTP 并立即同步（需要 sudo）
sudo apt install -y systemd-timesyncd
sudo systemctl restart systemd-timesyncd
sudo timedatectl set-ntp true

# 4. 确认（不需要 sudo）
timedatectl
```

预防：装 RTC 电池（见第 1 章 1.4），或让板子长期联网靠 NTP 校时。注意第 2 步的 `date -s` 必须在 apt 能用之前执行——如果时间差得太多，`apt install` 本身也会因为证书失败而装不上，此时只能先手工设时间（这一步不需要联网）。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

## 常见误区

**误区一：把「橙灯闪烁」当成首次启动成功的标志，然后干等 HDMI。**
灯只能证明 CPU 在跑，不能证明系统可用（帖 34973 就是绿灯常亮 + 橙灯闪烁但完全不可用的反例）。正确做法是上电前就接好串口，从第一行日志开始看。

**误区二：给 X5 Module 用 115200 的波特率。**
Module 的调试串口是 **921600**，全板载 X5 是 **115200**。这个参数官方在三处文档里都标了，但仍有大量用户按 115200 接 Module 然后看到满屏乱码，误以为板子坏了。

**误区三：在 locale 设置里选「更新目录名称」。**
`~/Desktop` 变成 `~/桌面` 之后，所有写死英文路径的脚本、systemd 服务、容器挂载全部失效。官方明确建议选 `Keep Old Name`。

**误区四：以为 X5 可以设成字符终端登录。**
官方原文「X5 系列板卡暂时不支持字符终端登录模式」。想省显存、开机直进字符界面，在 X5 上做不到——要么用 Server 版镜像，要么就接受图形界面。

**误区五：看到 `192.168.127.10` 就怀疑 IP 配错了。**
这是官方默认静态 IP，不是错误值。社区帖 34973 的自动回复曾把它误读成「198.168.127.10 是非标准网段」并给出改 netplan 的方案，方向完全错了。真正要做的是把 PC 改到同一网段。
