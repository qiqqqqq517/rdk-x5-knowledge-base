# 第 1 章 开箱检查与配件清单

## 本章解决什么

拿到 RDK X5 之后，第一件事不是插电，而是确认手上这块板子到底是「全板载的 RDK X5」还是「核心板 + 载板的 RDK X5 Module」——两者的接口编号、调试串口波特率、存储介质、能不能用 eMMC 都不同，按错型号的文档操作是最常见的开局错误。本章先把芯片规格、14 个对外接口、连接器型号、接口负载能力逐项列清，再讲电源与 RTC 电池这两处最容易被忽略、也最容易直接烧板子的硬性要求，最后给出官方认证配件清单与开箱检查动作。读完本章，应当能在不通电的前提下判断「这套硬件齐不齐、能不能上电」。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

## 1.1 芯片与整机规格

RDK X5 是一款全功能开发板，官方给的定位是「具有 10Tops 端侧推理算力与 8 核 ARM A55 处理能力，支持 2 路 MIPI Camera 接入，4 路 USB3.0 接口」。这三个数字是选型时的核心口径：10 TOPS 指 BPU 的端侧推理算力，8 核 A55 指 CPU 侧，2 路 MIPI Camera 指板载 MIPI CSI 通道数。

| 项目 | 规格 | 说明 |
| --- | --- | --- |
| 智能计算芯片 | D-Robotics Sunrise 5 | X5 全板载；X5 Module 将其做成核心板 |
| CPU | 8 核 ARM Cortex-A55 | 内核日志中可见 `SMP: Total of 8 processors activated` |
| BPU 算力 | 10 TOPS | 端侧推理，双核 BPU（`bpu0` / `bpu1`） |
| 内存 | LPDDR4 / LPDDR4X，4GB 或 8GB | 机械图文件名标注 `LPDDR4_4266MHz`；8GB 版本串口日志打印 `DRAM: 7.9 GiB` |
| 存储 | Micro SD 卡（X5 全板载）；X5 Module 另有板载 eMMC | X5 以 SD 卡为系统启动介质 |
| 底层固件存储 | 板载 QSPI NAND | 存放 miniboot、U-Boot，串口日志显示 128 MiB |
| 无线 | Wi-Fi 2.4GHz/5GHz + 蓝牙 | 板载天线，可选外置 IPEX 1 代天线 |
| 有线 | 千兆以太网，支持 PoE | 1000BASE-T / 100BASE-T |
| 显示 | HDMI（最高 1080P60）+ MIPI DSI | 二者不能同时使用 |
| 工作温度 | 推荐环境温度 -20°C 至 60°C | 芯片最高结温 105°C，超过 95°C 自动降频 |

关于内存容量的版本差异，官方硬件文档本身没有单列一张「4GB / 8GB 型号对照表」，但可以从两处证据交叉确认：机械尺寸图与 PCB 文件名统一带 `LPDDR4_4266MHz`；而社区帖 31743 的串口日志里，`hrut_boardid` 相关的 DDR 探测结果为 `ddr info:[LPDDR4]-[DUAL_RANK]-[ECC OFF]-[DVFS ON]-[4266M]`、`ddr size: 8 GB`，U-Boot 侧再打印 `DRAM: 7.9 GiB`。也就是说 8GB 物理内存扣掉固件保留区后，系统可见约 7.9 GiB。4GB 版本同理，可用内存会明显低于标称值，看到 `Total Memory` 只有 3.x Gi 不必怀疑板子坏了。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）、官方文档 RDK（https://developer.d-robotics.cc/rdk_x_doc/RDK）、社区帖 31743（https://forum.d-robotics.cc/t/topic/31743）

### 全板载与模组的区别

官方硬件文档在同一个页面里把两种形态并列描述，读的时候必须分清哪一段说的是哪一种：

- **RDK X5（全板载）**：文档明确写「全板载设计， 无核心模组」。所有接口都在一块板上。
- **RDK X5 Module**：核心板集成 Sunrise 5 芯片及 PMIC、DDR、eMMC、QSPI NAND、Wi-Fi/蓝牙，提供 300 针高速扩展接口，插在 RDK X5 Module Carrier Board 载板上使用。

判断依据：如果你手上的板子能单独拿出一块约名片大小的核心板、并插在带 40PIN 与 RJ45 的载板上，那是 Module；如果是一整块板、没有可拆的核心板，那是全板载 X5。这个判断直接决定后面所有接口编号的对应关系——官方文档对两者使用了两套编号体系。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

### 接口电源负载能力

这是外设选型最容易踩坑的一张表。官方注明「以下数据均为单个接口能提供的负载电流，多个接口同时使用时，可能会受影响」。

| 接口 | 负载能力 |
| --- | --- |
| CAN 接口 | 500mA @ 3.3V |
| DSI 接口 | 500mA @ 3.3V |
| 40Pin 接口 | 1A @ 3.3V / 1A @ 5V |
| USB3 接口 | 1A @ 5V |

推论三条：① 4 路 USB3 若同时插满高功耗设备（如 4 个 USB 摄像头 + 4G 模块），总需求可能超过整板余量，此时必须给外设独立供电的 HUB；② 通过 40PIN 给外部大电流负载（舵机、继电器阵列）供电时，1A @ 5V 是上限，舵机堵转电流远超这个值，必须外接电源并共地；③ PoE 供电能省掉 Type-C 这根线，但 PoE 模块本身的功率预算不等于整板预算，大负载场景仍要核算。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

## 1.3 电源要求

### 硬性规格

官方对 RDK X5 的供电要求写得很直接：开发板提供一路 USB Type C 接口作为供电接口，**需要使用支持 5V/5A 的电源适配器**。

| 项目 | 要求 | 后果 |
| --- | --- | --- |
| 电压 | 5V | 接 12V 会烧毁板卡 |
| 电流 | 5A（官方适配器规格） | 低于此值可能异常断电 |
| 接口 | USB Type-C | 该口仅供电，不传数据 |
| 线材 | 正规品牌 USB Type-C 供电线 | 劣质线电阻大，压降导致掉电 |
| 认证型号 | 微雪 PSU-27W-USB-C-CN-B（5V/5A） | 官方配件清单列名 |

官方在硬件文档、烧录文档、miniboot 文档三处重复了同一条警告：「请不要使用电脑 USB 接口为开发板供电，否则会因供电不足造成开发板异常断电、反复重启等情况。」烧录文档还额外补了一句「选用正规品牌的 USB Type-C 口供电线，否则会出现供电异常，导致系统异常断电的问题」。

### 供电不足的现场表现

这一点社区经验比官方文档描述得更具体。社区帖 35112 的原始现象是：「上电后，有时候能进入到Ubuntu界面，然后过一段时间就会卡住，然后手机热点连接也会断掉，大部分时候重新插拔电源会重新连上网络但是进不去ubuntu界面。」该帖的诊断思路把四个现象逐一对应到根因：

| 现象 | 指向 |
| --- | --- |
| 间歇性启动成功 | 供电处于临界状态 |
| 运行一段时间后卡死 | 供电不足 / 过热 / 看门狗触发 |
| 网络断开且无法 ping | 系统级死机，不是网络配置问题 |
| 必须断电重启，软重启无效 | 硬件锁死 |

帖中给出的优先级判断是「供电不足是 80% 类似问题的根因」，并明确「不能用电脑 USB 口供电（仅 0.5A-0.9A）」「不能用 12V 电源（会烧毁板子！社区有案例）」。

需要说明的是，上述 80% 这个比例是该帖的诊断性表述，不是官方统计数据；官方文档只陈述了「供电不足会导致异常断电、反复重启」，没有给概率。作为排障顺序的依据「先查供电」是合理的，但不要把这个数字当成可引用的统计结论。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）、官方文档 Quick_start/system-burn/burn-sd-card（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/system-burn/burn-sd-card）、社区帖 35112（https://forum.d-robotics.cc/t/topic/35112）

### 指示灯含义（官方文档内部存在两种说法）

这是本仓库取证时发现的一处官方文档自相矛盾，必须如实列出，否则读者会被误导。

硬件简介页面同一节里连续两段给了两套说法：

- 第一段：「将电源适配器接入开发板后， 绿色 电源指示灯 亮起 ，说明开发板供电正常，3.1.0 版本后， 橙色 状态指示灯 闪烁 ，说明系统运行正常。」
- 第二段：「将电源适配器接入开发板后， 绿色 5V 指示灯 PWR 指示灯 亮起 ，说明开发板供电正常， 绿色 ACT 指示灯 闪烁 ，说明系统运行正常。」

烧录文档与 miniboot 文档则是第三种表述：「绿色灯 点亮表示供电正常，橙色灯 闪烁表示系统启动完成。」

社区实测帖 34973 的标题本身就是一手证据：「X5烧录完系统绿灯常亮，橙灯闪烁，HDMI，ssh，串口均无反应」——注意这里「绿灯常亮 + 橙灯闪烁」同时成立，但系统并未真正可用（该帖后续确认是 SD 卡识别问题）。而同帖第 6 楼用户把 SD 卡插好后串口能进系统，说明「橙灯闪烁」并不等于「一定进了系统」。

综合判断：**「绿灯常亮 = 供电正常」这条是三方一致的，可以放心用；「橙灯闪烁 = 系统启动完成」这条不可靠，只能作为「CPU 在跑」的弱信号，不能替代串口日志作为启动成功的判据。** 判启动成功请走串口（见第 3 章）。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）、官方文档 Quick_start/system-burn/burn-sd-card（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/system-burn/burn-sd-card）、社区帖 34973（https://forum.d-robotics.cc/t/topic/34973）

## 1.4 RTC 电池要求

RTC 电池接口（接口 2）在全板载 X5 上，靠近 PWR 的引脚为 B+，另一引脚为 GND。官方给了一段非常具体、但很容易被跳过不看的要求：

| 项目 | 要求 |
| --- | --- |
| 供电电压 | 2~3.3V |
| 放电电流 | > 2.5uA |
| 可承受最大充电电压 | ≥ 3.3V |
| 最大可允许充入电流 | > 1mA |

官方原文还补了两句关键机制说明：开机后当 PMIC 检测到 RTC 电压低到充电电压时，会自动给 RTC 充电；此外，**非充电的 RTC 电池不可以使用进行供电**。

这里的实际含义是：RDK X5 的 RTC 电路会给电池充电，所以必须用**可充电**的纽扣电池（如 ML 系列或带充电保护的 LIR 系列），不能直接焊一颗 CR2032 上去。CR2032 是一次电池，被强制充电有鼓包、漏液甚至起火风险。反过来，如果你只用一次电池且不希望它被充电，只能不装电池、靠网络对时，或者自行在电路上断开充电回路——但这已经超出官方支持范围。

另一个常被忽略的点：不装 RTC 电池时，断电后系统时间会丢失，重启后时间回到一个较早的默认值。这在没有网络的环境里会直接导致 apt 校验失败（证书时间不匹配）、日志时间错乱、TLS 握手失败。所以「时间总是回到 2023 年」这类现象，第一怀疑对象不是系统坏了，而是没装 RTC 电池或电池已耗尽。

> 来源：官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

## 1.6 存储卡选用

全板载 RDK X5 的启动介质只有 Micro SD 卡。官方要求「准备至少 16GB 容量的 Micro SD 卡，以便满足 Ubuntu 系统、应用功能软件对存储空间的需求」。Module 形态支持 SD 卡与 eMMC 二选一，同样推荐至少 16GB。

容量只说了下限，没说速度等级。速度等级的要求来自 FAQ 里针对 X3 的建议，但硬件机理通用：「建议使用高速 C10 (Class 10) 或更高级别 (例如 UHS Speed Class 1 (U1) 或 UHS Speed Class 3 (U3), Application Performance Class A1 或 A2) 的 Micro SD 卡」。FAQ 同时指出「一些较老、非品牌或低速的 SD 卡可能会存在烧录镜像后无法启动、系统运行缓慢或数据读写不稳定的问题」。

社区侧的证据更硬。帖 34478 是一整条 26 回复的长帖，症状是烧录 3.4.1 desktop 镜像后串口停在 `Starting kernel …` 无后续输出，BootROM → BL1/BL2 → DDR → BL31 → OP-TEE → U-Boot 全部正常。官方人员在帖末的判断是「板子出现问题概率比较低，不过也不是没有可能，建议先从SD卡排查一下」，并确认「miniboot没看到有问题，还是SD卡的问题」。帖 32282 里也有用户反馈「最后解决方法就是我换了SD卡就没有失败过了。可能是SD卡的问题」。

因此选卡建议按这个优先级：品牌高速卡（U3 / A2，16–64GB）> 容量 > 价格。不要用来源不明的赠品卡、监控卡或扩容卡。

> 来源：官方文档 Quick_start/system-burn/burn-sd-card（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/system-burn/burn-sd-card）、官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）、社区帖 34478（https://forum.d-robotics.cc/t/topic/34478）、社区帖 32282（https://forum.d-robotics.cc/t/topic/32282）

## 1.7 环境与散热

官方给出的工作条件是：推荐环境温度 -20°C 至 60°C，芯片最高结温 105°C，**当芯片结温超过 95°C 时，系统将自动启动降频机制以降低温度，可能会影响性能表现**。降频的粒度可以在串口日志里看到——CPU 最低降到 240MHz、BPU 最低降到 400MHz（见 `config.txt` 的 `throttling_temp` 说明）。

散热建议分两个阶段：

- 开发与测试阶段：建议配备散热片、RDK Case 及散热风扇等辅助散热措施。
- 产品化阶段：请根据整机热环境进行充分的热设计评估与优化，确保芯片在各种使用场景下的工作温度处于合理范围。

实操上，判断是否已经过热降频最直接的办法是看频率而不是摸温度：

```bash
# 查看 CPU 温度与 BPU 频率/负载（需要 sudo）
sudo hrut_somstatus
```

输出里 `temperature` 段的 `CPU : 61.3 (C)` 是 CPU 温度（官方示例值），`cpu frequency` 段给出 `min cur max` 三列，`bpu status information` 段同理并多一个 `ratio`（BPU 负载率）。如果 `cur` 长期贴着小值而 `max` 是 1.8GHz，说明已经在降频。

另一个更细的读法是直接读 thermal zone：

```bash
# 温度单位为毫摄氏度，除以 1000 得到摄氏度，不需要 sudo
cat /sys/class/thermal/thermal_zone0/temp
```

降温阈值与宕机阈值可以通过 `/boot/config.txt` 调整，例如把降频点设到 86℃、宕机点设到 112℃：

```bash
# 编辑 /boot/config.txt（必须 root）
sudo nano /boot/config.txt
```

```
throttling_temp=86000
shutdown_temp=112000
```

官方提醒：「如果温度超过该温度，为了保护芯片和硬件，系统会自动关机，建议对设备做好散热处理，避免设备宕机，因为宕机后设备不会自动重启。」最后这句是重点——过热宕机不会自动恢复，无人值守场景必须靠散热而不是靠自动重启。

按顺序做完这 8 项，再插电：

| 步骤 | 动作 | 判据 |
| --- | --- | --- |

## 1.9 硬件层排障：供电不足导致间歇性启动失败

### 现象

社区帖 35112 的原文描述：「上电后，有时候能进入到Ubuntu界面，然后过一段时间就会卡住，然后手机热点连接也会断掉，大部分时候重新插拔电源会重新连上网络但是进不去ubuntu界面。」

典型特征可以归纳成四条，全部命中基本就是供电问题：

- 启动结果不稳定，同一块板子有时能进系统、有时不能。
- 进系统后运行一段时间（几分钟到几十分钟）无预警卡死。
- 卡死后网络同时断开，`ping` 不通，SSH 掉线。
- 必须断电重新上电，`reboot` 命令无效。

### 根因

官方对供电不足的定性是「会因供电不足造成开发板异常断电、反复重启等情况」，但没有展开机理。把三条官方事实拼起来可以还原完整链条：

1. 整板要求 5V/5A，而电脑 USB 口典型输出 0.5~0.9A。
2. 板上有多路开关电源（PMIC 给 CPU/BPU/DDR 分别供电），输入电压跌落时各路的输出会一起塌陷。
3. DDR 的时序参数依赖供电稳定；3.3.1 的发布说明里就有一例「修复 8G 板卡，内存减少 2G 的问题，需要更新 miniboot」，说明 DDR 初始化对固件与供电条件都敏感。

因此「能进系统但跑一会儿卡死」的机理是：启动瞬间负载较低，勉强够用；一旦 CPU 全核跑起来、BPU 开始推理、Wi-Fi 开始收发，电流需求上台阶，输入电压跌破 PMIC 的工作阈值，DDR 或 CPU 供电瞬间失稳，内核来不及打印就死锁——这解释了为什么「卡死后没有任何日志」。

社区帖 35112 给出的四条现象—原因对应关系可以作为判读模板：

| 现象 | 指向原因 |
| --- | --- |
| 间歇性启动成功 | 供电处于临界状态 |
| 运行一段时间后卡死 | 供电不足 / 过热 / 看门狗触发 |
| 网络断开 + 无法 Ping | 系统级死机，非网络配置问题 |
| 必须断电重启 | 软重启失效，硬件锁死 |

### 处置

```bash
# 第 1 步：确认供电规格。断电，翻看适配器铭牌，必须是 5V/5A
# 第 2 步：换用正规品牌 Type-C 线（劣质线电阻大，压降显著）
# 第 3 步：拔掉所有非必要 USB 外设（摄像头、键盘、雷达）
```

```bash
# 第 4 步：登录后确认当前挂了哪些 USB 设备（不需要 sudo）
lsusb

# 第 5 步：查看温度，排除过热路径（需要 sudo）
sudo hrut_somstatus

# 第 6 步：查看上一次启动的日志，确认死机前有无 watchdog/regulator 报错（需要 sudo）
sudo journalctl -b -1 -n 100 --no-pager
```

第 6 步是关键判据：如果 `journalctl -b -1` 里能看到 `watchdog` 超时复位、`regulator` 电压异常、或 `eth0` link down，就坐实了供电/硬件层问题；如果日志在死机前一片正常、没有任何收尾信息，同样指向「瞬间断电」而非软件崩溃。

### 预防

- 固定使用官方认证的 5V/5A 适配器（微雪 `PSU-27W-USB-C-CN-B`），不要用手机快充头——快充头在协议协商失败时会退回 5V/2A 甚至 5V/1A。
- 外设总功耗按第 1.2 节的接口负载表核算：4 路 USB3 各 1A @ 5V，40PIN 1A @ 5V。多路叠加超过余量时，给外设配独立供电的 HUB。
- 大负载场景改用 PoE 供电（兼容 IEEE 802.3af/at），前提是交换机或注入器真的支持该标准。
- 建立基线：新板子第一次上电就用 `sudo hrut_somstatus` 记下空载温度与 CPU 频率；后续跑重负载时对比，`cur` 明显低于基线即说明在降频或供电不足。

## 常见误区

**误区一：用电脑 USB 口或手机充电器给板子供电，只要能亮灯就算供电合格。**
亮绿灯只说明 5V 到了，不代表带得动。电脑 USB 口典型输出 0.5~0.9A，而官方要求 5V/5A；差值会在插上 USB 摄像头、跑 BPU 推理时以「随机卡死 + 断网 + 必须断电重启」的形式暴露。社区帖 35112 的整套排查逻辑就是围绕这一点展开的。

**误区二：把「橙灯闪烁」当成启动成功的判据。**
社区帖 34973 就是一个反例——标题写着「绿灯常亮，橙灯闪烁」，但 HDMI、SSH、串口全无反应，根因是 SD 卡没被识别。官方文档自身对这颗灯还有「橙色闪烁」与「绿色 ACT 闪烁」两种互相矛盾的说法（详见 1.3）。判断启动成功只认串口登录提示符或 HDMI 桌面。

**误区三：随便找一颗 CR2032 焊到 RTC 座上。**
官方明确「非充电的 RTC 电池不可以使用进行供电」，且 PMIC 会自动给 RTC 充电。一次电池被反复充电会鼓包漏液。要么用可充电型，要么不装。

**误区四：板子型号没确认就照着文档的「接口 N」接线。**
全板载 X5 与 X5 Module 是两套编号。全板载的「接口 4」是调试串口（115200），Module 的「接口 4」是 USB3.0 HOST——按错编号接线，轻则不通信，重则把 5V 灌进串口。
