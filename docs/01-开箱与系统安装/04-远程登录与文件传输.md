# 1.4 远程登录与文件传输

## 本章解决什么

板子一旦离开桌面、装进机器人本体或者塞进设备箱，HDMI 和键鼠就用不上了，剩下能碰它的通道只有三条：串口线、网线、Wi-Fi。这三条通道各自能做什么、什么时候必须用哪一条、以及登录进去之后怎么把代码和数据搬进搬出，是本章的全部内容。前半部分讲「怎么进去」——串口（含闪连直连）、SSH、VNC、RDK Studio，重点是 RDK X5 那两套固定网段（网口 `192.168.127.10`、闪连口 `192.168.128.10`）以及 Windows 和 Linux 双端的静态 IP 配法；后半部分讲「东西怎么进去」——`scp`、`rsync`、Samba、HTTP 临时服务、U 盘五条路径，各自适用什么规模的文件。文中所有命令都标注了是否需要 sudo，并且区分了板端执行和 PC 端执行。

> 来源：官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）

## 1.4.1 四条通道怎么选

官方的远程登录章节覆盖了四种方式：串口、RDK Studio、网络（VNC、SSH）。这四者的能力和适用边界差别很大，先列一张决策表：

| 通道 | 需要什么 | 能做什么 | 什么时候只能用这个 |
| --- | --- | --- | --- |
| 串口 | Micro-USB 数据线 | 看完整启动日志、登录 shell、改网络配置 | 系统起不来、网络没配通、要看 U-Boot 输出 |
| 闪连（USB Type-C 直连） | Type-C 数据线 + PC 端 RNDIS 网卡 | SSH / 传文件 | 手边没有网线和路由器、只想快速连一下 |
| SSH（网口或 Wi-Fi） | 板子联网、PC 同网段 | shell、`scp`/`rsync`、端口转发 | 日常开发的主力通道 |
| VNC（网口或 Wi-Fi） | 桌面版镜像 + 已启用 VNC | 图形桌面、远程操作 GUI 软件 | 必须看图形界面（如跑带窗口的示例） |

一条经验：**先保串口线不断**。官方的 LAN access 一节在讲完所有网络登录方式后特意补了一句「对于上述各步骤登录，始终需要保持串口线连接」——因为在配网络的过程中一旦把 SSH 弄断，串口是唯一的回退通道。

> 来源：官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）

## 1.4.2 网络前置：两套固定网段

RDK X5 出厂时网络不是 DHCP，而是写死的静态配置。这一点必须记住，否则所有「ping 不通」都会走弯路。

### 1.4.2.1 官方给定的默认值

| 接口 | 默认 IP | 掩码 | 网关 | 适用版本 |
| --- | --- | --- | --- | --- |
| 有线以太网 `eth0` | `192.168.127.10` | `255.255.255.0` | `192.168.127.1` | X5 3.0.0 起 |
| 闪连口（USB Device） | `192.168.128.10` | `255.255.255.0` | — | X5 3.0.0 起 |
| 无线 `wlan0` | 由路由器 DHCP 分配 | — | — | 全部 |

官方另给了一张跨型号的对照表，顺带说明了历史版本的差异：

| 板卡系列 | 镜像版本 | 网口 IP 地址 |
| --- | --- | --- |
| X3 | 小于等于 2.0.0 | `192.168.1.10/24` |
| X3 | 大于等于 2.1.0 | `192.168.127.10/24` |
| X5 | 3.0.0 | `192.168.127.10/24` |

也就是说 `192.168.127.0/24` 这个网段是 2.1.0 之后统一改过来的，早期 X3 是 `192.168.1.x`。网上大量旧教程还在写 `192.168.1.10`，照抄会连不上。

### 1.4.2.2 为什么优先走无线

官方在配置文件的注释里写了一条设计意图：静态网络配置里 `route-metric=700`，「是为了让有线网络的优先级更低，当有线和无线网络同时使能时优先会使用无线网络」。

这条设计对开发者其实很方便：网口保持默认静态 IP 不动，随时可以插网线直连调试；日常联网走 Wi-Fi，由路由器分配 IP。两条路互不干扰。

### 1.4.2.3 网段不通的通用排查

官方给的排查顺序是三步：

1. 确认开发板、电脑 IP 地址配置，一般前三段需要一样（例如板子 `192.168.127.10`、电脑 `192.168.127.100`）。
2. 确认开发板、电脑的子网掩码、网关配置是否一致。
3. 确认电脑网络防火墙是否处于关闭状态。

第 3 条在 Windows 上尤其关键——Windows Defender 防火墙默认会拦掉 ICMP 和部分入站端口，「ping 不通」常常不是网络问题而是防火墙把 echo request 丢了。

> 来源：官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）、官方文档 System_configuration/network_bluetooth（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/network_bluetooth）

## 1.4.3 网口直连与固定 IP

### 1.4.3.1 Windows 端设静态 IP

官方以 WIN10 为例给了步骤：

1. 在网络连接中找到对应的以太网设备并双击打开。
2. 找到 `Internet 协议版本 4` 选项并双击打开。
3. 填入对应网络参数，点确定。

更快的入口是 `Win + R` 输入 `ncpa.cpl`。

参数填法：

| 字段 | 值 |
| --- | --- |
| IP 地址 | `192.168.127.100`（任意 2–254，只要不撞车） |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | `192.168.127.1`（可留空，直连时无所谓） |
| DNS | 留空 |

注意要改的是**连板子的那块以太网卡**。笔记本上常有多块虚拟网卡（VMware、VirtualBox、WSL、Wi-Fi Direct），改错一块就会出现「设置了但还是不通」。判断方法是插拔网线看哪块网卡的状态在变。

### 1.4.3.2 Linux 端设静态 IP

NetworkManager 环境下用 `nmcli`（PC 端执行，需要 sudo）：

```bash
# 查看网卡名（不需要 sudo）
nmcli device status

# 设为静态 IP（需要 sudo，网卡名以实际为准，如 enp3s0）
sudo nmcli connection modify "有线连接 1" ipv4.method manual \
  ipv4.addresses 192.168.127.100/24 \
  ipv4.gateway 192.168.127.1

# 重新激活（需要 sudo）
sudo nmcli connection up "有线连接 1"
```

如果系统用的是老的 `ifupdown`，改 `/etc/network/interfaces`：

```
auto eth0
iface eth0 inet static
    address 192.168.127.100
    netmask 255.255.255.0
    gateway 192.168.127.1
```

```bash
# 生效（需要 sudo）
sudo systemctl restart networking
```

### 1.4.3.3 板端改成 DHCP

如果不想每次都配 PC 的静态 IP，可以把板子改成 DHCP，由路由器分配，然后在路由器上做 MAC 绑定把 IP 固定住——这是社区帖 33823 推荐的做法：「RDK X5 的有线网络默认可能是静态 IP，为了方便管理，建议先改为 DHCP 获取 IP，然后在路由器端将分配给板子的 IP 地址进行固定（MAC绑定），确保旁路由网关地址不会恒定」。

官方给了两种改法，**取决于系统版本**，这是一个必须注意的分界点：

**RDK X5 >= 3.3.0（NetworkManager）**：配置在 `/etc/NetworkManager/system-connections/netplan-eth0.nmconnection`。

```bash
# 编辑（需要 sudo）
sudo vim /etc/NetworkManager/system-connections/netplan-eth0.nmconnection
```

把 `[ipv4]` 段改成只保留两行：

```
[ipv4]
method=auto
route-metric=700
```

改静态 IP 则是改 `address1` 字段：

```
[ipv4]
address1=192.168.127.10/24,192.168.127.1
dns=8.8.8.8;8.8.4.4;
method=manual
route-metric=700
```

```bash
# 生效（需要 sudo）
sudo restart_network
```

**RDK X5 < 3.3.0（ifupdown）**：配置在 `/etc/network/interfaces`。

```bash
# 编辑（需要 sudo）
sudo vim /etc/network/interfaces
```

DHCP 写法：

```
source-directory /etc/network/interfaces.d
auto lo
iface lo inet loopback
auto eth0
iface eth0 inet dhcp
metric 700
```

静态写法：

```
source-directory /etc/network/interfaces.d
auto eth0
iface eth0 inet static
pre-up /etc/set_mac_address.sh
address 192.168.127.10
netmask 255.255.255.0
gateway 192.168.127.1
metric 700
```

```bash
# 生效（需要 sudo）
sudo restart_network
```

**改 MAC 地址**：3.3.0 之后在 `[ethernet]` 段加一行，改完 `reboot`：

```
[ethernet]
cloned-mac-address=12:34:56:78:9A:BA
wake-on-lan=0
```

3.3.0 之前则是在 `/etc/network/interfaces` 里加 `pre-up ifconfig eth0 hw ether 00:11:22:9f:51:27`。

版本判据：`cat /etc/version` 看版本号，或直接看 `/etc/NetworkManager/system-connections/` 目录是否存在。3.3.0 之后走 NetworkManager，改错文件不会生效——这是最常见的「改了没反应」原因。

> 来源：官方文档 System_configuration/network_bluetooth（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/network_bluetooth）、官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）、社区帖 33823（https://forum.d-robotics.cc/t/topic/33823）

## 1.4.4 串口登录

串口是最底层的通道，参数与接法详见第 3 章 3.2 节。要点复述：

| 参数 | RDK X5 | RDK X5 Module |
| --- | --- | --- |
| 波特率 | 115200 | 921600 |
| 数据位 | 8 | 8 |
| 奇偶校验 | None | None |
| 停止位 | 1 | 1 |
| 流控 | 无 | 无 |

串口登录后第一件有价值的事就是查 IP：

```bash
# 查看网络接口（不需要 sudo）
ifconfig
```

输出里 `eth0` 是有线、`wlan0` 是无线。官方示例输出中 `eth0` 段显示 `inet 192.168.127.10 netmask 255.255.255.0`，`wlan0` 段若还没有 IP 则只有 MAC 地址没有 `inet` 行。

也可以用更现代的写法：

```bash
# 只列出 IPv4 地址（不需要 sudo）
ip -4 addr show

# 只看路由（不需要 sudo）
ip route show
```

### 1.4.4.1 通过串口把 Wi-Fi 配起来

这是「板子只有串口线、想把网连上」的标准动作：

```bash
# 扫描（需要 sudo）
sudo nmcli device wifi rescan

# 列出热点（需要 sudo）
sudo nmcli device wifi list

# 连接（需要 sudo）
sudo wifi_connect "SSID" "PASSWD"
```

成功后板端 `ifconfig` 能拿到 `wlan0` 的 IP，此后就可以拔掉串口线走 SSH。官方对此的说明是「上述命令成功后，会出现 successfully 开头的提示……便可拔掉串口线，使用前文 SSH 登录进行远程连接」。实际的完整提示长这样：`Device 'wlan0' successfully activated with 'd7468833-4195-45aa-aa33-3d43da86e1a7'.`

> 来源：官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）、官方文档 System_configuration/network_bluetooth（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/network_bluetooth）

## 1.4.5 闪连（USB Type-C 直连）

闪连是 X5 相对前代新增的能力：用一根 Type-C 线把 PC 和板子的**接口 3（闪连接口）**连起来，板子会被枚举成一块 RNDIS 网卡，PC 上就多出一个「Remote NDIS based Internet Sharing Device」。板子在这条链路上的地址是 `192.168.128.10`。

需要说明的是：官方文档对闪连的技术描述只有一句——「闪连口（USB Device 口），为虚拟 USB 网卡，默认 IP：`192.168.128.10/24`」；具体操作流程在 RDK Studio 的用户手册里（`https://developer.d-robotics.cc/rdk_studio_doc/`），官方在入门文档里把 RDK Studio 的详细用法整体外链了出去，本页只保留下载入口。

### 1.4.5.1 社区实测的关键细节

社区侧有两篇长帖把闪连的坑讲透了。

**帖 28069**（教程帖）给了一条前置条件：「直接使用未烧录SD卡进行type—c闪连是不可行的，会直接识别到SD卡，需要对SD卡进行烧录方便后续操作」。也就是说闪连要求板子上已经有一个能启动的系统——它不是一个裸板烧录通道。

**帖 34957** 讲的是「IP地址被占用」这个最高频的报错。该帖的分析是闪连的虚拟网卡需要手动设静态 IP，而这个 IP 可能与局域网内其他设备冲突。给出的参数是「官方推荐的闪连网段」：IP `192.168.128.10`，掩码 `255.255.255.0`，网关 `192.168.128.1`（或留空），DNS 留空，若报占用可改 `192.168.128.11` 或 `192.168.129.10`。

这里有一个需要指出的问题：帖中把 PC 端 IP 也写成 `192.168.128.10`，而板子本身就是 `192.168.128.10`——两端同 IP 必然不通。帖 35101 里用户的实际报错正好印证了这个混乱：「已将所输入的此网络适配器的IP地址`192.168.128.100`分配给此计算机上的另一个适配器`Microsoft Wi-Fi Direct Virtual Adapter`」。这条报错说明用户填的是 `.100`，而 Windows 提示该地址已被另一块虚拟网卡占用。

正确的配法应当是：**PC 端虚拟网卡设 `192.168.128.100`（或 `.101` 等），板子保持 `192.168.128.10`。** 两端不能同号。

**帖 35101** 的报错值得完整抄下来，因为它是 Windows 多网卡环境的典型症状：

```
已将所输入的此网络适配器的IP地址192.168.128.100分配给此计算机上的另一个适配器
"Microsoft Wi-Fi Direct Virtual Adapter"。如果将相同的地址分配给两个适配器，
且两个适配器都处于活动状态，则仅有其中一个适配器将使用此地址。
这可能会导致系统配置错误。
```

处置：把 `Microsoft Wi-Fi Direct Virtual Adapter` 禁用掉（设备管理器 → 网络适配器 → 右键禁用），或给闪连网卡换一个没人用的地址。

**帖 35038** 记录了一个更隐蔽的坑：在图形界面里误点了「Enable Networking」，导致闪连配置被重置，之后闪连连不上、显示「没有 IP 地址 离线」。该帖的诊断是「X5 的闪联功能依赖固定的以太网配置（`192.168.128.10`），当你在图形界面点击『Enable Networking』时，系统会重置网络配置」。

### 1.4.5.2 闪连配置步骤（Windows）

1. 烧录好 SD 卡，插卡，用 Type-C 线连板子的闪连口与 PC。
2. 上电（部分固件需要按住 Sleep 键上电才会进闪连模式，以 RDK Studio 引导为准）。
3. `Win + R` → `ncpa.cpl`，找到 `Remote NDIS based Internet Sharing Device`。
4. 右键 → 属性 → `TCP/IPv4` → 「使用下面的 IP 地址」。
5. 填 IP `192.168.128.100`、掩码 `255.255.255.0`、网关 `192.168.128.1`（或留空）。
6. 确定后 `ping 192.168.128.10` 验证。

```bash
# 通了之后可以直接 SSH（PC 端执行，不需要 sudo）
ssh sunrise@192.168.128.10
```

## 1.4.6 SSH 登录

### 1.4.6.1 前置条件

板子必须联网且 IP 已知。默认 SSH 服务是开启的——官方在 `srpi-config` 的 Interface Options 一节明确「默认情况下系统是启用 SSH 选项的」，`configuration_wizard` 里也说「当前系统版本默认开启 SSH 登录服务」。

### 1.4.6.2 用终端软件（MobaXterm）

1. 打开 MobaXterm，`Session` → `SSH`。
2. 输入开发板 IP，例如 `192.168.127.10`。
3. 勾选 `specify username`，输入 `sunrise`。
4. 点 OK，输入用户名 `sunrise`、密码 `sunrise`。

### 1.4.6.3 用命令行

```bash
# PC 端执行，不需要 sudo
ssh sunrise@192.168.127.10
```

首次连接会弹出主机指纹确认，输入 `yes` 回车，再输密码。

指定端口、指定密钥、执行单条远程命令等常用形态：

```bash
# 指定端口（注意 ssh 用大写 -p，scp 用小写 -p 表示保留时间戳）
ssh -p 2211 sunrise@192.168.127.10

# 使用私钥
ssh -i ~/.ssh/id_ed25519 sunrise@192.168.127.10

# 远程执行单条命令并返回结果（不需要进交互 shell）
ssh sunrise@192.168.127.10 "uname -a"

# 生成密钥对（在 PC 上执行，不需要 sudo）
ssh-keygen -t ed25519 -C "rdkx5"

# 把公钥推到板子，实现免密登录（在 PC 上执行）
ssh-copy-id sunrise@192.168.127.10
```

免密登录对频繁 `scp`/`rsync` 的场景几乎是必需的——否则每次同步都要手打密码，脚本化就无从谈起。

### 1.4.6.4 端口转发

官方给的两种转发形态值得记住，它们在「板子在内网、你在外网」时非常有用：

```bash
# 本地端口转发：把本机 8080 转发到板子的 80
ssh -L 8080:localhost:80 sunrise@192.168.127.10

# 远程端口转发：把板子的 9000 转发到你本机的 9000
ssh -R 9000:localhost:9000 sunrise@192.168.127.10
```

第一种的典型用途是访问板子上跑 Web 服务（如 TROS 的 websocket 展示界面），不用给板子开防火墙。第二种用于把板子上的服务暴露到你自己的机器。

### 1.4.6.5 常见失败与判据

| 现象 | 判据 | 处置 |
| --- | --- | --- |
| `Connection timed out` | ping 也不通 | 网段不对或防火墙拦了 |
| `Connection refused` | ping 通但 22 端口拒绝 | SSH 服务没起或被关 |
| `Permission denied (publickey,password)` | 端口通、认证失败 | 用户名/密码错，或 SSH 只允许密钥 |
| `Host key verification failed` | 之前连过同一 IP 的另一台设备 | 删掉 `~/.ssh/known_hosts` 里对应行 |

板端自查（通过串口执行）：

```bash
# 看 SSH 服务状态（不需要 sudo）
systemctl status ssh

# 看 22 端口是否在监听（需要 sudo）
sudo netstat -tlnp | grep :22

# 重新打开 SSH 服务（需要 sudo）
sudo systemctl enable --now ssh
```

## 1.4.7 VNC 登录

### 1.4.7.1 前置条件

VNC 只对 **Ubuntu Desktop** 版本有意义（Server 版没有图形会话）。而且 VNC 服务默认是关的——官方在 3.0.1 的更新说明里写过「VNC 服务默认不自动开启，可减少系统资源消耗。用户可通过 srpi-config 工具打开」，`srpi-config` 文档也把它列为可启用/禁用的项。

开启方式两种：

- 桌面版：菜单栏 `RDK Configuration` → `Interface Options -> VNC`。
- 任意版本：`sudo srpi-config` → `Interface Options -> VNC`。

官方特别提醒：「选择使能 VNC 时需要设置登录密码，密码必须是一个 8 位长度的由字符组成的字符串」——8 位是硬约束。

### 1.4.7.2 用 VNC Viewer 连接

1. 下载并安装 VNC Viewer（`https://www.realvnc.com/en/connect/download/viewer/`）。
2. 输入设备 IP，如 `192.168.127.10`，回车。
3. 弹出「连接未加密」提示，点 `Continue`。
4. 输入密码（官方示例给的是 `sunrise`），勾选 `Remember password`，点 OK。

官方的说明是「VNC 支持直接、云端两种连接方式……本文推荐使用直接连接方式」。直接连接即上面这套，不经过 RealVNC 的云中转。

### 1.4.7.3 VNC 卡顿的处置

这是一个有官方 FAQ 支撑的具体问题。FAQ Q35 给的方案排序：

1. **接 HDMI 显示器或 HDMI 欺骗器（Dummy Plug）**。原因是「有些嵌入式系统在未检测到物理显示器连接时，可能会限制图形渲染的性能或帧率」。这一条最省事，插一个假负载即可。
2. **用虚拟显示器（Xvfb）**，让 x11vnc 从虚拟屏幕抓内容，不依赖物理显示器。
3. **降色彩深度与画质**：VNC 服务端/客户端降到 16 位色，关闭或降低图像压缩质量，禁用视觉特效。
4. **降分辨率**：显著减少需要传输和渲染的数据量。
5. **关掉桌面上不必要的图形应用**。
6. **查系统负载**：`top` 或 `htop` 看 CPU/内存占用。

补充一条版本相关的证据：3.2.3 的更新说明里写了「网络与远程优化 默认切换至 iptables legacy 模式，VNC 显示流畅性提升，远程桌面不卡顿」。也就是说如果你在 3.2.3 之前的版本上遇到 VNC 卡顿，升级本身就是解法之一。

### 1.4.7.4 新用户连不上 VNC

**现象**（帖 35243 原文）：「为什么我新创建的用户，连不上该用户的vnc,如何配置」。

**根因**：按该帖分析，系统预装的 `x11vnc` 服务「通常绑定在默认用户（如 `sunrise`）的 X11 会话上」，新用户「登录后没有独立的图形会话，VNC 无法找到对应的 DISPLAY」，而「Linux 用户间的图形会话是隔离的，不能直接跨用户访问」。这是 X11 会话模型决定的，不是配置漏了。

**处置**：先让新用户在图形界面登录一次（HDMI 或自动登录），产生 X11 会话后再启动 x11vnc 绑定到该会话：

```bash
# 查看当前 DISPLAY（在目标用户的会话里执行，不需要 sudo）
echo $DISPLAY

# 为新用户启动 VNC（需要该用户身份，端口 5901 避免与默认的 5900 冲突）
x11vnc -display :0 -forever -loop -noxdamage -repeat -rfbport 5901 -shared -auth guess
```

**预防**：需要多用户各自 VNC 时，给每个用户分配不同 `-rfbport`，并确保各自都有活跃的 X11 会话。更省事的做法是维持单用户 + 通过 `su -` 切换做管理操作。

> 来源：官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）、官方文档 Quick_start/remote_login（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/remote_login）、官方文档 System_configuration/srpi-config（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/srpi-config）、官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）、社区帖 35243（https://forum.d-robotics.cc/t/topic/35243）

## 1.4.8 文件传输：五条路径

官方 FAQ Q17 列了六种方式：SCP、SFTP、USB 存储设备、ADB、网络共享（Samba/NFS）、Python HTTP 服务器。下面按「日常用哪个」排序，并补上官方命令手册里的 `rsync`。

| 方式 | 适用规模 | 断点续传 | 需要装东西 | 速度 |
| --- | --- | --- | --- | --- |
| `scp` | 单文件、小目录（< 几百 MB） | 否 | 否（系统自带） | 中 |
| `rsync` | 大目录、增量同步、反复同步 | 是（`--partial`） | 板端需装 rsync | 高（只传差异） |
| Samba | 长期共享目录、图形化拖拽 | 视客户端 | 需装 samba | 中 |
| HTTP 临时服务 | 板子 → PC 单向下载 | 否 | 否（Python 自带） | 中 |
| U 盘 | 无网络、超大文件 | 否 | 否 | 高 |

### 1.4.8.1 scp

官方命令手册给的形态是标准的 `scp [option] file_source file_target`。

**PC → 板子**：

```bash
# 传单个文件到板子的 /userdata（PC 端执行，不需要 sudo）
scp ./model.bin sunrise@192.168.127.10:/userdata/

# 传文件并改名
scp ./model.bin sunrise@192.168.127.10:/userdata/model_v2.bin

# 传整个目录（-r）
scp -r ./my_project/ sunrise@192.168.127.10:/userdata/my_project/
```

**板子 → PC**：

```bash
# 从板子拉文件到本地当前目录（PC 端执行）
scp sunrise@192.168.127.10:/userdata/log.log ./

# 拉整个目录
scp -r sunrise@192.168.127.10:/userdata/logs/ ./logs_backup/
```

常用选项（来自官方手册）：

| 选项 | 作用 |
| --- | --- |
| `-r` | 递归复制整个目录（会跟随符号链接） |
| `-p` | 保留原文件的修改时间、访问时间和权限 |
| `-C` | 传输时压缩（对文本类文件效果明显） |
| `-P port` | 指定端口（**大写 P**，小写 `-p` 是保留时间戳） |
| `-l limit` | 限速，单位 Kbit/s |
| `-v` | 详细模式，调试连接/认证问题很有用 |

`-l` 这个选项在板子跟 PC 抢带宽时有用，比如同时在做 OTA 下载：

```bash
# 限速 2Mbit/s 传大文件
scp -l 2048 ./bigfile.img sunrise@192.168.127.10:/userdata/
```

**Windows 端**：PowerShell 与 CMD 从 Windows 10 1809 起自带 `scp`（OpenSSH 客户端）。若没有，用 Git Bash 里的 `scp`，或改用 WinSCP / MobaXterm 的图形界面 SFTP。

**sudo 说明**：`scp` 本身不需要 sudo。但若目标路径属于 root（如 `/etc/`、`/boot/`），会报 `Permission denied`。此时不要给 `scp` 加 sudo（本地 sudo 对远程无意义），而是先传到用户目录再在板端 sudo 移动：

```bash
# 第一步：传到用户目录
scp ./config.txt sunrise@192.168.127.10:/home/sunrise/

# 第二步：板端移动到目标位置（需要 sudo）
ssh sunrise@192.168.127.10 "sudo mv /home/sunrise/config.txt /boot/config.txt"
```

### 1.4.8.2 rsync

`rsync` 的核心价值是增量传输——「通过仅发送源文件与目标中现有文件之间的差异来减少通过网络发送的数据量」，且「通过默认的『快速检查』算法查找需要传输的文件，该算法查找大小或最后修改时间发生变化的文件」。

**PC → 板子**：

```bash
# 基本同步（PC 端执行，不需要 sudo）
rsync -av ./my_project/ sunrise@192.168.127.10:/userdata/my_project/

# 带进度、压缩、断点续传
rsync -avzP ./my_project/ sunrise@192.168.127.10:/userdata/my_project/

# 镜像式同步：删除目标端多余文件（危险，先加 -n 演练）
rsync -avzP --delete ./my_project/ sunrise@192.168.127.10:/userdata/my_project/
```

**板子 → PC**：

```bash
# 拉取板子的日志目录到本地
rsync -avzP sunrise@192.168.127.10:/userdata/logs/ ./logs_backup/
```

**板端本地复制**（官方手册示例）：

```bash
# 把 /app 复制到 /userdata（板端执行，需要 sudo 因为 /userdata 通常属 root）
sudo rsync -avSH /app/ /userdata/
```

关键选项：

| 选项 | 作用 |
| --- | --- |
| `-a` | 归档模式，等价于 `-rlptgoD`（保留权限、时间、属主、符号链接等） |
| `-v` | 详细输出 |
| `-z` | 传输时压缩 |
| `-P` | 等价于 `--partial --progress`（断点续传 + 进度） |
| `--delete` | 删除目标端多余文件（镜像同步） |
| `-n` / `--dry-run` | 演练，不实际改动 |
| `--exclude=PATTERN` | 排除匹配的文件 |
| `--bwlimit=RATE` | 限带宽 |

**路径尾斜杠的坑**：`./my_project/` 与 `./my_project` 语义完全不同。带尾斜杠表示「把目录**内容**同步到目标」，不带表示「把目录**本身**放到目标下」。写错的结果是在目标端多出一层同名目录，或者内容被摊平到目标根。

板端需要先装 rsync（部分镜像未预装）：

```bash
# 板端安装（需要 sudo）
sudo apt update && sudo apt install -y rsync
```

### 1.4.8.3 Samba

Samba 的价值是让板子上的目录在 Windows 资源管理器里变成一个网络盘，可以直接拖拽。官方 FAQ 对它的定位是「可以在开发板上配置 Samba 或 NFS 服务，将特定目录共享到局域网，然后在电脑上像访问网络驱动器一样访问这些文件。配置相对复杂一些」。

官方文档没有给出 RDK X5 上的 Samba 完整配置步骤，只有 FAQ 里那句定性描述。因此这里只给一个最小可用流程，并注明这是通用 Linux 做法而非官方推荐配置：

```bash
# 1. 板端安装（需要 sudo）
sudo apt update && sudo apt install -y samba

# 2. 备份原配置（需要 sudo）
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak

# 3. 追加共享定义（需要 sudo，用 tee 追加）
sudo tee -a /etc/samba/smb.conf > /dev/null <<'EOF'
[userdata]
   path = /userdata
   browseable = yes
   read only = no
   guest ok = no
   create mask = 0644
   directory mask = 0755
EOF

# 4. 为 sunrise 设置 Samba 密码（需要 sudo，密码与系统密码独立）
sudo smbpasswd -a sunrise

# 5. 重启服务（需要 sudo）
sudo systemctl restart smbd
sudo systemctl enable smbd
```

Windows 端访问：资源管理器地址栏输入 `\\192.168.127.10\userdata`，弹出认证框填用户名 `sunrise` 与第 4 步设的 Samba 密码。

需要提醒的是：`/userdata` 的所有者是 root，普通用户通过 Samba 写入需要额外处理权限（把 `sunrise` 加入对应组，或改共享目录属主）。这是 Samba 在实际使用中最常卡住的地方，也是它「配置相对复杂」的具体含义。

### 1.4.8.4 HTTPS/HTTP 临时服务

板子上有文件想让 PC 下载，最快的方式是起一个 Python 内置 HTTP 服务器：

```bash
# 在板子上，进入要共享的目录后执行（不需要 sudo，但端口 <1024 需要）
cd /userdata/export
python3 -m http.server 8000
```

PC 浏览器访问 `http://192.168.127.10:8000` 即可看到目录列表并下载。这条是从官方 FAQ Q17 抄来的原文流程。

适用场景：临时给同事传个日志、把板子上的截图拉到 PC。不适合传大文件（没有断点续传、没有校验）和涉及敏感数据的场景（HTTP 明文）。

### 1.4.8.5 U 盘

无网络时的唯一选择。X5 的 USB Type A 口支持 U 盘，「可自动检测 U 盘接入并挂载，默认挂载目录为 `/media/sda1`」。

```bash
# 看是否自动挂载（不需要 sudo）
ls /media/

# 若没自动挂载，手动挂载（需要 sudo）
sudo mkdir -p /mnt/usb
sudo mount /dev/sda1 /mnt/usb

# 用完卸载（需要 sudo）
sudo umount /mnt/usb
```

文件系统兼容性：官方说明「将 U 盘等格式化为开发板支持的文件系统（如 FAT32, exFAT, 或安装了 ntfs-3g 后的 NTFS）」。NTFS 需要额外装 `ntfs-3g`：

```bash
# 板端安装 NTFS 支持（需要 sudo）
sudo apt install -y ntfs-3g
```

U 盘的坑在于设备节点会变——插过多个 USB 存储设备后 `/dev/sda1` 可能变成 `/dev/sdb1`。用 `lsblk` 确认再挂。

> 来源：官方文档 Appendix/linux-command-manual/cmd_scp（https://developer.d-robotics.cc/rdk_x_doc/Appendix/linux-command-manual/cmd_scp）、官方文档 Appendix/linux-command-manual/cmd_rsync（https://developer.d-robotics.cc/rdk_x_doc/Appendix/linux-command-manual/cmd_rsync）、官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）、官方文档 Quick_start/hardware_introduction/rdk_x5（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/hardware_introduction/rdk_x5）

## 1.4.9 一次完整的连接流程

把上面所有内容串成一条可执行路径，用于「新板子、只有网线和一根 Type-C 线」的场景：

```
第 1 步  接串口线（Micro-USB 到 PC），打开 MobaXterm 串口会话
         参数：X5 = 115200-8-N-1，Module = 921600-8-N-1

第 2 步  给板子上电，观察完整启动日志，直到出现登录提示符

第 3 步  用 sunrise/sunrise 或 root/root 登录

第 4 步  插网线，ifconfig 确认 eth0 是 192.168.127.10

第 5 步  PC 端把以太网卡设为 192.168.127.100/24
         （Win: ncpa.cpl → TCP/IPv4 → 手动；Linux: nmcli）

第 6 步  PC 端 ping 192.168.127.10 验证

第 7 步  PC 端 ssh sunrise@192.168.127.10 验证 SSH

第 8 步  （可选）板端配 Wi-Fi：sudo wifi_connect "SSID" "PASSWD"
         然后 ifconfig 记下 wlan0 的 IP，拔掉网线走无线

第 9 步  （可选）PC 端 ssh-copy-id 实现免密，之后 scp/rsync 无需输密码
```

第 5 步到第 6 步之间如果 ping 不通，按这个顺序查：PC 的 IP 是否真的设到了那块网卡上 → 防火墙是否关着 → 网线是否插在板子的 `eth0`（不是闪连口）→ 板端 `ifconfig eth0` 是否有 `inet` 行。

## 常见误区

**误区一：闪连时把 PC 端 IP 也设成 `192.168.128.10`。**
板子的闪连口本身就是 `192.168.128.10`，PC 端必须用不同地址（如 `192.168.128.100`）。社区帖 34957 的建议里把两端写成同一个地址，照抄必然不通。

**误区二：认为 `192.168.127.10` 是「非标准网段、配置错了」。**
这是官方默认静态 IP。社区帖 34973 的自动回复曾把它误读成 `198.168.127.10` 并建议改 netplan，方向完全错误。要改的是 PC 端，不是板子。

**误区三：3.3.0 之后还去改 `/etc/network/interfaces`。**
从 RDK X5 3.3.0 起网络由 NetworkManager 管理，配置在 `/etc/NetworkManager/system-connections/netplan-eth0.nmconnection`。改老文件不生效，会让人误以为「配置没保存」。

**误区四：`scp` 报 `Permission denied` 就给 `scp` 加 sudo。**
`scp` 的 sudo 只影响本地进程权限，对远程写入无效。正确做法是先传到用户目录，再在板端用 sudo 移动。

**误区五：`rsync` 的源路径尾斜杠随手写。**
`src/` 与 `src` 语义相反：带杠同步内容，不带杠同步目录本身。这个差异会直接导致目标端多一层目录或文件被摊平。

**误区六：以为 VNC 默认就开着。**
官方从 3.0.1 起「VNC 服务默认不自动开启」，需要在 `srpi-config` 的 `Interface Options -> VNC` 里手动启用，且密码必须是 8 位。
