# 音频子系统

## 本章解决什么

RDK X5 的音频有三层：板载 ES8326（3.5mm 耳机口，开箱即用）、外接音频 HAT（微雪 Audio Driver HAT REV2、WM8960 Audio HAT、幻尔载板，需 `srpi-config` 启用）、以及用户自己接的 I2S 外放板（需要改设备树）。三层的声卡编号、设备节点、混音器控件完全不同，**混用命令是最大的坑**——同一句 `aplay -D hw:0,0` 在板载和外接 HAT 上指向完全不同的硬件。本章给出每块板的声卡拓扑、录音与播放的可复制命令、`tinymix` 路由配置、回采验证方法，以及"设备对、命令对、就是没声音"的分层判据。

---

## 1. 板载 ES8326：3.5mm 音频口

### 1.1 硬件前提：必须是 4 段式耳机

板载 3.5mm 口搭配 4 段式耳机或符合接口的其他设备使用。**3 段式耳机一般没有 MIC**，只能听不能录。

还有一个纯机械但极高频的错误：耳机插头没有完全插到位。官方给了正误对比图，判据是——**如果耳机的金属接口有裸露出来，就是没插到底**。这种情况下"程序能正常运行，但既听不到声音也录不到声音"。

### 1.2 声卡拓扑

```bash
# 确认声卡是否注册
cat /proc/asound/cards
```

```
0 [duplexaudio ]: simple-card - duplex-audio
                  duplex-audio
```

```bash
# 确认逻辑设备
cat /proc/asound/devices
```

```
 2: [ 0- 0]: digital audio playback
 3: [ 0- 0]: digital audio capture
 4: [ 0] : control
33: : timer
```

```bash
# 确认用户空间设备文件
ls /dev/snd/
```

```
by-path  controlC0  pcmC0D0c  pcmC0D0p  timer
```

**读法**：声卡 0 是板载声卡，设备号 `0-0`，实际操作的设备是 `pcmC0D0p`（播放）与 `pcmC0D0c`（录音）。对应到 ALSA 设备名就是 `hw:0,0`。

关键点：**板载声卡的 capture 与 playback 都在 device 0**（`0-0`），所以录音和播放都用 `hw:0,0`。

### 1.3 录音与播放

```bash
# 录音 10 秒，24bit / 48kHz / 立体声
# 需要 sudo（写 /userdata）
sudo arecord -D hw:0,0 -c 2 -r 48000 -f S24_LE -t wav -d 10 /userdata/record1.wav
```

正常输出：

```
Recording WAVE '/userdata/record1.wav' : Signed 24 bit Little Endian, Rate 48000 Hz, Stereo
```

```bash
# 回放
sudo aplay -D hw:0,0 /userdata/record1.wav
```

正常输出：

```
Playing WAVE '/userdata/record1.wav' : Signed 24 bit Little Endian, Rate 48000 Hz, Stereo
```

注意板载口用的格式是 **S24_LE**（24 位小端），不是常见的 S16_LE。用 16 位录也能跑，但会暴露位深转换问题。

> 来源：官方文档 Basic_Application/audio/rdk_x5/in_board_es8326（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/audio/rdk_x5/in_board_es8326）

## 2. 音频扩展板型号对照

### 2.1 三块官方支持的板子

| 板卡 | Codec 方案 | 能力 | `srpi-config` 菜单项 | 启用后声卡 0 的名字 |
| --- | --- | --- | --- | --- |
| **微雪 Audio Driver HAT REV2** | ES7210 + ES8156（双 Codec） | 环形 4 麦录音、双通道播放、音频回采 | `Audio Driver HAT V2` | `duplexaudioi2s1` |
| **微雪 WM8960 Audio HAT** | WM8960 | 双通道麦克风录音 + 音频播放 | `WM8960 Audio Driver HAT` | `duplexaudioi2s1` |
| **幻尔载板** | — | 该载板集成多种外设，音频是其中一部分 | `Hiwonder Audio Driver HAT` | `duplexaudioi2s1` |

三块板启用后，**声卡编号会发生位移**：

| 声卡 | 内容 |
| --- | --- |
| 0 | 外接 HAT（`duplexaudioi2s1`） |
| 1 | 板载 ES8326（`duplexaudio`） |

也就是说，**插上 HAT 并启用后，原来 `hw:0,0` 指向的板载声卡变成了 `hw:1,0`**。这是混用命令导致"没声音"的最主要原因——命令还是那句，硬件已经不是那块了。

菜单路径统一是：`3 Interface Options` → `I5 Audio`。

### 2.2 Audio Driver HAT REV2 的硬件前提：3 个拨码开关全拨 OFF

这一条官方单独列了一步：**3 个拨码开关全部拨到 OFF 位置**。

拨码开关决定 I2S 通道配置。拨错的表现是"能识别声卡但录音/播放无声，或回采通道无信号"。

### 2.3 启用后的声卡拓扑（三块板一致）

```bash
cat /proc/asound/cards
```

```
0 [duplexaudioi2s1]: simple-card - duplex-audio-i2s1
                     duplex-audio-i2s1
1 [duplexaudio ]: simple-card - duplex-audio
                  duplex-audio
```

```bash
cat /proc/asound/devices
```

```
2: [ 0- 0]: digital audio playback
3: [ 0- 1]: digital audio capture      ← 注意是 0-1，不是 0-0
4: [ 0] : control
5: [ 1- 0]: digital audio playback
6: [ 1- 0]: digital audio capture
7: [ 1] : control
33: : timer
```

```bash
ls /dev/snd/
```

```
by-path controlC0 controlC1 pcmC0D0p pcmC0D1c pcmC1D0c pcmC1D0p timer
```

**这张表的读法极其重要**：

- 声卡 0 = 外接 HAT，**播放是 device 0**（`pcmC0D0p`），**录音是 device 1**（`pcmC0D1c`）——播放与录音**不在同一个 device 上**；
- 声卡 1 = 板载 ES8326，`1-0`，本章场景不用它。

对比板载：板载的播放与录音都在 device 0；HAT 的播放 0、录音 1。**这就是为什么 `arecord -Dhw:0,0` 在 HAT 上录不到音**——`hw:0,0` 是播放设备，不是录音设备。

### 2.4 卸载

```bash
sudo srpi-config
# 3 Interface Options -> I5 Audio -> 选择 UNSET
# 然后断电拔板
```

> 来源：官方文档 Basic_Application/audio/rdk_x5/wm8960_audio_hat（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/audio/rdk_x5/wm8960_audio_hat）、audio_driver_hat2_rev2（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/audio/rdk_x5/audio_driver_hat2_rev2）、hiwonder_rasb5（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/audio/rdk_x5/hiwonder_rasb5）

## 3. Audio Driver HAT REV2：录音、播放、回采

这块板是三块里能力最强、配置也最复杂的（需要先配路由）。以下所有命令都在 `sunrise` 用户下执行，`tinymix` / `tinycap` / `tinyplay` **不需要 sudo**（属于 audio 组可访问）。

### 3.1 录音

REV2 的录音设备是 **`hw:0,1`**（device 1）。

```bash
# 2 通道录音
tinycap ./2chn_test.wav -D 0 -d 1 -c 2 -b 16 -r 48000 -p 512 -n 4 -t 5

# 4 通道录音（环形 4 麦）
tinycap ./4chn_test.wav -D 0 -d 1 -c 4 -b 16 -r 48000 -p 512 -n 4 -t 5
```

参数含义：`-D` 声卡号、`-d` 设备号、`-c` 通道数、`-b` 位深、`-r` 采样率、`-p` period size、`-n` period 数、`-t` 时长（秒）。

### 3.2 播放

播放设备是 **`hw:0,0`**（device 0）。**不支持播放 4 通道**——只支持双通道。

```bash
tinyplay ./2chn_test.wav -D 0 -d 0
```

### 3.3 音频回采（echo / loopback）

回采信号映射在**录音通道 7 和 8**。要验证回采必须录 **8 通道**。

关键约束（官方原文）：**如果使用同一个 I2S，需要保持通道数、位深、采样率对齐**；这款转接板根据拨码开关固定了一路 I2S，所以回采时 playback 与 capture 的格式必须完全一致。

三步流程（需要两个终端）：

```bash
# 终端 1：先录一段用作回采 playback 的数据，格式 16k / 8ch / 16bit
tinycap ./8chn_echo_data.wav -D 0 -d 1 -c 8 -b 16 -r 16000 -p 256 -n 4 -t 5
```

```bash
# 终端 1：开始 50 秒的采集（留足时间切终端）
tinycap ./8chn_capture.wav -D 0 -d 1 -c 8 -b 16 -r 16000 -p 256 -n 4 -t 50
```

```bash
# 终端 2：同时启动格式对齐的 8 通道播放
tinyplay ./8chn_echo_data.wav -D 0 -d 0
```

采集结束后用 Audacity 打开 `8chn_capture.wav`，看第 7、8 通道的波形或频谱。能看到与播放内容对应的信号 = 回采通路正常。

`8chn_echo_data.wav` 用自己制作的正弦波更方便判读。

### 3.4 一键验证示例

官方提供了 `audio_echo_test`，自动完成两阶段测试并给出 PASS / FAIL：

```bash
cd /app/cdev_demo/audio_echo_test
sudo make          # 依赖 libasound 与 pthread
./audio_echo_test  # 不需要 sudo
```

编译命令实际展开为：

```
gcc -Wall -O2 -o audio_echo_test audio_echo_test.c -lasound -lpthread
```

该示例固定使用 `plughw:0,0`（播放）与 `plughw:0,1`（采集），格式固定 8ch / 16kHz / 16bit / period=512。

正常输出：

```
OK: ALSA card 0 'duplex-audio-i2s1' matches Audio Driver HAT REV2 driver config.
Driver/overlay check only confirm the mounted board is
Waveshare Audio Driver HAT REV2 (ES7210+ES8156), 3x DIP OFF, then continue.
playback plughw:0,0 capture plughw:0,1

format: 8ch 16000Hz 16bit period=512
=== phase 1: speak into mic (5s) ===

saved record_first.wav (80000 frames, 5.0s)
phase1 peak: ch1=10904 ch2=11271 ch3=13384 ch4=13647 ch5=18 ch6=5 ch7=5 ch8=9

=== phase 2: play voice x2 (gap 2s) + capture ===
capture length: 12.0s

saved audio_echo_test.wav (192000 frames, 12.0s)
phase2 peak: ch1=8072 ch2=7046 ch3=8708 ch4=7500 ch5=16 ch6=7 ch7=201 ch8=194

PASS: wired loopback ch1-ch4 (peak 8708)
note: ch7/ch8 peak 201 (use ch1-ch4 if speaker taps MIC)
```

**怎么读这个输出**：

- `phase1 peak` 里 ch1–ch4 是有效人声（几千到上万），ch5–ch8 接近 0（无输入）——说明 4 个麦克风通道正常；
- `phase2 peak` 里 ch7/ch8 出现 201/194——回采有信号；
- `PASS: wired loopback ch1-ch4` 是主判据；`note` 提示如果扬声器串到了麦克风，用 ch1–ch4 判定更可靠。

生成的两个文件：`record_first.wav`（Phase 1 的 5 秒 8 通道录音）、`audio_echo_test.wav`（Phase 2 的约 12 秒同步采集）。

> 来源：官方文档 Basic_Application/audio/rdk_x5/audio_driver_hat2_rev2、Basic_Application/cdev_demo_sample/audio_echo_test（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/cdev_demo_sample/audio_echo_test）

## 4. WM8960 Audio HAT：必须配路由才有声音

### 4.1 为什么这块板特别麻烦

官方原文：**"该音频板需要配置 Audio 路由才可以执行对应的功能，所以在以下每个场景功能执行之前都有加载特定路由的命令。"**

也就是说，同一套硬件，想录音要先切到录音路由，想喇叭放要先切到喇叭路由，想耳机放要再切。每次换场景都要重新 `tinymix`。

设备和官方例子一律用 **`-D 0`**（声卡 0）。

### 4.2 录音

```bash
# 1) 设置左右通道输入增益（3 为较高，1 为较低；有啸叫就降到 1）
tinymix -D 0 set 'Left Input Boost Mixer LINPUT1 Volume' 3
tinymix -D 0 set 'Right Input Boost Mixer RINPUT1 Volume' 3

# 2) 设置录音音量
tinymix -D 0 set 'Capture Volume' 40 40
tinymix -D 0 set 'ADC PCM Capture Volume' 200 200

# 3) 打开输入通路开关
tinymix -D 0 set 'Left Boost Mixer LINPUT1 Switch' 1
tinymix -D 0 set 'Right Boost Mixer RINPUT1 Switch' 1
tinymix -D 0 set 'Left Input Mixer Boost Switch' 1
tinymix -D 0 set 'Right Input Mixer Boost Switch' 1

# 4) 打开录音开关
tinymix -D 0 set 'Capture Switch' 1 1

# 5) 录音 5 秒，2 通道 / 48kHz / 16bit
tinycap ./2chn_test.wav -D 0 -d 0 -c 2 -b 16 -r 48000 -p 512 -n 4 -t 5
```

### 4.3 喇叭播放（双通道）

```bash
# 1) 打开左右声道 PCM 播放开关
tinymix -D 0 set 'Left Output Mixer PCM Playback Switch' 1
tinymix -D 0 set 'Right Output Mixer PCM Playback Switch' 1

# 2) 设置喇叭音量
tinymix -D 0 set 'Speaker DC Volume' 3
tinymix -D 0 set 'Speaker AC Volume' 3
tinymix -D 0 set 'Speaker Playback Volume' 127 127
tinymix -D 0 set 'Playback Volume' 255 255

# 3) 再次确保输出开关已打开
tinymix -D 0 set 'Left Output Mixer PCM Playback Switch' 1
tinymix -D 0 set 'Right Output Mixer PCM Playback Switch' 1

# 4) 播放
tinyplay ./2chn_test.wav -D 0 -d 0
```

第 3 步"再次确保"不是重复——官方文档就是这么写的，因为某些控件的写入顺序会影响生效结果。

### 4.4 耳机与喇叭同时播放

```bash
tinymix -D 0 set 'Headphone Playback Volume' 80 80
tinymix -D 0 set 'Playback Volume' 220 220
tinymix -D 0 set 'Speaker DC Volume' 4
tinymix -D 0 set 'Left Output Mixer PCM Playback Switch' 1
tinymix -D 0 set 'Right Output Mixer PCM Playback Switch' 1
tinyplay ./2chn_test.wav -D 0 -d 0
```

### 4.5 仅耳机播放（喇叭静音）

```bash
tinymix -D 0 set 'Headphone Playback Volume' 115 115
tinymix -D 0 set 'Speaker Playback Volume' 0 0     # 喇叭静音
tinymix -D 0 set 'Playback Volume' 244 244
tinymix -D 0 set 'Speaker DC Volume' 4
tinymix -D 0 set 'Left Output Mixer PCM Playback Switch' 1
tinymix -D 0 set 'Right Output Mixer PCM Playback Switch' 1
tinyplay ./2chn_test.wav -D 0 -d 0
```

### 4.6 两个官方 FAQ

| 问题 | 官方答复 |
| --- | --- |
| 硬件软件都正常、Audio 通路也正常，喇叭有声音但耳机没有 | 可能耳机音量太小，调大 `Headphone Playback Volume`（如 115 115） |
| 用 `tinymix` 设置了但不符合预期 | 可能命令没生效，或 `tinymix` 版本不对，检查版本与对应版本用法 |

第二条值得展开：`tinymix` 的控件名是 Codec 驱动导出的，**换一个内核版本，控件名可能变**。所以命令没效果时，第一件事是列出当前实际存在的控件名：

```bash
# 列出声卡 0 的所有控件与当前值
tinymix -D 0
```

把官方命令里的控件名与这份列表逐一对照，名字不一致就按实际名字改。

> 来源：官方文档 Basic_Application/audio/rdk_x5/wm8960_audio_hat

## 5. 幻尔载板

幻尔载板把音频作为多外设之一集成，用法与 WM8960 类似但不完全一样。

### 5.1 配置

```bash
sudo srpi-config
# 3 Interface Options -> I5 Audio -> Hiwonder Audio Driver HAT
# 重启（或 sync && sudo reboot）
```

启用后同样是 `duplexaudioi2s1` 占据声卡 0。

### 5.2 录音与播放

幻尔载板的例子用的是 `arecord` / `aplay`，且**录音也写 `hw:0,0`**：

```bash
# 录音；注意格式是 S32_LE（32 位小端）
arecord -Dhw:0,0 -c 2 -r 48000 -f S32_LE -t wav -d 10 /userdata/record1.wav

# 播放
aplay -D hw:0,0 /userdata/record1.wav
```

**这里有一个必须指出的官方文档矛盾**：幻尔载板文档写 `arecord -Dhw:0,0`，但同一套声卡拓扑（`duplexaudioi2s1`）在 `devices` 列表里显示 capture 是 `0-1`。按 ALSA 语义，`hw:0,0` 是 playback 设备，用它录音应该失败。

**判断依据与做法**：先用 `cat /proc/asound/devices` 确认本机实际的 capture device 号。若是 `0-1`（与 REV2/WM8960 一致），录音命令应改为 `-Dhw:0,1`。幻尔载板文档的这条命令可能是笔误，或该载板的 I2S 映射与另外两块不同——**以本机 `devices` 输出为准，不要照抄**。

> 来源：官方文档 Basic_Application/audio/rdk_x5/hiwonder_rasb5

## 6. `srpi-config` 音频切换与版本差异

### 6.1 菜单语义

`3 Interface Options` → `I5 Audio`，菜单里列出可用的音频转接板：Audio Driver HAT V1 / V2、WM8960 Audio HAT、Hiwonder Audio Driver HAT，以及 `UNSET`（卸载）。

官方说明：**"不同的硬件能支持的音频转接板也有差别"**——菜单项会根据板卡型号过滤。

### 6.2 版本差异（重要）

| 版本 | 音频相关变更 |
| --- | --- |
| 3.1.0 及之前 | 音频方案有限，ES8311 之类无开箱配置 |
| 3.2.3 | **新增支持微雪 WM8960 Audio HAT 与幻尔载板** |
| 3.3.3 | 修复音频 codec 驱动自动加载导致的 I2C 占用问题 |
| 3.4.1 | **`srpi-config` 音频配置流程改进，与 Ubuntu PulseAudio 通道切换保持同步** |
| 3.5.0 | 新增支持幻尔音频子板（补充完善）；新增 BMI08x、ICM42688 两款 IMU 的接口支持 |

三条可直接落地的判断：

1. **WM8960 与幻尔载板要 3.2.3 及以上**才有菜单项。3.1.x 上看不到 `WM8960 Audio Driver HAT` 是正常的。
2. **3.4.1 之前，`srpi-config` 配完音频后 PulseAudio 的默认通道可能没跟着切**，表现为 `aplay` 能响但桌面应用（浏览器、播放器）没声音。3.4.1 之后这个问题被修掉了。
3. **"修复音频 codec 驱动自动加载导致的 I2C 占用问题"**（3.3.3）解释了一个典型现象：没插音频板却扫到某个 I2C 地址被占（`i2cdetect` 显示 `UU`），是 codec 驱动被自动加载了。

### 6.3 ES8311 这类未官方支持的 Codec

社区明确：ES8311 在驱动的支持范围内，但**没有开箱即用的 demo 与配置**。要用必须自己改设备树。官方完整支持的音频方案只有：板载 ES8326、微雪 Audio Driver HAT REV2、WM8960 Audio HAT、幻尔载板。

> 来源：官方文档 System_configuration/srpi-config（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/srpi-config）、Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）、社区帖 35359（https://forum.d-robotics.cc/t/topic/35359）

## 7. `aplay` / `arecord` / PulseAudio 的关系

### 7.1 三套并存的音频栈

| 层 | 工具 | 特点 |
| --- | --- | --- |
| 硬件/驱动 | ALSA（`hw:x,y`） | 直通硬件，**独占**，最可靠 |
| 混音服务 | PulseAudio | 多应用共享，桌面默认走这层 |
| 简单封装 | `aplay` / `arecord` | 默认走 PulseAudio，可用 `-D` 强制直通 ALSA |

关键区别：

- `aplay xxx.wav`（不带 `-D`）→ 走 PulseAudio，可能被重采样、可能被路由到别的声卡；
- `aplay -D hw:0,0 xxx.wav` → **直通 ALSA 硬件**，跳过 PulseAudio。

所以官方所有示例都显式带 `-D hw:x,y`：这样能确保测的是硬件通路，不被音频服务干扰。

### 7.2 先列设备，再下命令

```bash
# 列出所有播放设备
aplay -l

# 列出所有录音设备
arecord -l

# 列出 PulseAudio 视角的 sink / source
pactl list short sinks
pactl list short sources
```

`aplay -l` 的典型输出（外接 HAT 场景）：

```
**** PLAYBACK 硬體裝置清單 ****
card 0: duplexaudioi2s1 [duplex-audio-i2s1], device 0: ...
card 1: duplexaudio [duplex-audio], device 0: i2s0-(null) ES8326 HiFi-0 [...]
```

### 7.3 `hw:` 与 `plughw:` 的区别

| 写法 | 行为 |
| --- | --- |
| `hw:0,0` | 严格直通，格式/采样率必须硬件支持，否则报错 |
| `plughw:0,0` | 允许 ALSA 做格式/采样率转换，兼容性更好 |

**排查时用 `hw:`**（能暴露格式问题），**日常使用用 `plughw:`**（省事）。`audio_echo_test` 用 `plughw` 是因为它要固定 16kHz，而硬件可能更偏好其它采样率。

### 7.4 PulseAudio 与直通冲突

`hw:` 是独占的。当 PulseAudio 正占着声卡时，`aplay -D hw:0,0` 会报 `Device or resource busy`。

处置（按侵入性从小到大）：

```bash
# 1) 临时挂起 PulseAudio（推荐，恢复简单）
pulseaudio --kill
# 用完恢复
pulseaudio --start

# 2) 只是让某个应用别走 PA：加上 -D hw: 即可，但要求 PA 没占着该设备

# 3) 彻底停掉用户态 PA（会影响桌面音频）
systemctl --user stop pulseaudio
```

### 7.5 3.4.1 之前的通道不同步问题

3.4.1 之前，`srpi-config` 切音频板只改 ALSA/设备树，不改 PulseAudio 的默认 sink。表现：

- `aplay -D hw:0,0 test.wav` 有声音；
- 但浏览器、VLC、`paplay` 没声音（还在往已经不存在的板载 sink 送）。

诊断：

```bash
pactl info | grep "Default Sink"
pactl list short sinks
```

若 Default Sink 还是旧的板载名，手动指定：

```bash
# 把 sink 名换成上一条命令列出的实际名字
pactl set-default-sink alsa_output.platform-sound.stereo-fallback
```

3.4.1 及以上版本不需要手工做这一步。

> 来源：官方文档 Release_Note/release_note、Basic_Application/audio 各篇

## 8. I2S 外接外放板

### 8.1 论坛里的真实尝试

社区有一位用户想把喇叭挪到 I2S 上，接了一块 MAX98357 音频板：

| MAX98357 | 40PIN 引脚 |
| --- | --- |
| SD | 24 |
| VCC | 6 |
| GND | — |
| LRC | 35 |
| BCLK | 12 |
| DIN | 40 |
| GAIN | 悬空 |

系统上用 SDK 配置"只开 I2S1，其余全部关闭"。结果 `aplay -l` 只看到板载 ES8326，看不到新声卡：

```
card 0: duplexaudio [duplex-audio], device 0: i2s0-(null) ES8326 HiFi-0 [...]
```

### 8.2 根因：`srpi-config` 只切总线，不建声卡

这是理解整件事的关键：

- `srpi-config` 的 `Peripheral bus config` 只改设备树里对应总线的 `status`（`okay` / `disabled`）；
- **它不会为你新接的 Codec 创建一个 `simple-audio-card` 声卡**。

一个能出声的声卡需要三个东西齐全：I2S 控制器（`cpu-dai`）、Codec 驱动（`codec-dai`）、以及把两者绑起来的 `sound` 节点。用户只做了第一件。

### 8.3 为什么改 DTS 会编译失败

该用户尝试直接改板上的 `/boot/hobot/x5-rdk.dts` 然后 `dtc -O dtb`，报：

```
Error: x5-rdk.dts:10.1-9 syntax error
FATAL ERROR: Unable to parse input tree
```

连"恢复原文件"后编译也报同样错误。

**根因**：板上的 `x5-rdk.dts` 是一个**包含 `#include` 的源文件**，它依赖同目录的 `x5-rdk.dtsi` 以及一堆被 include 的头文件。直接用 `dtc` 编译单个 `.dts`，预处理器没跑、include 路径没给，必然报语法错误——报错位置在第 10 行（也就是第一个 `#include` 之后），正是这个原因。

**正确做法**：不要用 `dtc` 手工编译板上文件。要么在 PC 上搭 SDK 环境用 `make dtbs`，要么用 `cpp` 预处理好再交给 `dtc`：

```bash
# 在 SDK 环境里（PC 侧），这是官方推荐路径
make dtbs
# 产物在 arch/arm64/boot/dts/hobot/ 下
```

### 8.4 结论与替代方案

对"只想加个 I2S 外放"的需求，务实的三条路：

| 方案 | 说明 | 代价 |
| --- | --- | --- |
| 用官方支持的 HAT | Audio Driver HAT REV2 / WM8960 / 幻尔载板，`srpi-config` 一键配 | 要买板，但零开发 |
| 走 3.5mm 口 | 板载 ES8326 已可用，接有源音箱 | 受限于 3.5mm 输出功率 |
| 自建 DTS | 搭 SDK 环境写 sound 节点，`make dtbs` | 需要 SDK 环境 + 驱动知识，且属于 BSP 范畴 |

第三条的 DTS 骨架（仅示意结构，实际需按硬件填 `phandle`）：

```dts
/ {
    sound {
        compatible = "simple-audio-card";
        model = "rdk-x5-max98357";

        simple-audio-card,cpu {
            sound-dai = <&i2s1>;
        };
        simple-audio-card,codec {
            sound-dai = <&max98357>;
        };
    };
};

&i2c1 {
    status = "okay";
    max98357: max98357@18 {
        compatible = "maxim,max98357a";
        reg = <0x18>;
        #sound-dai-cells = <0>;
        sdmode-gpios = <&lsio_gpio1 5 0>;
    };
};
```

**注意**：这类改动官方划在 BSP 范畴之外，社区支持范围内不覆盖。如果要量产级方案，官方建议直接对接商业研发团队或 FAE。

> 来源：社区帖 31206（https://forum.d-robotics.cc/t/topic/31206）

## 9. 声卡拓扑对照速查

把三块板放在一起对照，这张表是本章最该记住的内容。**同一句命令在不同板子上指向不同硬件**，是音频问题里最高频的误配来源。

| 场景 | 声卡 0 | 声卡 1 | 播放设备 | 录音设备 | 播放命令 | 录音命令 |
| --- | --- | --- | --- | --- | --- | --- |
| 仅板载（无 HAT） | ES8326 `duplexaudio` | — | `0-0` | `0-0` | `hw:0,0` | `hw:0,0` |
| 插 HAT 并启用后 | HAT `duplexaudioi2s1` | ES8326 `duplexaudio` | `0-0` | `0-1` | `hw:0,0` | `hw:0,1` |
| 插 HAT 但未启用 | ES8326 `duplexaudio` | — | `0-0` | `0-0` | `hw:0,0` | `hw:0,0` |

关键三点：

1. **板载的播放与录音在同一个 device（`0-0`）**；
2. **HAT 的播放在 `0-0`、录音在 `0-1`**，两者分开；
3. **HAT 启用后，板载被挤到声卡 1**，原来能用的 `hw:0,0` 现在指向 HAT。

判断当前处于哪种状态的唯一可靠手段：

```bash
cat /proc/asound/cards          # 有几张卡、各是什么
cat /proc/asound/devices        # 每张卡有哪些 device
ls /dev/snd/                    # 用户空间设备文件
```

三条输出必须能互相对应上。只看 `cards` 而不看 `devices`，就会犯"知道有 HAT，但不知道录音是 device 1"的错误。

### 9.1 从 `devices` 反推命令

`cat /proc/asound/devices` 的每一行格式是 `[card-device]`：

```
 2: [ 0- 0]: digital audio playback      → 播放：hw:0,0
 3: [ 0- 1]: digital audio capture       → 录音：hw:0,1
 5: [ 1- 0]: digital audio playback      → 播放：hw:1,0
 6: [ 1- 0]: digital audio capture       → 录音：hw:1,0
```

规则很直接：`digital audio playback` 的 `[card-device]` 就是 `-D hw:card,device`；`digital audio capture` 同理。**不要背命令，照着这张表抄。**

## 10. 完整自查流程

按顺序走一遍，能覆盖 90% 的音频问题：

```bash
# ── 第 1 步：硬件层 ──────────────────────────
# 耳机是否是 4 段式？插头是否插到底（金属部分不应外露）？
# HAT 的拨码开关是否正确（REV2 需 3 个全拨 OFF）？
# 40PIN 是否插紧、方向正确？

# ── 第 2 步：驱动层 ──────────────────────────
cat /proc/asound/cards
# 期望：板载场景只有 1 张卡；HAT 场景有 2 张卡且 card0 是 duplexaudioi2s1

cat /proc/asound/devices
# 期望：能看清每张卡有几个 playback / capture device

ls /dev/snd/
# 期望：pcmC*D*p（播放）与 pcmC*D*c（录音）成对出现

# ── 第 3 步：内核层 ──────────────────────────
sudo dmesg | grep -iE "es8326|es7210|es8156|wm8960|asoc|codec" | tail -30
# 关注：Clock coefficients do not match（时钟不匹配）
#       某个 codec probe failed（驱动加载失败）

# ── 第 4 步：路由层（仅 WM8960 需要）──────────
tinymix -D 0
# 列出所有控件与当前值；确认官方命令里的控件名在本机存在

# ── 第 5 步：直通测试 ────────────────────────
# 用官方示例的格式，先录再放，闭环验证
sudo arecord -D hw:0,0 -c 2 -r 48000 -f S24_LE -t wav -d 5 /tmp/t.wav
sudo aplay -D hw:0,0 /tmp/t.wav

# ── 第 6 步：服务层 ──────────────────────────
pactl info | grep "Default Sink"
pactl list short sinks
# 若 Default Sink 指向已不存在的旧设备，手动设置
```

### 10.1 各步骤的判据

| 卡在哪一步 | 说明 | 下一步 |
| --- | --- | --- |
| 第 1 步 | 纯物理问题 | 换耳机、重插、拨对拨码 |
| 第 2 步 `cards` 少一张 | HAT 驱动没加载 | 重新 `srpi-config` 选板 + 重启 |
| 第 2 步 `devices` 缺 capture | Codec 的 ADC 侧没起来 | 查 `dmesg` 里 codec probe 记录 |
| 第 3 步有 `Clock coefficients` | 采样率/位深与硬件不匹配 | 换官方示例格式（S24_LE / 48k） |
| 第 4 步控件名对不上 | `tinymix` 版本与驱动不匹配 | 按 `tinymix -D 0` 的实际名字改 |
| 第 5 步录得到但放不出 | 播放路由没开 | 回第 4 步打开 output mixer |
| 第 6 步 Default Sink 旧 | PulseAudio 没跟着切 | `pactl set-default-sink` |

> 来源：官方文档 Basic_Application/audio/rdk_x5 各篇、System_configuration/srpi-config（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/srpi-config）

## 11. 四段式排障：`aplay` 能响但耳机只有杂音

**现象**

```bash
aplay -D hw:1,0 ./mali.wav
```

输出正常：

```
Playing WAVE './mali.wav' : Signed 16 bit Little Endian, Rate 22050 Hz, Stereo
```

但耳机里传来的是**杂音**而不是音乐。耳机是 4 段式的。系统版本 3.1.0。

**根因**

三条线索交叉：

1. 声卡号用了 `hw:1,0`。在**没插任何 HAT** 的板子上，声卡 0 才是板载 ES8326；用 `hw:1,0` 指向了一个不存在的或非目标设备。这个案例里很可能系统识别到了第二个声卡（如 USB 声卡或异常注册的节点），而它并非耳机口对应的硬件。
2. 用户日志里有一条反复出现的内核告警：

```
kernel: es8326 7-0018: Clock coefficients do not match
```

这是 ES8326 Codec 的**时钟系数不匹配**告警——I2S 主时钟与 Codec 期望的系数对不上。它会直接导致输出的音频数据被错误重采样，听感就是杂音/爆音而不是音乐。
3. 同日志里还有 PulseAudio 的报错：

```
pulseaudio[2370]: Most likely this is a bug in the ALSA driver 'snd_soc_hobot_sound_duplex_host'.
pulseaudio[2370]: ALSA woke us up to write new data to the device, but there was actually nothing to write.
```

这说明 HAL 层与驱动在 period 边界上不同步——典型的采样率/位深与硬件能力不匹配。

4. 系统版本是 **3.1.0**，而音频相关的关键修复（codec 驱动自动加载的 I2C 占用、`srpi-config` 与 PulseAudio 同步）分别在 3.3.3 和 3.4.1 才进。

**处置**

```bash
# 1) 先用正确的声卡号：板载是 0
cat /proc/asound/cards          # 确认哪个是板载
sudo aplay -D hw:0,0 /userdata/record1.wav

# 2) 核对时钟告警是否还在
dmesg | grep -i "clock coefficients"

# 3) 用官方推荐的格式（S24_LE / 48kHz）复测，排除格式不匹配
sudo arecord -D hw:0,0 -c 2 -r 48000 -f S24_LE -t wav -d 5 /userdata/t.wav
sudo aplay -D hw:0,0 /userdata/t.wav

# 4) 仍有杂音 → 升级系统（3.4.1 及以上）
sudo apt update && sudo apt full-upgrade
sudo reboot
```

**预防**

- 不要凭印象写声卡号，每次都先 `cat /proc/asound/cards` + `ls /dev/snd/`；
- 出现 `Clock coefficients do not match` 一律先怀疑采样率/位深与硬件不匹配，改用官方示例的 `S24_LE / 48000`；
- 音频问题在 3.1.x 上出现时，先升级再排查——3.2.3 / 3.3.3 / 3.4.1 三个版本连续修了音频相关的问题。

> 来源：社区帖 28970（https://forum.d-robotics.cc/t/topic/28970）

## 12. 常见误区

1. **"插上 HAT 后 `hw:0,0` 还是板载声卡"**——不是。启用 HAT 后声卡 0 变成 HAT（`duplexaudioi2s1`），板载被挤到声卡 1。命令不变但硬件变了，是"没声音"的头号原因。

2. **"`arecord -D hw:0,0` 在 HAT 上能录音"**——不能。HAT 的拓扑是播放 `0-0`、录音 `0-1`，`hw:0,0` 是播放设备。录音必须 `hw:0,1`。（板载相反：播放录音都在 `0-0`。）

3. **"`srpi-config` 打开 I2S 就能用自己接的外放板"**——不能。它只改总线 `status`，不会创建声卡。还需要 Codec 驱动 + `simple-audio-card` 节点。

4. **"用 `dtc` 直接编译板上的 `x5-rdk.dts` 就行"**——必然报 `syntax error`，因为该文件含 `#include`，需要预处理和 include 路径。要在 SDK 环境里 `make dtbs`。

5. **"耳机没声音就是硬件坏了"**——先查两点：耳机是不是 4 段式、插头有没有插到底（金属部分外露即未插到底）。WM8960 还要单独查 `Headphone Playback Volume` 是否被设成 0。

6. **"`tinymix` 设了就该生效"**——控件名随 Codec 驱动版本变化。命令没效果时先 `tinymix -D 0` 列出当前实际控件名再对照，别硬套官方原文。

7. **"`aplay` 有声音，桌面应用也该有声音"**——3.4.1 之前不是。`srpi-config` 切板子后 PulseAudio 的默认 sink 可能没跟着切，需要 `pactl set-default-sink` 手动指定。
