# 网络、蓝牙与多媒体示例

## 本章解决什么

前四章讲的都是"某个外设怎么用"，本章讲两件把它们串起来的事：第一，**网络与蓝牙**——有线怎么从静态 IP 改 DHCP、WiFi 在 Server 版上怎么配、蓝牙从初始化到配对、以及 Soft AP 热点怎么开；第二，**五个官方多媒体示例**（`vio2display`、`vio2encoder`、`rtsp2display`、`bpu`、`decode2display`）的逐个拆解——每个示例吃什么输入、吐什么输出、参数怎么填、日志里哪些是正常、哪些是真故障。这些示例是理解 X5 多媒体链路（VIO / VENC / VDEC / BPU / Display）最直接的入口，也是"跑通了但不知道为什么通"和"报错了但不知道为什么错"的分水岭。

## 1. 有线网络

### 1.1 默认是静态 IP，不是 DHCP

这一点最容易踩：**开发板有线网络默认采用静态 IP 配置，初始 IP 地址为 `192.168.127.10`**。插上网线不会自动从路由器拿地址。

### 1.2 两套配置文件（按版本分）

官方文档明确按版本分成两套，改错文件等于没改：

| 版本 | 配置文件 | 说明 |
| --- | --- | --- |
| **RDK X5 ≥ 3.3.0**、RDK X3 ≥ 3.0.2 | `/etc/NetworkManager/system-connections/netplan-eth0.nmconnection` | NetworkManager 时代 |
| 更早版本 | `/etc/network/interfaces` | ifupdown 时代 |

**判断本机是哪套**：

```bash
cat /etc/version                 # 看系统版本
ls /etc/NetworkManager/system-connections/ 2>/dev/null
```

### 1.3 改静态 IP（3.3.0 及以上）

```bash
sudo vim /etc/NetworkManager/system-connections/netplan-eth0.nmconnection
```

```ini
[connection]
id=netplan-eth0
uuid=f6f8b5a7-9e23-49b2-a792-dc589b3d3e88
type=ethernet
interface-name=eth0

[ethernet]
wake-on-lan=0

[ipv4]
address1=192.168.127.10/24,192.168.127.1
dns=8.8.8.8;8.8.4.4;
method=manual
route-metric=700

[ipv6]
addr-gen-mode=eui64
method=ignore
```

改完生效：

```bash
sudo restart_network
```

两个字段要读懂：

- `address1` 的格式是 `IP/掩码位数,网关`；
- `route-metric=700` 是**网络优先级**，设为 700 是让有线优先级**更低**——有线与无线同时可用时优先走无线。

### 1.4 改 DHCP（3.3.0 及以上）

把 `[ipv4]` 段改成只留两行：

```ini
[ipv4]
method=auto
route-metric=700
```

```bash
sudo restart_network
```

### 1.5 改 MAC 地址

在 `[ethernet]` 段加一行：

```ini
[ethernet]
cloned-mac-address=12:34:56:78:9A:BA
wake-on-lan=0
```

MAC 改动**需要 reboot 生效**（`restart_network` 不够）。

### 1.6 老版本（`/etc/network/interfaces`）

静态 IP：

```
auto eth0
iface eth0 inet static
    pre-up /etc/set_mac_address.sh
    address 192.168.127.10
    netmask 255.255.255.0
    gateway 192.168.127.1
    metric 700
```

DHCP：

```
auto eth0
iface eth0 inet dhcp
    metric 700
```

改 MAC 就在静态配置后面追加一行：

```
    pre-up ifconfig eth0 hw ether 00:11:22:9f:51:27
```

同样 `sudo restart_network` 生效，MAC 改动要 reboot。

> 来源：官方文档 System_configuration/network_bluetooth（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/network_bluetooth）

## 2. 无线网络（WiFi）

### 2.1 硬件与模式

开发板集成 2.4GHz 无线 WiFi 模块，支持 **Soft AP** 与 **Station** 两种模式，**默认运行在 Station 模式**。

3.3.3 版本把 WiFi 驱动升级到 `2025_0410`，提升连接稳定性；3.2.3 版本也有一次"增强弱信号环境下连接稳定性，优化休眠/唤醒过程中的自动重连机制"的升级。

### 2.2 Station 模式：Desktop 版

点桌面右上角 Wi-Fi 图标 → 选热点 → 输密码。没有命令可讲。

### 2.3 Station 模式：Server 版（命令行）

三步：

```bash
# 1) 扫描
sudo nmcli device wifi rescan
```

如果返回：

```
Error: Scanning not allowed immediately following previous scan.
```

说明**扫描过于频繁**，等几秒再试，不是故障。

```bash
# 2) 列出热点
sudo nmcli device wifi list

# 3) 连接（RDK 提供的封装脚本）
sudo wifi_connect "WiFi-Test" "12345678"
```

成功输出：

```
Device 'wlan0' successfully activated with 'd7468833-4195-45aa-aa33-3d43da86e1a7'.
```

失败输出：

```
Error: No network with SSID 'WiFi-Test' found.
```

这条失败说明**热点没被扫到**（不是密码错）。重新 `nmcli device wifi rescan` 再连。密码错的报错与之不同，通常是 `Secrets were required, but not provided`。

### 2.4 天线：板载 vs 外置

RDK X5 支持在板载天线与外置天线之间切换：

```bash
sudo srpi-config
# 3 Interface Options -> Configure Wi-Fi antenna -> Onboard / External
```

验证当前状态：

```bash
cat /boot/config.txt
```

```
antenna_option=trace     # 板载天线
antenna_option=cable     # 外置天线
```

**适用型号**（官方列出）：RDK X3（V2.1）、RDK X5（V0.1、V1.0）、RDK X5 MD（小于 V1.1）。其余型号没有这个选项。

社区有用户问"外接天线是否需要软件配置"，正确答复是**需要**——不是即插即用，要走上面的 `srpi-config` 或直接改 `config.txt`。另外 IPEX 接口是**1 代**，买成 2 代/3 代物理上装不上。

### 2.5 Soft AP 模式：两条路

**路线一：hostapd + isc-dhcp-server（老方案，全版本可用）**

```bash
sudo apt update
sudo apt install hostapd isc-dhcp-server
```

配置 `/etc/hostapd.conf`，2.4G 有密码版本：

```
interface=wlan0
driver=nl80211
ctrl_interface=/var/run/hostapd
ssid=Sunrise
channel=6
ieee80211nat=1
hw_mode=g
ignore_broadcast_ssid=0
wpa=2
wpa_key_mgmt=WPA-PSK
wpa_pairwise=CCMP
wpa_passphrase=12345678
```

X5 还支持 **5G 热点**，把两行改掉：

```
channel=36
hw_mode=a
```

配置 DHCP 服务：

```bash
# /etc/default/isc-dhcp-server
INTERFACESv4="wlan0"
```

```bash
# /etc/dhcp/dhcpd.conf 末尾追加
subnet 10.5.5.0 netmask 255.255.255.0 {
  range 10.5.5.100 10.5.5.254;
  option subnet-mask 255.255.255.0;
  option routers 10.5.5.1;
  option broadcast-address 10.5.5.31;
  default-lease-time 600;
  max-lease-time 7200;
}
```

停掉 `wpa_supplicant`、复位网卡、起 hostapd、配 IP、起 DHCP：

```bash
sudo systemctl mask wpa_supplicant
sudo systemctl stop wpa_supplicant

sudo ip addr flush dev wlan0
sudo ifconfig wlan0 down
sudo ifconfig wlan0 up

sudo hostapd -B /etc/hostapd.conf
sudo ifconfig wlan0 10.5.5.1 netmask 255.255.255.0
sudo systemctl start isc-dhcp-server
sudo systemctl enable isc-dhcp-server
```

**切回 Station**（X5 专用，多一步重装驱动）：

```bash
killall -9 hostapd
sudo ip addr flush dev wlan0
sudo ifconfig wlan0 down
sudo ifconfig wlan0 up

sudo systemctl unmask wpa_supplicant
sudo systemctl restart wpa_supplicant

# X5 专用：重装 WiFi 驱动
sudo rmmod aic8800_fdrv
sudo modprobe aic8800_fdrv

sudo wifi_connect "WiFi-Test" "12345678"
```

注意驱动名：X5 用 **`aic8800_fdrv`**（官方文档写这个）。社区某些回复里写的是 `aicwf_sdio`——**以本机 `lsmod | grep -i aic` 的实际输出为准**，不要照抄任何一边。

**路线二：NetworkManager（≥ 3.3.0 / ≥ 3.0.2）**

桌面右上角无线图标 → `Edit Connections...` → 左下角 `+` → Connection Type 选 `Wi-Fi` → 填 `SSID`、`Mode` 选 `Hotspot`、`Band` 选 `Automatic` / `A(5GHz)` / `B/G(2.4GHz)` → `Wi-Fi Security` 里选加密方式与密码 → 重启或 `restart_network`。

### 2.6 STA + AP 并发：不支持

社区明确提问"X5 支持 STA+AP 并发吗"，回答是**不支持**——连接 WiFi 后再配热点会导致 WiFi 断开。

原因（社区给的判断）：WiFi 驱动对 AP/STA 热切换处理不完善，且模组固件不支持同时工作在两种模式。

需要同时联网 + 开热点，唯一务实方案是**加一个 USB WiFi 网卡**：板载走 STA，USB 网卡走 AP。

> 来源：官方文档 System_configuration/network_bluetooth、System_configuration/srpi-config（https://developer.d-robotics.cc/rdk_x_doc/System_configuration/srpi-config）、Release_Note/release_note、社区帖 35412（https://forum.d-robotics.cc/t/topic/35412）、35522（https://forum.d-robotics.cc/t/topic/35522）

## 3. DNS 服务

```bash
sudo vim /etc/systemd/resolved.conf
```

```ini
DNS=8.8.8.8 114.114.114.114
```

```bash
sudo systemctl restart systemd-resolved
sudo systemctl enable systemd-resolved

sudo mv /etc/resolv.conf /etc/resolv.conf.bak
sudo ln -s /run/systemd/resolve/resolv.conf /etc/resolv.conf
```

最后一步是把 `/etc/resolv.conf` 换成指向 systemd-resolved 的软链——不换的话，`resolved.conf` 里的 DNS 不会真正生效。

## 4. 蓝牙

### 4.1 初始化：3.0.0 起默认随系统启动

官方明确：**从 3.0.0 系统开始，蓝牙默认随系统启动，无需手动重复初始化**，X3 与 X5 一致。

如果 `hciconfig` 看不到设备（说明没起来），手动跑初始化脚本：

```bash
sudo /usr/bin/startbt.sh
```

该脚本做三件事：

```bash
hciconfig hci0 up        # Link Up
hciconfig hci0 piscan    # 可被发现
```

确认蓝牙进程是否正常：

```bash
ps ax | grep "/usr/bin/dbus-daemon\|/usr/lib/bluetooth/bluetoothd"
```

期望看到两行：`/usr/bin/dbus-daemon`、`/usr/lib/bluetooth/bluetoothd`。

### 4.2 通信接口的现实限制

官方说得很直白：受限于接口布局与硬件资源分配，**开发板未能完整复现蓝牙模组的所有通信接口**。目前只提供 `BT_RX` / `BT_TX` 双线模式。

三种接口能力对照：

| 模式 | 引脚 | 能力 | 风险 |
| --- | --- | --- | --- |
| 基础通信（UART Only） | BT_RX、BT_TX | AT 指令、低速数据 | **无流控**，波特率超载或大数据量时丢包/缓冲溢出 |
| 增强传输（加硬件流控） | BT_RX、BT_TX、BT_CTS、BT_RTS | 避免丢包，支持 A2DP 单向音频 | 需硬件支持流控引脚 |
| 语音通信（PCM 同步） | PCM_SYNC、PCM_DIN、PCM_CLK、PCM_DOUT | SCO 链路实时双向音频（HFP/HSP） | 需 PCM 接口引出 |

### 4.3 USB 蓝牙：功能更完整的选择

需要 SPP（虚拟串口高速通信）、PAN（虚拟网卡保带宽）、A2DP（高保真音频不中断）时，官方推荐**优先用 USB 蓝牙模块**。

板端已集成 `USB2.0-BT`、`CSR8510 A10` 等常见驱动，可**直接支持大部分免固件的 USB 蓝牙模组**。

**Realtek 系列例外**：需要额外固件。要向模组厂家索取适配 Linux 的固件，放到指定目录后才能用。

### 4.4 扫描、配对、信任

```bash
sudo bluetoothctl
```

交互模式下的完整流程：

```
[bluetooth]# show                    # 看 controller 信息，留意 powered / discoverable
[bluetooth]# power on                # 使能蓝牙
[bluetooth]# discoverable on         # 让附近设备能发现自己（默认名 ubuntu）
[bluetooth]# scan on                 # 主动扫描，会周期性打印附近设备
[bluetooth]# scan off                # 关闭扫描并汇总
[bluetooth]# pair AA:BB:CC:DD:EE:FF  # 配对，按提示输 yes，对端选"配对"
[bluetooth]# trust AA:BB:CC:DD:EE:FF # 信任，下次自动连接
```

`power on` 与 `discoverable on` 是两个不同状态：

- `powered` = 蓝牙射频开了；
- `discoverable` = 别人能扫到你。

**只 `power on` 不 `discoverable on`，手机是搜不到板子的**——这是"连不上蓝牙"最常见的原因。

### 4.5 蓝牙连上了但控制不了设备

社区有一个典型场景：手机连上了小车的蓝牙，但控制小车运动没反应。

根因是**"蓝牙已连接"只代表底层链路通了，不代表上层控制服务在跑**。蓝牙本身只提供一条数据通道，谁去解析指令、谁去驱动电机，是另一个进程的事。

```bash
# 1) 看有没有控制服务在跑
ps -ef | grep -i blue
ros2 node list | grep -i blue

# 2) 蓝牙链路本身是否正常
hciconfig
bluetoothctl info <MAC>

# 3) 从对端发数据，看板端能否收到
sudo rfcomm watch /dev/rfcomm0
```

> 来源：官方文档 System_configuration/network_bluetooth、社区帖 35143（https://forum.d-robotics.cc/t/topic/35143）

## 5. 多媒体示例总览

### 5.1 五个示例的共同点

全部位于 `/app/cdev_demo/`，全部是 C 语言 + `libspcdev`，全部需要 `make` 编译，全部在 Desktop 版上要先关桌面：

```bash
sudo systemctl stop lightdm
```

官方 V4L2 文档对这条给了一句总括："涉及到 hdmi 显示，需要先关闭桌面。"

`decode2display` 的 FAQ 解释了为什么："我们也可以用窗口来显示，但资源占用过大，会导致不流畅或者卡顿，直接显示到显示器效果更直观。"

### 5.2 五个示例的输入输出矩阵

| 示例 | 输入 | 输出 | 涉及模块 | 是否需要摄像头 |
| --- | --- | --- | --- | --- |
| `vio2display` | MIPI 摄像头 | HDMI 直出画面 | VIN → ISP → VSE → Display | 是 |
| `vio2encoder` | MIPI 摄像头 | H.264 码流文件 | VIN → ISP → VSE → VENC | 是 |
| `decode2display` | H.264 文件 | HDMI 直出画面 | VDEC → VPS → Display | 否 |
| `rtsp2display` | RTSP 流（H.264） | HDMI 直出画面 | RTSP → VDEC → VPS → Display | 否 |
| `bpu` | MIPI 摄像头 或 H.264 文件 | HDMI 叠加检测框 | VIN/VDEC → BPU → Display | 可选 |

另外还有 `vio_capture`（采集 YUV/RAW 存文件）和 `audio_echo_test`（音频回采验证，见第四章）。

### 5.3 示例都依赖的公共环境

```bash
# 1) 关闭桌面（需要 sudo）
sudo systemctl stop lightdm

# 2) 确认摄像头已被识别（仅 vio* 系列需要）
ls /dev/video*

# 3) 确认显示通路
modetest -M vs-drm -c | head -30
```

## 6. `vio2display`：摄像头直出

### 6.1 作用与参数

把摄像头画面直接送到 HDMI，不经过任何处理——这是验证"摄像头 + 显示"整条硬件链路最快的办法。

```bash
cd /app/cdev_demo/vio2display
make
./vio2display -h 1080 -w 1920
```

参数只有两个，都必填：

| 参数 | 含义 | 是否必填 |
| --- | --- | --- |
| `-h` / `--height` | sensor 输出高度 | 是 |
| `-w` / `--width` | sensor 输出宽度 | 是 |

**`-h` / `-w` 必须匹配摄像头实际分辨率。** 摄像头是 1080p 就填 1080/1920，是 480p 就填 480/640。填错的表现是画面撕裂、绿屏或直接失败。

官方文档里还用一句"`-i` 是必填选项，代表输入视频的文件路径"——但 `--help` 输出里**没有 `-i` 参数**。以 `--help` 为准：`vio2display` 只有 `-h` 和 `-w` 两个参数。

### 6.2 正常日志怎么读

```
Opened DRM device: /dev/dri/card0
1920x1080
1360x768
1280x1024
1280x720
1024x768
800x600
720x576
720x480
640x480
disp_w=1920, disp_h=1080
```

前 9 行是**显示器支持的模式列表**（从 EDID 读出来的），最后一行 `disp_w=..., disp_h=...` 是最终选中的模式。

接着是一大段 sensor 探测日志：

```
Searching camera sensor on device: /proc/device-tree/soc/cam/vcon@0 i2c bus: 6 mipi rx phy: 0
WARN: Sensor Name: sc1330t, Expected Chip ID: 0xCA18, Actual Chip ID Read: 0x00
WARN: Sensor Name: irs2875-tof, Expected Chip ID: 0x2875, Actual Chip ID Read: 0x00
...（几十行）
[0] INFO: Found sensor name:imx219-1920x1080-30fps on mipi rx csi 0, i2c addr 0x10,
      config_file:linear_1920x1080_raw10_30fps_2lane.c
```

**这一大堆 `WARN` 是正常的**——驱动在遍历所有可能的 sensor，每试一个不是的就打一条 `Actual Chip ID Read: 0x00`。真正要看的是 `Found sensor name:` 那一行。

最后是模块状态表：

```
================= VP Modules Status ====================
======================== VFLOW =========================
(active)[S0] vin0_C0*(dma)-m2m-isp0_C0-m2m-vse0_C0
```

这条 vflow 说明链路是 `vin0 → isp0 → vse0`，全部 active。如果某一段断开，vflow 里会显示缺失。

```
========================= SIF ==========================
width:1920  height:1080  format:0x2b  online_isp:1  ddr_en:0
========================= ISP ==========================
input_format:1  input_bit_width:10  output_format:2  output_bit_width:8
========================= VSE ==========================
dns0 channel: roi [0][0][1920][1080], target [1920][1080]
```

`input_bit_width:10` + `output_bit_width:8` 说明 RAW10 进、8bit 出——这是标准路径。

最后：

```
sp_open_camera success!
Press 'q' to Exit !
```

按 `q` 退出（**焦点要在显示窗口上**）。

### 6.3 常见误配

- **填了 `-i`**：`vio2display` 没有这个参数，传了会被忽略或报 usage；
- **分辨率与摄像头不符**：画面异常；
- **没关 `lightdm`**：能跑但屏幕黑；
- **摄像头没识别**：日志里没有任何 `Found sensor name:` 行，全是 `WARN`。

> 来源：官方文档 Basic_Application/cdev_demo_sample/vio2display（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/cdev_demo_sample/vio2display）

## 7. `vio2encoder`：摄像头编码

### 7.1 作用与参数

把摄像头数据编码成 H.264 码流存文件。

```bash
cd /app/cdev_demo/vio2encoder
make
./vio2encoder -w 1920 -h 1080 --iwidth 1920 --iheight 1080 -o stream.h264
```

参数分两组，**这是最容易搞混的地方**：

| 参数 | 含义 | 组 |
| --- | --- | --- |
| `--iwidth` | **sensor 输出**宽度 | 输入侧 |
| `--iheight` | **sensor 输出**高度 | 输入侧 |
| `-w` / `--owidth` | **编码输出**宽度 | 输出侧 |
| `-h` / `--oheight` | **编码输出**高度 | 输出侧 |
| `-o` / `--output` | 输出文件路径 | — |

因为有两组尺寸，所以可以做到"sensor 出 1080p，编码成 720p"：

```bash
./vio2encoder -w 1280 -h 720 --iwidth 1920 --iheight 1080 -o stream_720p.h264
```

### 7.2 正常日志

```
!INFO [OpenCamera][0450]hbn module
set camera fps: -1,width: 1920,height: 1080
...
[0] INFO: Found sensor name:imx219-1920x1080-30fps on mipi rx csi 0, ...
...
sp_open_camera success!
!INFO [OpenEncode][0072]pipe:0 type:0 1920x1080 bit_rate:8000 begin init
!INFO [vp_encode_config_param][0418]codec type is h264: frame size:3110912 frame rate: 30
sp_start_encode success!
sp_module_bind(vio -> encoder) success!
```

三个关键点：

- `bit_rate:8000` —— 码率 8000kbps = 8Mbps，**写死在示例里**，没有命令行参数可调；
- `codec type is h264` —— 编码格式固定 H.264；
- `frame rate: 30` —— 取 sensor 帧率；
- `sp_module_bind(vio -> encoder) success!` —— 绑定成功，这是"开始出流"的标志。

产出的 `stream.h264` 是**裸 H.264 码流**（无容器），用 VLC 能直接播，`ffprobe` 也能读。

### 7.3 常见误配

- **只填 `-w`/`-h` 不填 `--iwidth`/`--iheight`**：输入侧尺寸缺失，编码器按默认值初始化，输出比例错误；
- **以为能改码率**：不能，8Mbps 是硬编码；
- **想同时出多路不同分辨率**：一个进程只出一路，多路要起多个进程，但 MIPI 摄像头通常不支持被两个进程同时打开。

> 来源：官方文档 Basic_Application/cdev_demo_sample/vio2encoder（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/cdev_demo_sample/vio2encoder）

## 8. `decode2display`：文件解码上屏

### 8.1 作用与参数

把本地 H.264 文件解码后循环播放到 HDMI。**不需要摄像头**，这是纯软件链路验证的首选。

```bash
cd /app/cdev_demo/decode2display
make
# 先准备输入：把板端自带的样例文件拷过来
cp /opt/tros/humble/lib/hobot_codec/config/1920x1080.h264 ./
sudo ./decoder2display -w 1920 -h 1080 -i 1920x1080.h264
```

注意：**可执行文件叫 `decoder2display`，目录叫 `decode2display`**。官方原文就是这样，写错名字会 `command not found`。

| 参数 | 含义 | 是否必填 |
| --- | --- | --- |
| `-w` / `--width` | 输入视频宽度 | 是 |
| `-h` / `--height` | 输入视频高度 | 是 |
| `-i` / `--input` | 输入视频文件路径 | 是 |

### 8.2 正常日志

```
Opened DRM device: /dev/dri/card0
1920x1080
1280x800
1280x720
...
disp_w=1920, disp_h=1080
sp_start_decode success!
Opened DRM device: /dev/dri/card0
DRM is available, using libdrm for rendering.
...
Mode 0: 1280x800 @ 59Hz
Mode 1: 1920x1080 @ 60Hz
...
```

以及一个反复出现的提示，**这是正常的**：

```
!INFO [vp_decode_work_func][0974]No more input data available, avpacket.size: 0.
       Re-cycling to send again.
```

它表示文件读完了，解码器重新从头开始——也就是"循环播放"。不是错误。

### 8.3 工作流程

基于 `libspcdev`：解析命令行参数 → 通过 `libspcdev.so` 的 API 获取显示屏分辨率 → 初始化解码器与显示模块 → **根据视频分辨率与显示器分辨率判断是否需要 VPS 缩放** → 启动解码循环。

这个"判断是否需要 VPS"是理解该示例的关键：如果视频是 1920x1080、显示器也是 1920x1080，就走直通；如果显示器是 1280x800，就要过 VPS 缩放。

### 8.4 常见误配

- **可执行文件名写错**（`decode2display` vs `decoder2display`）；
- **没准备输入文件**：目录里默认没有 `.h264`，要从 `/opt/tros/humble/lib/hobot_codec/config/` 拷；
- **把 `No more input data available` 当报错**：它是循环播放的标志。

> 来源：官方文档 Basic_Application/cdev_demo_sample/decode2display（https://developer.d-robotics.cc/rdk_x_doc/Basic_Application/cdev_demo_sample/decode2display）

## 9. `rtsp2display`：拉流解码上屏

### 9.1 作用与参数

从 RTSP 拉 H.264 流，硬件解码（`SP_Decoder`）+ 视频处理（`SP_VPS`）+ 显示（`SP_Display`）。

```bash
cd /app/cdev_demo/rtsp2display
make
```

| 参数 | 含义 | 取值 |
| --- | --- | --- |
| `-i` / `--input` | RTSP URL | 如 `rtsp://127.0.0.1/1920x1080.h264` |
| `-t` / `--type` | 传输方式 | `tcp` 或 `udp` |

### 9.2 官方给的完整自测流程

这个示例自带一个 `live555MediaServer`，可以本地起一个 RTSP 服务器自测，不需要外部摄像头或网络流：

```bash
# 1) 准备输入文件
cp /opt/tros/humble/lib/hobot_codec/config/1920x1080.h264 ./

# 2) 后台起本地 RTSP 服务器
./live555MediaServer &

# 3) 关桌面
sudo systemctl stop lightdm

# 4) 拉流解码上屏
sudo ./rtsp2display -i rtsp://127.0.0.1/1920x1080.h264 -t tcp
```

`live555MediaServer` 启动后会打印可用 URL 与支持的格式清单：

```
version 1.01 (LIVE555 Streaming Media library version 2020.07.09).
Play streams from this server using the URL
        rtsp://192.168.127.10/
where is a file present in the current directory.
Each file's type is inferred from its name suffix:
        ".264" => a H.264 Video Elementary Stream file
        ".265" => a H.265 Video Elementary Stream file
        ...
```

### 9.3 正常日志

```
avformat_open_input ok!
avformat_find_stream_info ok!
Input #0, rtsp, from 'rtsp://127.0.0.1/1920x1080.h264':
  Metadata:
    title           : H.264 Video, streamed by the LIVE555 Media Server
    comment         : 1920x1080.h264
  Duration: N/A, start: 0.041667, bitrate: N/A
  Stream #0:0: Video: h264 (High), yuv420p(progressive), 1920x1080
          [SAR 1:1 DAR 16:9], 24 fps, 24 tbr, 90k tbn, 48 tbc
av_dump_format ok!
Opened DRM device: /dev/dri/card0
```

`avformat_*` 三行说明 FFmpeg 层的协议解析与流信息都拿到了；`Stream #0:0: Video: h264 (High)` 是视频流的实际参数。

还要注意这一行，**它是流的正常结束**：

```
Could not read frame ---(error 'End of file')
```

文件流播完了就是 EOF，不是解码错误。用真实网络摄像头流时不会有这条。

### 9.4 常见误配

- **`-t` 填了别的值**：只接受 `tcp` 或 `udp`；
- **本地测试忘了起 `live555MediaServer`**：`avformat_open_input` 就会失败；
- **URL 里写主机名而非 IP**：`live555` 绑定的是本机地址，用 `127.0.0.1` 最稳；
- **`rtsp://127.0.0.1/` 少了文件名**：必须带 `/1920x1080.h264`。

## 10. `bpu`：模型推理示例

### 10.1 作用与两种模式

`bpu` 是 C 语言调用 BPU 模型的示例，有**两种输入模式**：

| 模式 | 输入 | 说明 |
| --- | --- | --- |
| 带摄像头 | MIPI 摄像头实时画面 | 固定用 YOLOv5 模型 |
| 不带摄像头 | 本地 H.264 文件，先解码再推理 | 用 FCOS 模型 |

### 10.2 编译与运行

```bash
cd /app/cdev_demo/bpu/src
make
# 产物在 src/bin 下
cd bin
```

**模式 0：摄像头 + YOLOv5**

```bash
sudo ./sample -f /app/model/basic/yolov5s_672x672_nv12.bin -m 0
```

**模式 1：H.264 文件 + FCOS**

```bash
sudo ./sample -f /app/model/basic/fcos_512x512_nv12.bin -m 1 -i 1080p_.h264 -w 1920 -h 1080
```

| 参数 | 含义 | 说明 |
| --- | --- | --- |
| `-f` / `--file` | 模型文件路径 | 必填 |
| `-m` / `--mode` | `0` = yolov5，`1` = fcos | 必填 |
| `-i` / `--input_video` | 输入视频路径 | **只有不带摄像头时**才需要 |
| `-w` / `--video_width` | 视频宽度 | 配合 `-i` |
| `-h` / `--video_height` | 视频高度 | 配合 `-i` |
| `-d` / `--debug` | 打印更多调试信息 | 可选 |

**模式与模型的对应是硬编码的**：`-m 0` 只认 YOLOv5 后处理，`-m 1` 只认 FCOS 后处理。用 `-m 0` 加载 FCOS 模型不会报错，但输出结果是乱的。

- **不同模型前处理不同**：官方 FAQ 明确"不同模型一般前处理不一样"，不能指望一套前处理通吃。

## 11. 四段式排障：WiFi 连不上 / 连上就断

**现象**

`sudo wifi_connect "WiFi-Test" "12345678"` 返回：

```
Error: No network with SSID 'WiFi-Test' found.
```

或者连上了但几分钟就断，或者一开热点 WiFi 就掉。

**根因**

分三种，处理完全不同：

| 现象 | 根因 | 判据 |
| --- | --- | --- |
| `No network with SSID ... found` | 热点没被扫到（不是密码错） | `nmcli device wifi list` 里有没有这个 SSID |
| 连上几分钟就断 | 弱信号 / 休眠重连机制 / 驱动旧 | `dmesg \| grep -i wlan` 有无 deauth、power save 相关 |
| 一开热点 WiFi 就断 | **X5 不支持 STA+AP 并发** | 这是设计限制，不是故障 |

另外三种硬件层原因容易被忽略：

1. **天线选错**。板载/外置天线要在 `srpi-config` 里切，`antenna_option=trace` 是板载、`=cable` 是外置。装了外置天线但配置还是 `trace`，信号不会改善。
2. **IPEX 接口代次错**。X5 用的是 IPEX **1 代**，买了 2 代/3 代装不上。
3. **天线贴在金属上**。FPC 天线贴在喷塑金属壳上会导致信号极差。

**处置**

```bash
# 1) 确认接口存在（没有 wlan0 说明模块没起来）
ip link show
sudo rfkill unblock wlan        # 若被软禁用

# 2) 重新扫描并确认 SSID 可见
sudo nmcli device wifi rescan
sleep 3
sudo nmcli device wifi list | grep -i "WiFi-Test"

# 3) 再连
sudo wifi_connect "WiFi-Test" "12345678"

# 4) 确认天线配置与实际硬件一致
cat /boot/config.txt | grep antenna_option

# 5) 看信号强度与断连原因
nmcli -f IN-USE,SSID,SIGNAL device wifi list
sudo dmesg | grep -iE "wlan|deauth|disconnect" | tail -20
```

若第 1 步就没有 `wlan0`：

```bash
# 3.3.3 之前驱动名可能是 aic8800_fdrv；以实际 lsmod 为准
lsmod | grep -i aic
sudo modprobe aic8800_fdrv      # 名字按上一条输出替换
```

**预防**

- 所有操作前先 `ip link show` 确认 `wlan0` 存在，没有就先解决模块加载，别在应用层打转；
- 需要同时联网 + 热点，直接上 USB WiFi 网卡，不要试图让板载模块并发；
- 换天线后**必须**确认 `antenna_option`，否则配了等于没配。

> 来源：官方文档 System_configuration/network_bluetooth、System_configuration/srpi-config、FAQ/interface（https://developer.d-robotics.cc/rdk_x_doc/FAQ/interface）、社区帖 35412、35522

## 12. 四段式排障：示例跑起来了但屏幕上什么都没有

**现象**

`vio2display` / `decode2display` / `bpu` 都能正常编译、启动、打印完整日志（包括 `sp_open_camera success!`、`sp_start_decode success!`、`sp_module_bind success!`），但 HDMI 显示器上什么都没有，或者只有一个灰屏/黑屏。

**根因**

三种，按概率排序：

1. **没关 `lightdm`**（最常见）。桌面占着 DRM 通道，示例能算不能显示。
2. **显示模式不匹配**。日志里 `disp_w=..., disp_h=...` 选中的是显示器不支持的模式。
3. **DSI/HDMI 互斥没配对**。之前切到 DSI 过，`xorg_hdmi_ignore.conf` 还在生效，HDMI 被忽略。

**处置**

```bash
# 1) 关桌面（需要 sudo）
sudo systemctl stop lightdm
#    确认真的停了
systemctl status lightdm | head -3

# 2) 重新运行示例
cd /app/cdev_demo/vio2display
sudo ./vio2display -h 1080 -w 1920

# 3) 若仍无画面，看 DRM 侧
modetest -M vs-drm -c | head -40
#    connector 必须是 connected，且 Mode 列表非空

# 4) 核对 xorg 的两个 ignore 文件
ls -l /etc/X11/xorg.conf.d/ | grep -E "hdmi|dsi"
```

**预防**

把这条当条件反射：**任何"直出 HDMI"的示例，在 Desktop 版上第一步就是 `sudo systemctl stop lightdm`**。官方在 `vio2display`、`bpu`、`decode2display`、`rtsp2display`、MIPI 示例、V4L2 文档六处都写了这句，是共性要求。

恢复桌面：

```bash
sudo systemctl start lightdm
```

> 来源：官方文档 Basic_Application/cdev_demo_sample 各篇、Advanced_development/hardware_development/rdk_x5/V4l2

## 13. 常见误区

1. **"插上网线就能上网"**——不能。X5 有线默认静态 IP `192.168.127.10`，不是 DHCP。要 DHCP 必须改配置文件。

2. **"改网络配置随便改哪个文件都行"**——不行。≥ 3.3.0 改 `netplan-eth0.nmconnection`，更早改 `/etc/network/interfaces`。改错文件等于没改。

3. **"`wifi_connect` 报 `No network with SSID ... found` 是密码错了"**——不是。这条是**热点没被扫到**；密码错的报错文本不同。先 `nmcli device wifi rescan` 再连。

4. **"X5 可以一边连 WiFi 一边开热点"**——不支持 STA+AP 并发，一开热点 WiFi 就断。要两者兼得只能加 USB WiFi 网卡。

5. **"装了外置天线信号就好了"**——还要在 `srpi-config` 里把 `antenna_option` 从 `trace` 改成 `cable`，并确认用的是 IPEX 1 代接口、天线没贴在金属面上。

6. **"蓝牙 `power on` 了手机就能搜到"**——还要 `discoverable on`。`powered` 与 `discoverable` 是两个独立状态。

7. **"手机连上蓝牙了就能控制小车"**——蓝牙只是通道。链路通不代表上层控制服务在跑，要 `ps -ef | grep -i blue` / `ros2 node list` 确认接收端存在。

8. **"`vio2display` 也能传 `-i` 输入文件"**——不能，它只有 `-h` 和 `-w`。官方文档正文里"`-i` 是必填选项"那句是从别处串过来的错误，以 `--help` 输出为准。

9. **"`vio2encoder` 可以调码率"**——不能，`bit_rate:8000` 硬编码在示例里。要改码率得改源码重编。

10. **"`decoder2display` 里的 `No more input data available` 是报错"**——是循环播放的标志，文件读完了从头再来。

11. **"`bpu` 的 `-m` 只是选后处理，随便填"**——`-m 0` 只认 YOLOv5、`-m 1` 只认 FCOS，配错模型不报错但输出是乱的。

12. **"示例打印了 `success!` 就说明看到画面了"**——`sp_open_camera success!` 只说明采集通路建好了。要看到画面，`lightdm` 必须停掉。
