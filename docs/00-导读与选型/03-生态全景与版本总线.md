# 0.3 生态全景与版本总线

## 本章解决什么

RDK X5 不是一个孤立的板子，它挂在一整套软硬件体系里：芯片（Sunrise 5）、系统（RDKOS）、机器人中间件（TROS）、算法工具链（OpenExplore / OE）、模型库（Model Zoo）。这套体系里**至少四条版本线在同时演进**，而且互不同步。

不理解这四条版本线的关系，就会反复遇到「按 A 文档做，报错说找不到 B 库」的情况。本章把四条线拉平，给出对应关系与选型建议。

> 来源：官方文档 RDK（https://developer.d-robotics.cc/rdk_x_doc/RDK）、Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）、model_zoo_intro（https://developer.d-robotics.cc/rdk_x_doc/model_zoo_intro）

## 0.3.1 四条版本线

| 版本线 | 是什么 | 现在的版本 | 谁在维护 | 与其它线的关系 |
| --- | --- | --- | --- | --- |
| **RDKOS** | 板子上跑的操作系统镜像 | 3.5.0（2026-04） | 地瓜机器人 | 底座，决定其它三条线的可用性 |
| **TROS** | TogetheROS.Bot，ROS2 机器人中间件 | V2.4.3（对应 RDKOS 3.3.3） | 地瓜机器人 | 随 RDKOS 发布，版本号独立 |
| **OE 工具链** | OpenExplore，x86 上的模型转换工具链 | V1.2.8（X5 线） | 地瓜机器人 | 独立 Docker 镜像，与 RDKOS 版本弱耦合 |
| **Model Zoo** | BPU 可运行模型示例集 | 跟随 RDKOS 3.5.0 | 社区共建 | 按 RDKOS 版本分支 |

**关键认知**：这四条线的版本号**不相等、也不同步**。「我的 RDKOS 是 3.3.3，那 OE 工具链该用哪个版本」这类问题没有单一答案，要看工具链的兼容性说明。

## 0.3.2 RDKOS 版本时间线

这是最需要记住的一条线。RDK X5 从首发到现在的完整演进：

| 版本 | 发布时间 | 关键变化 |
| --- | --- | --- |
| 3.0.0 | — | 首个 RDK X5 固件，基于 Ubuntu 22.04 |
| 3.0.1 | — | Server 版固件；支持 7 款微雪 MIPI DSI 屏；支持非 root 用户跑示例 |
| 3.1.0 | — | 按键休眠唤醒；开放 40PIN 第二功能；修正 CAN 频率异常 |
| 3.1.1 | — | `rdk-backup` 一键备份；`config.txt` 配 40pin 启动状态；StereoNet 升级；DOSOD 开放词汇检测 |
| 3.2.3 | 2025-06 | 实时内核切换；miniboot 集成新版（`rdk-miniboot-update` 后释放更多内存）；V4L2 框架适配 imx477/ov5647/imx219；apt 源支持在线升级 |
| 3.3.3 | 2025-10 | SC132GS 双目驱动；`srpi-config` 支持接口自动管脚复用；Wi-Fi 驱动升级；闪连接口支持 macOS |
| 3.4.1 | 2025-12 | 对齐 X5 SDK 1.1.1；EMMC/SD 启动可靠性增强；多媒体链路大规模修复；HDMI 多分辨率；WiringPi 修复；`hobot-gpio` 多路 PWM |
| **3.5.0** | **2026-04** | **Python 推理统一为 `hbm_runtime`**；`/app/pydev_demo/` 全量重写；HDMI 时序优化；GPU 桌面修复；支持幻尔音频子板、BMI08x、ICM42688 |

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

### 0.3.2.1 是硬分界

这一版把 Python 侧的算法推理接口从 `pyeasy_dnn` 换成了 `hbm_runtime`，官方原文：

> 「自 3.5.0 版本起，Python 算法推理、目标检测、语义分段等模块统一升级为 **hbm_runtime** 接口。该接口基于 **pybind11** 实现，提供对 **libdnn** C++ 库的高效访问」
> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

同时 `/app/pydev_demo/` 下所有示例**全量重写**。这意味着：

- 网上 3.4.x 时代的 Python 示例代码，在 3.5.0 上**路径和接口都可能对不上**
- 3.5.0 的示例代码，在 3.4.1 及更早的系统上**跑不起来**
- 官方文档也「基于 hbm_runtime 与 /app/pydev_demo/ 全新示例完成全面修订」

判断自己该看哪套：

```bash
cat /etc/version
rdkos_info
```

| 输出 | Python 推理接口 | 该看哪套示例 |
| --- | --- | --- |
| 3.5.0 及以上 | `hbm_runtime` | 当前官方文档 + `/app/pydev_demo/`（新版） |
| 3.4.1 及以下 | `pyeasy_dnn` | 旧版教程 / 旧版示例，注意甄别 |

**TROS 侧不受影响**：TROS 的 C++ 推理仍走 `hobot_dnn`。看到「Python 用 hbm_runtime、C++ 用 hobot_dnn」不要以为是矛盾，这是两套并行接口。

### 0.3.2.2 升级的强制步骤

每次系统升级后，官方明确要求：

> 「更新系统后，请使用 `rdk-miniboot-update` 命令更新 NAND 固件至最新版本。」
> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

```bash
sudo rdk-miniboot-update
```

跳过这一步的后果：miniboot 与新系统不匹配，表现为启动异常或内存占用偏高。3.2.3 的更新说明里给了具体例子——集成新版 miniboot 后，「使用 `rdk-miniboot-update` 命令烧录 NAND 后，会释放更多内存给系统」。

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

## 0.3.3 TROS 版本线

TROS（TogetheROS.Bot）是地瓜的机器人中间件，在 ROS2 Humble 之上封装了 BPU 推理、图像编解码、零拷贝等能力。

版本对应关系（官方 Release Note 中明确标注的）：

| RDKOS 版本 | 同期 TROS 版本 | TROS 侧关键更新 |
| --- | --- | --- |
| 3.3.3 | TROS V2.4.3 | 单目 MIPI 多路采集；新增 SC132GS 双目支持 |
| 3.4.1 | — | 修复 `hobot_cv` 的 vse resize bug；修复 `hobot_dnn` 推理延迟统计错误；修复 ros component so 路径错误；优化 `hobot_codec` 配置 |

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）

注意 3.4.1 那三条「修复」——它们都是**曾经真实存在过的 bug**：

- `hobot_cv` 用 vse 加速 resize 有 bug → 你的 resize 结果可能不对
- `hobot_dnn` 推理延迟统计错误 → 你测的性能数字可能不准
- ros component so 安装路径错误 → 运行时报加载失败

如果你在 3.4.1 之前的系统上遇到「性能数字对不上」或「ros component 加载失败」，先怀疑是这三个已知问题，而不是自己的代码。

## 0.3.4 OE 工具链版本线

OE（OpenExplore）是在 **x86 开发机**上跑的模型转换工具链，以 Docker 镜像形式发布。它和 RDKOS 是两条独立的线。

X5 对应的工具链版本：

| 平台 | 工具链版本 |
| --- | --- |
| RDK X5 | V1.2.8 |
| RDK X3 | V2.6.6 |

> 来源：官方文档 Advanced_development/toolchain_development/rdk_x5/oe_toolchain_v1_2_8（https://developer.d-robotics.cc/rdk_x_doc/Advanced_development/toolchain_development/rdk_x5/oe_toolchain_v1_2_8）

**X3 和 X5 的工具链版本号完全不同**（2.6.6 vs 1.2.8），拿 X3 的工具链转 X5 的模型会失败。这是社区里出现过的错误。

### 0.3.4.1 Docker 镜像 Ubuntu 20.04 的问题

官方 FAQ 专门解释过这个疑问：工具链 Docker 镜像基于 Ubuntu 20.04，但板端是 Ubuntu 22.04，会不会不兼容？

答案是**不影响转换产物在板端的运行**。Docker 只是转换环境，产物是 `.bin` 模型文件，与宿主系统无关。

> 来源：官方文档 FAQ/toolchain（https://developer.d-robotics.cc/rdk_x_doc/FAQ/toolchain）Q5

## 0.3.5 Model Zoo

Model Zoo 是 BPU 可运行模型的示例集，覆盖图像分类、目标检测、实例分割、姿态估计、OCR、多模态。

仓库地址：https://github.com/D-Robotics/rdk_model_zoo

每个模型提供从「原始模型（PyTorch/ONNX）→ 定点量化转换 → 推理运行 → 结果解析 → 示例验证」的完整参考实现。

> 来源：官方文档 model_zoo_intro（https://developer.d-robotics.cc/rdk_x_doc/model_zoo_intro）

Model Zoo 的用户手册按版本分支提供：

- RDK X3：`?v=3.0.0&p=RDK+X3`
- RDK X5：`?v=3.5.0&p=RDK+X5`

> 来源：官方文档 model_zoo_intro（https://developer.d-robotics.cc/rdk_x_doc/model_zoo_intro）

**注意手册带版本参数**：`v=3.5.0` 是给新版系统的。系统是 3.4.x 却按 3.5.0 的手册操作，脚本和路径会对不上。

## 0.3.6 两条系统镜像路线：Ubuntu vs Buildroot

很多人不知道 RDK X5 有两条完全不同的系统路线，选错了会白折腾：

| 维度 | Ubuntu 镜像 | Buildroot 镜像 |
| --- | --- | --- |
| 适用用户 | 熟悉树莓派、聚焦应用层开发 | 有嵌入式 Linux 经验、要内核定制/驱动适配 |
| 桌面 | 支持图形桌面 | **不支持图形桌面** |
| 装新组件 | 在线 deb 安装 | 需要源码编译，自行定制镜像 |
| 编程接口 | Python 接口，简化图像/AI 开发 | **HBRE C 接口**，完整底层能力 |
| 适用硬件 | RDK X3 / X5 | **RDK X5 Module eMMC 版** |
| 镜像大小 | — | 源码包约 3.1GB，手册约 163MB |

> 来源：官方文档 Quick_start/download（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/download）

**选择规则很简单**：要做应用、跑模型、用 ROS —— 选 Ubuntu。要做产品、改内核、裁剪系统 —— 选 Buildroot，且硬件必须是 X5 Module eMMC 版。

Buildroot 路线没有 Python 推理接口，只有 HBRE C 接口。本文档前六卷默认按 **Ubuntu 路线** 写。

## 0.3.7 软件栈分层图

从下往上：

```
┌─────────────────────────────────────────────┐
│ 应用层：你的程序 / Model Zoo 示例 / 案例      │
├─────────────────────────────────────────────┤
│ 框架层：TROS (hobot_dnn/hobot_cv/hobot_codec) │
│         Python: hbm_runtime (3.5.0+)          │
│                 pyeasy_dnn  (≤3.4.1)          │
├─────────────────────────────────────────────┤
│ 运行时：libdnn / libhb* / ION / hbmem         │
├─────────────────────────────────────────────┤
│ 系统层：RDKOS (Ubuntu 22.04)                  │
├─────────────────────────────────────────────┤
│ 硬件层：Sunrise 5 (8×A55 + 10TOPS BPU)        │
└─────────────────────────────────────────────┘
        ↑ 以上都在板子上
        ↓ 以下在 x86 开发机
┌─────────────────────────────────────────────┐
│ OE 工具链 (Docker, V1.2.8): hb_mapper         │
│   输入 .onnx → 输出 .bin                      │
└─────────────────────────────────────────────┘
```

理解这张图的价值：**报错时先定位是哪一层**。

| 报错特征 | 可能的层 |
| --- | --- |
| `ImportError: No module named hbm_runtime` | 框架层（版本不对） |
| `hb_mapper` 转换报错 | 工具链层（x86 侧） |
| `Segmentation fault` 跑示例 | 运行时层（模型与运行时版本不匹配） |
| 上电无反应 / 反复重启 | 硬件层 / 系统层（先查电源） |

## 0.3.8 一张表搞定版本自查

登录板子后，按顺序跑这几条，把结果记下来，遇到问题先贴这些：

```bash
# 系统大版本
cat /etc/version

# 地瓜核心功能包版本
apt list --installed | grep hobot

# 推荐：一站式系统信息（2.1.0 及以上）
rdkos_info

# 板卡 ID 与 DDR 信息
hrut_boardid

# SoC 状态（温度/频率）
hrut_somstatus
```

> 来源：官方文档 FAQ/hardware_and_system（https://developer.d-robotics.cc/rdk_x_doc/FAQ/hardware_and_system）Q2

官方 FAQ 也强调过这一点：提问算法工具链问题时，需要先提供版本信息，否则无法判断。

> 来源：官方文档 FAQ/toolchain（https://developer.d-robotics.cc/rdk_x_doc/FAQ/toolchain）Q1

## 常见误区

1. **「RDKOS 3.5.0，所以 TROS 也是 2.5.0」** —— 不对。TROS 版本号独立，3.3.3 对应的是 TROS V2.4.3。
2. **「X5 和 X3 工具链通用，都是地瓜的」** —— 不对。X5 是 V1.2.8，X3 是 V2.6.6，不通用。
3. **「升级完系统就完事了」** —— 还要跑 `rdk-miniboot-update`，否则 NAND 固件与系统不匹配。
4. **「官方文档是唯一真相，照做就行」** —— 官方文档呈现的是最新版，你的板子可能不是最新版。先 `rdkos_info` 再决定看哪套文档。
5. **「Buildroot 和 Ubuntu 只是有没有桌面的区别」** —— 差得远。Buildroot 没有 Python 推理接口，只有 HBRE C 接口，且只支持 X5 Module eMMC 版。
