# 0.1 这份知识库是什么，怎么用

## 本章解决什么

RDK X5 的资料分散在三处：官方文档站、地瓜社区论坛、以及散落在各处的个人博客。官方文档讲「设计上应该怎么做」，社区帖讲「实际会怎么坏」，两边都对，但没有人把它们缝在一起。这份知识库做三件事：

1. **把官方文档结构化地重讲一遍**，补上官方文档里默认你会、但新手其实不会的前置知识；
2. **把社区里真实发生过的故障收进来**，保留原始报错文本，给出可执行的处置；
3. **标出「版本分界」** —— RDK X5 从 RDKOS 3.0.0 走到 3.5.0，接口变过两次，网上大量教程已经过期，用错版本会卡很久。

> 来源：官方文档 rdk_x_doc 全站（https://developer.d-robotics.cc/rdk_x_doc/）；社区论坛 https://forum.d-robotics.cc

## 0.1.1 素材来自哪里

本知识库不是二手转述，所有内容都取自两个一手来源：

| 来源 | 范围 | 用途 |
| --- | --- | --- |
| 官方文档站 `developer.d-robotics.cc/rdk_x_doc` | 全站 247 个中文页面，约 131 万字符 | 硬件规格、接口定义、API 用法、官方 FAQ |
| 地瓜社区论坛 `forum.d-robotics.cc` | 892 个主题帖，约 1100 万字节 | 真实报错、排查过程、官方技术支持回复 |

每条技术结论后面都有出处行，格式为：

```
> 来源：官方文档 <页面 slug>（<完整 URL>）
> 来源：社区帖 <topicId>（https://forum.d-robotics.cc/t/topic/<topicId>）
```

看到出处行就说明这条结论可回溯。没有出处的段落是编者按，属于经验归纳。

## 0.1.2 与官方文档的分工

官方文档是**唯一权威**，本知识库不替代它，只做三件官方不做的事：

- **官方讲「怎么用」，本库补「为什么会坏」**。例如官方写了 40PIN 的 GPIO 编号表，但没写「编号与物理引脚号不是一回事」这个新手必踩的坑，社区帖里踩过，本库补上。
- **官方按功能组织，本库按任务组织**。官方文档第 3 章叫「基础应用开发」，本库叫「我要接一个摄像头出图」，按你要做的事索引。
- **官方一次只讲一个版本，本库标注版本漂移**。官方文档站现在呈现的是最新版，你在板子上跑的可能是老系统。

如果两者冲突，**以官方文档 + 你自己的板端实测为准**，本库会明确指出冲突点在哪。

## 0.1.4 版本分界：先确认你在哪个版本

这是全库最重要的一页。执行：

```bash
cat /etc/version
rdkos_info
```

| 你看到的版本 | 意味着什么 | 影响哪些章节 |
| --- | --- | --- |
| < 3.0.0 | Ubuntu 20.04 底座 | 本文档基本不覆盖，接口与 3.x 差异大 |
| 3.0.0 ~ 3.4.1 | Ubuntu 22.04 底座，Python 推理用 `pyeasy_dnn` | 卷3 第2章讲旧接口 |
| **3.5.0 及以上** | Python 推理统一改为 **`hbm_runtime`** | 卷3 第2章讲新接口，网上教程大多还是旧的 |

版本口径的确切出处：

> 来源：官方文档 Release_Note/release_note（https://developer.d-robotics.cc/rdk_x_doc/Release_Note/release_note）——「自 3.5.0 版本起，Python 算法推理、目标检测、语义分段等模块统一升级为 hbm_runtime 接口。该接口基于 pybind11 实现，提供对 libdnn C++ 库的高效访问」
> 来源：官方文档 Quick_start/download（https://developer.d-robotics.cc/rdk_x_doc/Quick_start/download）——「系统镜像 < 3.0.0：基于 Ubuntu 20.04；系统镜像 >= 3.0.0：基于 Ubuntu 22.04」

## 0.1.5 这套资料是怎么攒起来的

不是凭记忆写的，也不是把官方文档换个说法。流程是固定的：

1. **全量抓取官方文档**。从 `sitemap.xml` 枚举出 263 个 URL，剔除英文与已下架的 X3 旧页，留下 247 个中文页面，逐页抓 HTML 转 Markdown，共约 131 万字符。
2. **按主题检索社区论坛**。用地瓜论坛的 Discourse JSON 接口，以 50 多个关键词（烧录、量化、hbm_runtime、MIPI、TROS、CAN……）检索，命中 961 个主题帖并抓取全部楼层，共约 1100 万字节。
3. **交叉比对**。同一条结论，官方怎么说的、社区里实际发生的是什么，逐条对齐。冲突处并列写出。
4. **按任务重组**。不按官方文档的功能模块分章，按「你要做什么」重组，并把故障单独抽成第 6 卷。

所以本库里每一段技术事实，都能在这两个来源里找到对应位置。出处行就是这个映射。

### 0.1.5.1 为什么不直接给官方文档的目录

官方文档的结构是按**功能模块**组织的：硬件、系统配置、基础应用、进阶开发、工具链。这个结构对维护文档的人友好，对使用者不友好。

举个例子：你想「用 MIPI 摄像头跑一个实时检测」，这件事涉及官方文档的六个分散位置——硬件简介（接口定义）、入门配置（srpi-config 使能）、摄像头使用（MIPI 章节）、示例程序（mipi_camera_sample）、多媒体 API（VIO 接口）、以及 FAQ 里的摄像头排障。本库把这条任务链拉直，你要找的东西在同一章里。

## 0.1.6 素材的边界（我们没覆盖什么）

任何资料都有边界，说清楚比含糊过去好：

| 未覆盖 | 原因 | 去哪找 |
| --- | --- | --- |
| RDK X3 / X3 Module | 本文档专为 X5；X3 的驱动、工具链版本与 X5 完全不同 | 官方文档 rdk_x_doc 的 X3 分节 |
| 官方文档英文版 | 中文版内容更新更及时 | https://developer.d-robotics.cc/rdk_x_doc/en/ |
| 论坛全量帖 | 只按关键词覆盖检索，非全量爬取 | 论坛直接搜索 |
| RDK S100 及其他型号 | 不同芯片平台 | 官方对应文档 |
| 商业算法工具链手册 | 官方建议优先查阅社区手册 | 官方下载中心 |
| 视频教程 | 本文档为文本资料 | 地瓜 B 站账号、社区活动区 |

还有一类内容**刻意不写**：官方文档明确标注为「待测试」的规格、社区帖里没有结论的猜测、以及无法在板端复现的说法。这些内容留在库里会误导人，不如不写。

## 0.1.7 本库的写法约定

- **报错原文不改写**。社区帖里贴的报错，本库原样抄进代码块。你可以直接拿它去搜。
- **命令可直接复制**。不加 `$` 前缀，需要 `sudo` 的地方会写明。
- **故障按四段式写**：现象（原文报错）→ 根因（机制）→ 处置（命令）→ 预防（怎么避免）。这是本库与普通教程最大的区别，集中在[卷6](../06-错误反思与排障/01-排障总纲与信息采集.md)。
- **表格优先**。引脚、型号、错误码、版本差异，一律用表。

## 常见误区

1. **「官方文档更新了，我的板子就是新版」** —— 不成立。板子出厂烧的是测试镜像，你手上这块可能是 3.1.0。先 `rdkos_info` 再说。
2. **「社区帖里的方案照着抄就行」** —— 社区帖大多没标版本。同一个报错在 3.4.1 和 3.5.0 上根因可能完全不同，尤其涉及 Python 推理接口的。
3. **「先跑通再说，环境不用管」** —— RDK X5 供电不足会表现为「随机卡死」「网络时断时续」，看起来像软件 bug，实际是电源。这类误判在社区里占比很高。
4. **「文档这么长，直接问 AI 就行」** —— AI 不知道你板子上的实际版本和外设型号。本库的价值在于把「版本 + 外设 + 报错」三者的对应关系固定下来。
